## 第一遍中暴露的学习陷阱

| 陷阱 | 第二遍核实要求 | 对应功能 ID |
|---|---|---|
| 有 MessageBus/ChannelManager，不代表 Feishu 入站和回复真的经过它们 | 从 webhook/轮询入口一路追到 bus、manager、agent 和出站发送；补真实或有代表性的端到端验收 | WAH-API-005、WAH-API-006 |
| 有 JWT 中间件，不代表全部需要保护的路由都受保护 | 按匿名/认证/授权角色列路由矩阵，验证每条实际入口及拒绝结果 | WAH-GOV-001–004 |
| 有流式接口或 runner，不代表运行时真实逐步产出并保留状态 | 检查 token、工具事件、终态、取消和断连；区分真实流、缓存后整块返回和仅测试桩 | WAH-RUN-007、WAH-TOOL-006、WAH-API-002 |
| 保存了会话记录，不代表重启后能恢复正确历史和运行状态 | 分开验证消息历史、业务 session、checkpoint；覆盖重启、分页、继续对话和客户端同步 | WAH-RUN-004–007、WAH-UI-003 |
| 目录/类名看起来对应 EvoFlow，不代表行为、生命周期和入口等价 | 以用户场景为单位，查真实 caller、配置、状态变化、错误和测试；孤立组件注明未接线 | 所有 WAH ID |
| 文档路径、结论和测试数字会随源码快照过期 | 每条路径对应当前 commit；历史记录标明时间和基线，不能直接搬用旧结论 | 所有 WAH ID |

上述是第一遍审查中指出的风险线索，不是对当前 AgentFlow 或 EvoFlow 的自动判定。重学时要按冻结快照复现并保存证据。
