| 行为 | EvoFlow 起点（相对仓库根） | 需留意 |
|---|---|---|
| 对话与持久化 | backend/packages/harness/evoflow/config/、models/、agents/、persistence/ | 分清业务 session 和 checkpoint |
| 工具和流 | evoflow/tools/、agents/middlewares/、stream 生产/消费端 | 分类盘点，样例不代表全量 |
| 上下文与记忆 | evoflow/context/、memory/、agents/memory*/、assets/ | 短期状态和长期记忆分开 |
| 知识和代码索引 | evoflow/knowledge/、code_index/、uploads/ | 追更新、引用、权限、后台任务 |
| 执行与委派 | evoflow/subagents/、sandbox/、execution_security/、session_execution/ | path guard 不等于进程隔离 |
| 计划与协作 | evoflow/plans/、collab/、agents/goal/、workflows/、stage/、exploration/ | 根 plans 含 Plan Bundle/适配器，不可直接当任务 DAG |
| 自动化 | evoflow/scheduler/、core/scheduler/、automation/、proactive/、app runner | 区分工具调度、定时自动化、主动循环 |
| 扩展协议 | evoflow/mcp/、plugins/、skills/、community/、capability/、external_agents/、a2a/ | 追生命周期、授权和真实注入 |
| 服务入口 | backend/app/gateway/（含 v4/、speech/）、backend/app/channels/、evoflow/app_server/、runtime/ | v4/speech 在应用层，核对每个入口 |
| 治理观测 | evoflow/authz/、organizations/、guardrails/、observability/、eval/、admin/ | 验证策略实际覆盖入口 |

目录只是线索。找不到真实 caller 时标“待追入口”或“仅内部能力”；发现新域就更新地图和稳定 ID。


## 源码覆盖导航

核心源码按当前快照位于 `backend/packages/harness/evoflow/`。功能单元路线逐项把核心包归入运行时、工具、记忆、知识、执行、计划、自动化、扩展、治理、观测等行为；横切清点单列尚需判定真实 caller 的内部域。应用层 `backend/app/gateway/` 和 `backend/app/channels/`、核心 `app_server/`、Web/桌面 `evopanel/src/` 也各有专门功能单元。不要从目录本身推断入口、产品能力或完成状态。
