## 从一个问题进入

用户消息怎样进入 Agent、产生回复，并在下一轮或重启后恢复？

## 源码入口和阅读方法

backend/packages/harness/evoflow/config/、models/、agents/lead_agent/、agents/thread_state.py、agents/checkpointer/、persistence/；向外追 CLI、Gateway 和 evopanel 的真实入口。

对选定场景补全“用户输入/入口 → 注册装配 → 核心行为 → 状态或副作用 → 事件/结果”。每个环节记源码符号和相关测试。至少看一个成功路径、一个关键数据结构和一个错误/权限分支；先找真实 caller 再扩阅读。

## 概念和代码解释

模型/provider 解析与配置；lead Agent 图和消息状态；业务 session 与 checkpoint 的职责；数据库 schema/migration；恢复与清理。

每个概念回答：数据由谁创建和拥有、谁能修改、何时持久化、失败时保留什么、用户在哪里看到结果。把概念对应到真实源码，不以 README 的理想图替代当前装配。

## 从最小实验到完整能力

1. 写一个具体用户场景、输入输出和依赖关系。
2. 最小闭环：先用 fake model 跑单轮、多轮；加配置解析和持久化；补 provider、错误、线程隔离与恢复；最后从真实产品入口重启复现。
3. 对照本单元原子功能 ID 补齐配置、真实入口、生命周期、错误和边界；WorkAgentHarness 没有的实现仍标为未实现。
4. 从真实入口复现一个不同输入，解释因果链，更新记录和差异。
