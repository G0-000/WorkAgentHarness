# Gateway、HTTP/SSE、IM 渠道与服务运行时

> 功能导航单元 WAH-API，不是课程里程碑。逐项状态以[功能清单](../功能清单.md)为准。EvoFlow 基准 commit：62a4117ceff4626213ad434eae6b311bcc3bcfe1。

## 从一个问题进入

API 或 IM 消息怎样进入 Agent 并正确返回？

## 源码入口和阅读方法

backend/app/gateway/（routers、streaming、v4/、speech/、cancellation/）、backend/app/channels/、evoflow/app_server/、evoflow/runtime/ 和启动装配。

对选定场景补全“用户输入/入口 → 注册装配 → 核心行为 → 状态或副作用 → 事件/结果”。每个环节记源码符号和相关测试。至少看一个成功路径、一个关键数据结构和一个错误/权限分支；先找真实 caller 再扩阅读。

## 概念和代码解释

区分 app/core；route 注册和注入；SSE 断连；channel bus/manager；Webhook 校验；后台服务生命周期；runtime port/adapter。v4、speech 属于 app/gateway。

每个概念回答：数据由谁创建和拥有、谁能修改、何时持久化、失败时保留什么、用户在哪里看到结果。把概念对应到真实源码，不以 README 的理想图替代当前装配。

## AgentFlow 第一遍复盘

在 /Users/main/AgentFlow 记录当前 HEAD，找对应入口和测试，而不是只搜索同名文件。将行为标记为相同、部分覆盖、语义不同或缺失并附证据。第一遍缺少的功能仍在本轮学习范围内。

## 从最小实验到完整能力

1. 写一个具体用户场景、输入输出和依赖关系。
2. 最小闭环：TestClient/fake runtime 走一条 API；再做渠道入站→bus/manager→Agent→出站；补流式、取消、启动/关闭并盘点其余入口。
3. 对照本单元原子功能 ID 补齐配置、真实入口、生命周期、错误和边界；WorkAgentHarness 没有的实现仍标为未实现。
4. 从真实入口复现一个不同输入，解释因果链，更新记录和差异。

## 练习与验收

| 验收 | 练习 | 证据 |
|---|---|---|
| 核心契约 | 验证输入、输出和状态变化 | 精确命令、结果、commit |
| 错误/权限 | 未授权路由、Webhook 重放、断流、重复投递、队列拥塞、shutdown 任务和多进程状态。 | 错误、权限结果及副作用 |
| 真实集成 | 从注册入口进入，不绕过装配直调内部函数 | 运行依赖和完整调用链 |
| 生命周期 | 验证适用的重启、取消、删除、卸载或重配置 | 状态变化、恢复和残留资源 |
| 讲解 | 不看笔记复述入口→逻辑→状态→结果并对照第一遍 | 学习记录和结论 |

## 关闭出口

所有适用原子 ID 有实现和风险相符的验收、真实入口已接线、差异或排除可解释，才标已验收。否则标注最小闭环、已实现未集成或边界待验。总收口见[最终验收](../最终验收.md)。
