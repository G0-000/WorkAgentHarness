## 本章场景

你要开始仿写一个 Agent 框架。开工前必须回答两个问题：**教材长什么样**、**照着抄有没有法律问题**。

这两件事的权重完全不同。许可证是"确认底色"——读一遍、记结论，之后不再回头；追调用链是"练基本功"——它决定你后面二十几章能不能读懂源码。所以本章把许可证压缩成准备动作，把时间留给调用链。

## 本章学习目标

| 层级 | 目标 | 时间 |
|---|---|---|
| **主目标（必须通过）** | 从真实用户入口追一条消息，走完 配置 → 模型 → Agent → 状态写入 → 返回，每一跳都能报出 `文件::符号` | 本章大部分时间 |
| **辅目标（准备材料）** | 记录三仓库 HEAD；读懂 EvoFlow 的许可与分层边界，能说出"哪些能抄、哪些不能" | 半小时内，只记摘要 |

**辅目标不设验收门槛**。它不是知识点考核，而是"确认可以合法地继续"的一次性检查。读不完 LICENSE 不影响你开始第 3 章。

**本章不写业务代码**，产物是可复查的基线：三份 commit + 一张调用链图 + 一张限定范围的差异表。

## 走哪块代码（只读，不改）

| 步骤 | 做什么 | 走哪块代码 | 产出 |
|---|---|---|---|
| 1 | 记仓库基线 | 三仓库根目录 `git rev-parse HEAD`、`git status --short` | `doc/dev/学习记录/起点/` 下一条记录 |
| 2 | 读许可与分层 | `/Users/main/EvoFlow/LICENSE`、`NOTICE`、`backend/ARCHITECTURE.md` | 半页摘要：能抄 / 不能抄 / 需保留声明 |
| 3 | **定位真实入口** | EvoFlow `backend/app/gateway/routers/` 下与对话相关的路由文件 | 说出哪个 HTTP 端点接收用户消息 |
| 4 | 追到服务层 | 从路由函数调用的 service / 用例 | 说出消息在哪个函数里被写入业务库 |
| 5 | 追到 Agent 与模型 | `backend/packages/harness/evoflow/agents/`、`models/` | 说出 `create_agent` 在哪被调、模型配置从哪来 |
| 6 | 追状态与返回 | checkpointer 装配点、运行结束后的返回路径 | 说出状态写进哪张表、响应怎么回到路由 |
| 7 | 限定范围对照第一遍 | `/Users/main/AgentFlow` 中**与上述 4–6 跳相关**的同名模块 | 只标这几跳的"真正接入 / 只有代码" |

## 为什么把 AgentFlow 对照限定在消息主链

"找出第一遍里所有只有代码、没有调用者的功能"是一个跨全项目的审计任务，单是枚举模块就要几小时，而且结论会随着你后面章节的理解不断变化。

本章只回答一个具体问题：**在这条消息主链上，第一遍有没有把某一段写成死代码？** 其他模块（工具、记忆、调度、渠道）留到讲它们的章节再各自审计。这样每一章的审计范围都和当章读的代码重合，不会提前透支。

## 按顺序完成

### 准备（30 分钟内结束）

1. 记录三仓库 `git rev-parse HEAD` 与 `git status --short`，存到 `doc/dev/学习记录/起点/`。
2. 读 EvoFlow 根 `README.md`、`backend/ARCHITECTURE.md`、`LICENSE`、`NOTICE`，写半页摘要：
   - 应用层（`backend/app/`）与核心层（`backend/packages/harness/`）分别是什么定位；
   - 许可证允许什么、要求保留什么、哪些部分不能直接搬。
3. 到此为止。不要逐行读 LICENSE 全文，也不要整理第三方依赖树——那是发布前才需要做的事。

### 主线练习：追一条消息

4. 从 gateway 路由里找到接收用户消息的端点，记下 `文件::函数`。
5. 顺着这个函数往下，记录它调用的 service 方法；确认业务消息（session/message/run）在哪一步写库。
6. 继续往下，找到构建模型的配置来源与 `create_agent` 的调用点，记下 `文件::符号`。
7. 找到 checkpointer 的装配位置，确认图状态写进哪张表、与业务表是什么关系。
8. 回到入口，说明响应是怎么从运行结果变成 HTTP 返回的。
9. 粗图先行：先画一张 6 跳的箭头图，再逐跳拿代码验证；每跳标注"读过 / 没读透"。

### 对照与定位

10. 在 AgentFlow 里找第 4–7 步对应的模块，逐跳判断：**有真实入口调用 / 只有代码无调用者 / 完全没有**。
11. 浏览 WorkAgentHarness 现状，确认本项目自己的架构决定与目录规划；不要为复刻预先复制 EvoFlow 目录结构。

## 交付

仓库基线表、半页许可摘要、一张消息调用链图、**限定在消息主链上的** AgentFlow 差异表。

有了这四样，你就能回答"下一章从哪里开始、为什么从那里开始"。

## 与其他章的关系

本章没有实现代码，也没有与原版的实现差异——它是第 3 章及之后的对照起点。第 3 章开始每次改代码，都用这里记下的 commit 作为"教材版本"基准。
## 本章代码测试与验收
**测试代码**：无。第 1 章是理解验收（读仓库、记基线、画 6 跳图），没有可执行断言；证据仍是基线表与调用链图。

> **验收类型：理解验收** —— 证据为源码路径与符号（`文件:行`）、调用链图或书面说明，不要求命令；阅读结论不得写成「已实现 / 已通过」。


| 项 | 通过标准 |
|---|---|
| 主目标 | 能不看笔记，在白板上画出这条消息的 6 跳，并在每一跳报出真实的 `文件::符号` |
| 主目标 | 能解释 checkpointer 写入与业务消息写入是两套东西、服务于两个目的 |
| 辅目标 | 能说出三仓库各是什么角色、EvoFlow 的许可边界结论（一句话即可） |
