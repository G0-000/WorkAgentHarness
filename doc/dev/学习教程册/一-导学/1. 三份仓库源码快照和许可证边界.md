## 这一章要实现什么功能

把三个仓库摆在正确位置：EvoFlow 是当前源码教材，AgentFlow 是第一遍仿写证据，WorkAgentHarness 是第二遍学习和重新实现的目标。不要从目录树直接推导课程。

**本章不写业务代码**，交付的是"可复查的基线"：三份 commit + 一张调用链图 + 一张差异表。后续每章写代码时，都要能对回这份基线。

**可验收的行为**：
- 报得出三个仓库各自的 `HEAD`，且知道哪个是教材、哪个是目标。
- 能在 EvoFlow 里从"用户发一条消息"追到"回复返回"，并指出每一段落在哪个文件。
- 能指出 AgentFlow 第一遍里哪些功能只有代码、没有真实调用者。

## 这一章走哪块代码（只读，不改）

| 步骤 | 做什么 | 走哪块代码 | 说明 |
|---|---|---|---|
| 1 | 记录仓库基线 | 三仓库根目录 `git rev-parse HEAD` / `git status --short` | 存到 `doc/dev/学习记录/起点/` |
| 2 | 读许可与边界 | `/Users/main/EvoFlow/LICENSE`、`NOTICE`、`backend/ARCHITECTURE.md` | 记应用层 / 核心层边界 |
| 3 | 追一条消息 | EvoFlow `backend/app/gateway/routers/` → 服务层 → `agents/` → `models/` | 每一跳记 `文件::符号` |
| 4 | 找调用者 | `grep` 该符号被谁引用，确认不是死代码 | 这一条决定"能不能算已实现" |
| 5 | 对照第一遍 | `/Users/main/AgentFlow` 同名模块 | 标"真正接入 / 只有代码" |
| 6 | 确认目标定位 | `/Users/main/WorkAgentHarness` 现状与规划 | 只做架构决策，不预复制目录 |

这一章的产物不是代码，而是"后面所有章节的对账依据"。第 2 章开始每次改代码，都用这里的 commit 作为对照起点。

## 按顺序完成

1. 记录三仓库 `git rev-parse HEAD` 和 `git status --short`，保存到 `doc/dev/学习记录/起点/`。
2. 阅读 EvoFlow 根 README、`backend/ARCHITECTURE.md`、LICENSE、NOTICE。写出应用层与核心层边界、许可限制和第三方依赖边界。
3. 用"用户发一条消息并得到回复"练习追踪：从 UI/API 入口找调用者、配置/model、Agent、状态写入和响应返回。粗图先行，再逐段拿代码验证。
4. 在 AgentFlow 第一遍实现中找对应功能，标记哪些是真正接入、哪些只有代码/文档但缺调用者。
5. 浏览 WorkAgentHarness 现状和总规划，确认项目自己的架构决定；不要为复刻预先复制 EvoFlow 目录。
