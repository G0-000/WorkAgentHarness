## 场景

你把 30 个文件拖进知识库：有 PDF 报告、Word 方案、PPT 汇报、还有几个 `.md` 笔记。然后问："我们上一季度的续费率是多少？"

Agent 要回答，必须先做三件事：

1. **收下文件**：放到本次会话专属的目录，别人不能覆盖；
2. **变成文本**：PDF 要抽文字，PPT 要抽幻灯片文字；
3. **切成块**：一整个 PDF 塞不进上下文，得切成能被检索的小段。

任何一步出问题，后面全废：路径没校验 → 可以写到系统目录；切块按字数硬切 → 一句话被从中间劈开，检索出来的片段没法读。

## 本章要完成的功能

| 功能 ID | 要达成的行为 | 用户可见结果 |
|---|---|---|
| `WAH-KNOW-001` | 上传与文件管理：按 thread 隔离目录、重名去重、路径穿越拦截 | 文件不会串到别的会话，也不会覆盖别人 |
| `WAH-KNOW-002` | 解析与切块：多格式转文本，按段落优先切块并保留重叠 | 检索能找到"一整句话"，不是半句 |

## 本节业务问题

| 问题 | 后果 |
|---|---|
| 上传目录不按 thread 隔离 | 两个会话互相覆盖文件 |
| 文件名不规范化 | `../../etc/passwd` 或空文件名写入成功 |
| 重名直接覆盖 | 后传的覆盖先传的，用户以为还在 |
| 只支持纯文本 | PDF/Word/PPT 一律失败 |
| 只按字数硬切 | 段落、表格行被劈开，检索结果读不懂 |
| 切块无重叠 | 关键句正好落在切口，两边都搜不到 |

## EvoFlow 源码阅读路径

**原版是"上传层 → 解析层 → 切块层"三段，各自独立文件**。

| 层 | 文件与真实符号 | 作用 |
|---|---|---|
| ① 上传目录 | `uploads/manager.py:25` `validate_thread_id(thread_id)`；`:35` `get_uploads_dir(thread_id)`；`:41` `ensure_uploads_dir` | 每 thread 一个目录 |
| ② 上传安全 | 同文件 `:17` `class PathTraversalError(ValueError)`；`:101` `validate_path_traversal(path, base)`；`:48` `normalize_filename(filename)`；`:76` `claim_unique_filename(name, seen)` | 拦截 `../`、清洗文件名、重名改名 |
| ③ 列文件 | `:113` `list_files_in_dir(directory)` | 给 UI / 索引层读 |
| ④ 解析 | `knowledge/parser.py:55` `parse_file(...)`；`:112` `_convert_with_markitdown`；`:102` `_format_context(doc_id, kb_id, path)` | 统一入口，优先 markitdown |
| ⑤ Office 兜底 | `:181` `_fallback_pptx(p)`；`:204` `_convert_office_fallback(p)`；`:168` `_try_format_fallback` | markitdown 失败时的第二方案 |
| ⑥ 切块 | `knowledge/chunker.py:37` `chunk_text(...)`；`:128` `_split_paragraphs`；`:155` `_make_chunk(parts, char_start, char_end)`；`:166` `_hard_split(text, chunk_size, overlap)`；`:30` `_count_tokens` | 段落优先 + 超长硬切 + 重叠 |
| ⑦ Wiki 专用切块 | `knowledge/wiki_chunker.py` | 按标题层级切，与普通文档不同 |

逐层追读要点：

1. **入口**：上传是谁触发的（HTTP 上传路由 / CLI）？`thread_id` 从哪来。
2. **调用者**：`parse_file` 的调用方是 `pipeline` 还是 worker。
3. **核心决策**：切块的 `chunk_size` / `overlap` 默认值是多少、按字符还是 token（`_count_tokens` 的存在说明有 token 口径）。
4. **状态**：解析结果存哪（DB 还是文件）、chunk 的 `char_start` / `char_end` 是否保留。
5. **返回**：`_make_chunk` 产出的 dict 有哪些字段。
6. **证据**：`PathTraversalError` 是独立异常类型，说明这是被测试覆盖的安全边界。

## 调用流程

```text
上传请求（thread_id + file）
  ▼
① 校验         validate_thread_id → get_uploads_dir → ensure_uploads_dir
  ▼
② 文件安全      normalize_filename → claim_unique_filename(seen)
  ▼
③ 落盘        validate_path_traversal(path, base) → 写文件
  ▼
④ 解析        parse_file → _convert_with_markitdown
  │             └ 失败 → _try_format_fallback → _fallback_pptx / _convert_office_fallback
  ▼
⑤ 切块        chunk_text(text, chunk_size, overlap)
  │             ├ 先 _split_paragraphs 按段落
  │             └ 单段超长 → _hard_split
  ▼
⑥ chunk 记录   _make_chunk(parts, char_start, char_end) → 入库
```

## WorkAgentHarness 现状与设计

**现状**：完全没有知识库能力。第三篇的 `workspace_file.py` 只能读工作区内已存在的文本文件，**既不能上传也不能解析**。

| 缺口 | 设计方案 | 边界 |
|---|---|---|
| 上传目录 | `<cwd>/.wah/uploads/<thread_id>/`，`thread_id` 必须匹配 `[A-Za-z0-9_-]+` | 不做用户级隔离 |
| 安全 | 照搬三点：`normalize_filename`、`claim_unique_filename`、`validate_path_traversal` | 拒绝绝对路径与 `..` |
| 解析 | **只做纯文本**：`.md` / `.txt` / `.py` / `.json`，UTF-8 读取 | 不做 PDF/Word/PPT（不引 markitdown） |
| 切块 | 段落优先（空行分割）→ 每块约 400 字 → 相邻重叠 50 字 | 不做 token 口径 |
| 记录 | `kb_chunks(id, doc_id, ord, char_start, char_end, content)` | 字段对齐 `_make_chunk` |
| Wiki 切块 | 不做 | 本项目不做 wiki |

**为什么不引 markitdown**：本项目没有 Office 文档输入源，引一个大依赖只为"看起来对齐"不值。这条偏差要写进差异表，不能 pretend。

## 与 EvoFlow 的差异

| 项 | EvoFlow | 本项目 |
|---|---|---|
| 上传目录 | `get_uploads_dir(thread_id)` | 同名设计，落在 `.wah/uploads/` |
| 安全函数 | `validate_path_traversal` / `normalize_filename` / `claim_unique_filename` | 三个同名对齐 |
| 支持格式 | PDF/Word/PPT/MD/HTML 等（markitdown + 两套兜底） | 只有纯文本 |
| 解析入口 | `parse_file(...)` + 三级 fallback | 单函数 `parse_text(path)` |
| 切块 | `chunk_text` + 段落优先 + `_hard_split` + overlap | 同名思路，参数更小 |
| 切块口径 | 有 `_count_tokens`（token 口径） | 字符口径 |
| Wiki 切块 | `wiki_chunker.py` | 不做 |
| 异常类型 | `PathTraversalError(ValueError)` | 对齐，用同名异常 |
