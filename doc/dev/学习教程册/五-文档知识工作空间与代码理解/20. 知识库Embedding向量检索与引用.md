## 场景

第 19 章把 30 个文件切成了 800 个 chunk。现在用户问："上一季度续费率是多少？"

如果只做向量检索，会有两个典型失败：

- 用户问"续费率"，向量检索返回一堆"费用""费率"的相近段落，但**没有一条是带具体数字的**——数字往往在表格里，语义向量对数字不敏感；
- 用户问一个**专有名词**（比如内部项目代号 `Phoenix-2`），向量模型没见过这个词，检索不出来。

所以真做检索，必须**关键词 + 向量两条路一起走，再融合排序**。这就是本章要讲的东西。

## 本节业务问题

| 问题 | 后果 |
|---|---|
| 只做向量检索 | 数字、专有名词、精确短语检索不到 |
| 只做关键词检索 | 同义表达（"续费" vs "留存"）检索不到 |
| 两路结果直接拼接 | 前 10 条全是同一路，另一路一条进不来 |
| 换 embedding 模型直接覆盖旧表 | 维度不同，旧向量作废，全库要重建 |
| 命中没有出处 | 用户无法核对，回答不可信 |
| 中文没做重叠度 | `_cjk_overlap` 缺失时中文短语命中率骤降 |

逐层追读要点：

1. **入口**：检索被谁调用（知识库工具 `kb_search_tool` / 聊天前置检索）。
2. **调用者**：`rrf_fuse` 的输入是三路各自的 top_k，输出排好序的列表。
3. **核心决策**：RRF 的 `k` 常数是多少；`rerank_by_query_match` 用什么打分。
4. **状态**：向量表名由 `dim + model` 组成，意味着**一个 kb 可有多张向量表**。
5. **返回**：`enrich_hits` 加了哪些字段（出处？文件名？偏移？）。
6. **证据**：`_cjk_overlap` 的存在说明中文不是靠空格分词的，这一条最容易漏。

## 调用流程

```text
用户提问
  ▼
① 三路并发
  ├ search_keyword(kb_id, query, top_k=20)   ← FTS/BM25
  ├ search_vector(...)                       ← 余弦
  └ search_title(kb_id, query, top_k=20)     ← 标题
  ▼
② 融合      rrf_fuse(三路结果)                ← Reciprocal Rank Fusion
  ▼
③ 重排      rerank_by_query_match(items, query)
  ▼
④ 补出处    enrich_hits(hits) → 文件、doc_id、char_start/char_end
  ▼
⑤ 进上下文  按预算截断后注入
```

## WorkAgentHarness 现状与设计

**现状**：没有知识库。第 19 章的设计也停在"切块入库"，没有 embedding 与检索。

| 缺口 | 设计方案 | 边界 |
|---|---|---|
| Embedding | 定义一个 `Embedder` 接口：`embed(texts) -> list[list[float]]`；本地实现先做**假向量**（哈希投影，维度 64） | 不接真实模型，避免额度依赖 |
| 向量存储 | 直接存 SQLite：`kb_vectors(kb_id, dim, model, chunk_id, vec BLOB)` | 不装 sqlite-vec 扩展 |
| 关键词检索 | 复用 SQLite `LIKE` + 手写打分（词命中数 / 查询词数） | 不接 FTS5 |
| 向量检索 | 读 BLOB → `cosine` 逐个算（800 chunk 量级够用） | 不做 ANN 索引 |
| 融合 | 照 RRF 公式：`score = Σ 1/(k + rank)`，`k=60` | 对齐 `rrf_fuse` 的思路 |
| 出处 | 命中带 `doc_id` / `chunk_ord` / `char_start` | 对齐 `enrich_hits` |
| 数据集管理 | 不做多库，单库 `default` | 第 21 章再谈 Owned |

**为什么用假向量**：本章要验证的是"三路检索 + 融合 + 出处的链路"，不是 embedding 模型质量。用确定性假向量能把链路测通，换真模型时只替换一个实现。

## 与 EvoFlow 的差异

| 项 | EvoFlow | 本项目 |
|---|---|---|
| 检索路数 | 三路（关键词 / 向量 / 标题） | 三路（同） |
| 融合 | `rrf_fuse(...)` | 同名同公式，`k=60` |
| 重排 | `rerank_by_query_match(...)` | 只做简单加权，不做二次重排 |
| 向量表 | 按 `kb_id + dim + model` 分表，支持多模型 | 单表，`dim/model` 存列 |
| 向量索引 | sqlite-vec 扩展 | 无扩展，逐个余弦 |
| Embedding provider | 本地 + 云端 registry | 假向量（哈希投影） |
| 中文处理 | `_cjk_overlap` | 字符二元组重叠（简化） |
| 数据集 | 多 dataset + folder | 单库 |
| 出处 | `enrich_hits` | 对齐字段 |
