# WorkAgentHarness × EvoFlow 逐章仿写教程册

> 这是主学习教材，不是功能清单。每章带你从用户行为读 EvoFlow，再按 L1 最小闭环 → L2 真实入口和状态 → L3 功能补齐 → L4 失败与边界，在 WorkAgentHarness 亲手实现。EvoFlow 是源码教材，AgentFlow 是第一遍学习的复盘样本。

## 使用方法

1. 按篇学习：读篇导读，再打开每章独立教程。不要只看功能 ID 表。
2. 跟着“源码阅读顺序”找到真实调用者，画调用链和状态生命周期；先用代码证据验证文档。
3. 先做 L1，再逐层接入真实入口、持久化、完整行为和边界。每一步都留下可复现操作记录。
4. 把实际状态写入[唯一功能清单](../学习手册/功能清单.md)，不要另维护第二套状态。
5. 每章末节固定为「本章代码测试与验收」，每篇末章固定为「本篇综合测试与验收」，第 60 章为课程级验收；三级都过了才算本篇完成。

   **验收类型跟着章节标**：每章验收节首行写明是「理解验收」还是「运行验收」。理解验收（源码阅读、架构边界、调用链、数据流）可用路径/符号、图或书面说明交差；运行验收（代码行为、命令、持久化、协议、入口、集成）必须有预期与实测，并注明依赖真伪。第 1 章为理解验收，第 2–18 章为运行验收（第 2、7、13、18 章是篇级集成）；第 19–60 章为理解验收（设计态，未来运行条件仅登记）。
6. WorkAgentHarness 自身模块讲解写到 `doc/code/`；学习过程写到 `doc/dev/学习记录/`。

当前路线登记 129 个稳定功能 ID（121 个首轮 + 8 个 8e462a37 增补），分配到 60 章；正式课程为 13 篇、60 章；每篇最后一章固定为「本篇综合测试与验收」；第 1 篇为导学，第 2–13 篇各含若干章。以实际源码用户行为为准，发现新能力要补 ID 和教程，不把数量当永远固定上限。

> 教材目标快照为 EvoFlow `8e462a37ba584c17feffa8c1bb22c3b53d98a057`（2026-11-10，工作区干净）。第 1–13 章已于 2026-11-10 在新快照/本仓复跑，逐项证据见[复跑记录](../学习记录/快照8e462a37复跑记录.md)；旧表保留 `1e393d9` 原日期与输出。第 14–18 章已于 2026-11-10 实现并验收（57 例，见[第四篇第15–18章验收记录](../学习记录/第四篇第15-18章验收记录.md)）；第 19–60 章无实现、未验收。

## 每章交付

- 用户场景、EvoFlow 源码快照、AgentFlow 第一遍证据。
- 入口→调用者→核心逻辑→状态/依赖→返回的调用链图。
- L1–L4 分步实现、真实/fake 依赖说明和可复现验收记录（L1–L4 只适用于实现态章节；设计态章节以「本章实作单」登记未来实现项，转入实现时再按 L1→L4 执行）。
- 失败、权限、并发、取消、恢复等适用边界。
- 用自己的话讲清输入、状态变化和结果的短讲解。
