## 场景

用户已经有一个"聊天客户端"——它认 OpenAI 的 `/v1/chat/completions` 格式。

现在想让这个客户端接上你的 Agent。有两条路：

1. **改客户端**：自己写一套对接，麻烦；
2. **让 Gateway 装成 OpenAI**：客户端以为在调 OpenAI，实际后面是你的 Agent。

第 2 条就是"兼容协议"的价值：**不用改客户端**。代价是 Gateway 要处理两套语义的差异（比如 OpenAI 的 `stream` 是分块 JSON，你的内部事件是另一种格式）。

再加上语音：客户端可能发语音，Gateway 要转文字再进 Agent。

## 本节业务问题

| 问题 | 后果 |
|---|---|
| 协议语义不对齐 | 客户端能连上，但流解析错乱 |
| 不处理 `stream=false` | 只支持流式，非流式客户端直接崩 |
| 错误格式不兼容 | 客户端只认 OpenAI 的 error 结构 |
| 语音不做格式校验 | 上传任意文件都当音频处理 |
| 语音不落原文 | 转完就丢，用户看不到自己说了什么 |
| 代理端点无隔离 | 外部能直接操作内部图状态 |

## EvoFlow 源码阅读路径

| 层 | 文件与真实符号 | 作用 |
|---|---|---|
| ① 端口解析 | `app_server/embed.py:17` `resolve_app_server_listen_port()` | 嵌入式场景的端口 |
| ② 基址解析 | `:28` `resolve_gateway_base_url_for_embed()` | 对外访问地址 |
| ③ 协程隔离 | `platform/isolated_loop.py:14` `run_coroutine_on_fresh_loop(coro)` | **在全新事件循环里跑协程** |
| ④ 兼容层 | 兼容协议与 LangGraph 代理主要由 Gateway 侧实现（`app_server/` 只做桥接与地址解析） | 本章重点是"桥"而非"协议实现主体" |

**`run_coroutine_on_fresh_loop` 值得单独记**：当调用方已经在某个事件循环里（比如 Jupyter、某些 SDK），不能直接 `asyncio.run`，必须开一个新 loop 来跑。这是"嵌入式集成"必踩的坑。

逐层追读要点：`resolve_app_server_listen_port` 的默认值与"端口占用时怎么办"。

## 调用流程

```text
OpenAI 客户端发 /v1/chat/completions
  ▼
① 解析请求     messages → 内部消息格式
  ▼
② 建会话       thread_id（无则新建）
  ▼
③ 跑 Agent     run_coroutine_on_fresh_loop → 避免嵌套循环冲突
  ▼
④ 转流式       stream=true → 分块 JSON（OpenAI 格式）
  │             stream=false → 一次性返回
  ▼
⑤ 错误映射     内部错误 → OpenAI error 结构
  ▼
⑥ 语音（可选） 音频 → 转文本 → 当作 user message
```

## WorkAgentHarness 现状与设计

**现状**：无兼容层、无语音。

| 缺口 | 设计方案 | 边界 |
|---|---|---|
| 兼容端点 | `POST /v1/chat/completions`，只实现 `stream=true` | 不支持 `stream=false` |
| 消息映射 | `messages[-1].content` → 内部 user 消息 | 不支持多轮历史回放 |
| 事件映射 | 内部 `token` 事件 → `data: {choices:[{delta:{content}}]}` | 单 choices |
| 错误映射 | `{error: {message, type}}` | 三种 type |
| 语音 | **不做** | 无 STT 依赖 |
| LangGraph 代理 | **不做** | 无外部图暴露 |
| 协程隔离 | 若接入 FastAPI，直接 `async def` 即可，不需要新 loop | 不做 `run_coroutine_on_fresh_loop` |

**要写清的一条**：本项目做兼容层只为"能接一个现成客户端"，**不做双向全兼容**（OpenAI 的 `tools` / `function_call` 语义都不支持）。

## 与 EvoFlow 的差异

| 项 | EvoFlow | 本项目 |
|---|---|---|
| 协议覆盖面 | 较完整（含 LangGraph 代理） | 单端点、单流式 |
| 语音 | 有 | 不做 |
| 协程隔离 | `run_coroutine_on_fresh_loop` | 不需要（纯 async） |
| 端口/基址 | 两个解析函数 | 配置项 |
| 工具调用语义 | 支持 | 不支持 |
