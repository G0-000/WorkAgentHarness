逐层追读并记笔记：
1. **入口**：route/CLI/UI/channel/启动注册中谁触发；输入 schema、身份、配置从哪里来。
2. **调用者**：谁调用领域能力；它是真实产品路径还是内部/诊断用例。
3. **核心行为**：找到决策函数与状态转移，分清适配层和业务逻辑。
4. **状态**：实体、字段、owner、存储、读写者、过期/删除、恢复方式。
5. **返回**：结果、事件或 UI 如何交给用户；异常在哪里转换。
6. **证据闭环**：反查配置、迁移、启动注册、相关测试和产品文档，给每条判断标路径/符号。

## WorkAgentHarness 仿写流程

### L1：只做一个可解释的最小闭环
目标：fake channel 收/发消息。

先实现领域输入/输出契约、一个核心用例和最简单 fake adapter。只保留完成这个场景必须的逻辑；不要引入尚未需要的数据库、队列或复杂框架。写清 fake 掉的依赖和它不能证明的边界。

### L2：接真实入口与状态
目标：经 bus/manager 跑通 Agent 往返。

把 L1 用例放到真实入口后面。入口只做协议解析、身份与依赖装配，核心层不依赖 HTTP/UI 类型；若有状态先确认数据 owner、迁移和事务，再接 repository；若有外部服务，定义 timeout/error/credential contract。证明真实入口最终调用同一个核心用例。

### L3：按功能路线补齐
目标：按快照逐渠道核对 webhook/poll、签名、去重、事件持久化。

把功能路线的每个完整出口拆成单项行为，按“实现→调用者接线→用户可见结果→证据”逐项完成。为每个变体标出其 EvoFlow caller、WorkAgentHarness 路径、配置、状态和结果；无 caller 的部分需标为内部/待核，而非默认当成功能。

### L4：验证失败和边界
目标：测重试、断开、关机和权限。

按本章功能选择适用场景：无效输入、依赖失败、超时、重复提交、并发冲突、越权、取消、重启恢复、清理/删除。逐项观察持久化状态和用户结果。不适用的项也写理由。
