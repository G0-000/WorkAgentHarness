## 场景

第三篇结束时，CLI 已经能跑通：输入一句话，Agent 调工具，SSE 事件打印出来。

但用户不在终端里。他在浏览器/客户端里点"发送"，要看到字**一个字一个字地出来**。

这中间缺的东西：

1. **一个服务**：监听端口、处理 HTTP 请求；
2. **一份依赖清单**：哪些是启动必需的，哪些可以缺；
3. **一个聊天 API**：`POST /chat` 进来、SSE 出去。

第 2 点最容易被忽略：Gateway 启动时如果连数据库密码都没配好，应该**立刻失败并说清缺什么**，而不是启动成功后第一个请求才崩。

## 本章要完成的功能

|---|---|---|

| `WAH-API-008` | 嵌入式/stdio 入口：不占端口的接入方式 | 桌面客户端可直连 |

## 本节业务问题

| 问题 | 后果 |
|---|---|
| 启动不检查依赖 | 启动成功，第一个请求 500 |
| 依赖清单不区分必需/可选 | 缺可选依赖也让服务起不来 |
| 聊天 API 不流式 | 用户等 30 秒才看到第一个字 |
| SSE 帧格式不统一 | 前端解码失败 |
| Auth header 不传递 | 下游拿不到用户身份 |
| 无 stdio 入口 | 桌面客户端必须起端口，易冲突 |

## EvoFlow 源码阅读路径

**`app_server/` 只有 3 个文件，`platform/` 只有 2 个**——规模小，说明它专注"桥接"，不自己做完整 HTTP 框架。

| 层 | 文件与真实符号 | 作用 |
|---|---|---|
| ① 聊天桥 | `app_server/chat_bridge.py:61` `_auth_headers(authorization)` | **把用户 token 带到下游** |
| ② 流地址 | `:130` `_build_stream_url(gateway_base, thread_id, query)` | 拼流式端点 |
| ③ 帧解析 | `:153` `_parse_sse_frame(payload)` | 解析 `event:` / `data:` |
| ④ 并发保护 | `:21` `_client_lock()` | asyncio 锁 |
| ⑤ stdio 服务 | `app_server/stdio_rpc.py:26` `class StdioAppServer`；`:503` `serve_stdio(...)`；`:684` `main_argv(argv)` | **不占端口的 RPC** |
| ⑥ 编码 | `:486` `_force_utf8_stdio(stream)` | Windows 下的 UTF-8 强制 |
| ⑦ 事件循环隔离 | `platform/isolated_loop.py`；`platform/asyncio_windows.py` | 平台差异 |

逐层追读要点：`_force_utf8_stdio` 存在说明作者踩过"Windows 控制台编码"的坑；`_client_lock` 说明 chat_bridge 是**单例共享客户端**。

## 调用流程

```text
客户端 POST /chat
  ▼
① 鉴权          authorization header → _auth_headers
  ▼
② 建 thread     thread_id → _build_stream_url
  ▼
③ 起 Agent      交给运行时
  ▼
④ 流式返回      SSE 帧（event + data）
  ▼
⑤ 客户端解码    _parse_sse_frame → event 类型分发
  ▼
⑥ 收尾          done 事件 → 关闭连接

（另一条路）
客户端 stdio → StdioAppServer → serve_stdio → 同一套业务逻辑
```

## WorkAgentHarness 现状与设计

**现状**（第三篇已核实）：
- `app_server/sse.py` 有 `build_sse_response` / `create_sse_app`，但依赖里**只有 starlette，没有 fastapi/uvicorn**，**不提供独立 HTTP 服务进程**。
- `events/sse.py` 有 `encode_sse_event` / `EventBuffer`（内存 deque，200 条）。

| 缺口 | 设计方案 | 边界 |
|---|---|---|
| HTTP 服务 | 用 `starlette` + `uvicorn` 起一个 | 新增 `uvicorn` 依赖 |
| 依赖检查 | 启动时检查：db 可写、workspace 存在、config 可解析 | 缺一项即退出码 1 |
| 聊天 API | `POST /threads/{id}/messages` → 返回 SSE | 单端点 |
| Auth 传递 | 透传 `Authorization` 到下游（当前无身份体系） | 第 48 章才有主体 |
| stdio 入口 | **不做** | 桌面客户端不在本项目范围 |
| 事件循环 | 不做平台隔离 | 只支持 Linux/macOS |

**要写清的一条**：本章会**新增一个依赖**（uvicorn）和一个**常驻进程**，这是本项目第一次有"服务"。写之前要先确认用户接受这个跨度。

## 与 EvoFlow 的差异

| 项 | EvoFlow | 本项目 |
|---|---|---|
| HTTP 框架 | 完整 Gateway（多路由） | starlette + uvicorn，单端点 |
| 鉴权透传 | `_auth_headers` | 预留，暂不实现 |
| SSE 解码 | `_parse_sse_frame` | 只编码不解码 |
| stdio 入口 | `StdioAppServer` + `serve_stdio` | 不做 |
| 平台适配 | `asyncio_windows` / `isolated_loop` | 不做 |
| 依赖检查 | 有启动检查 | 三项最小检查 |
