## 本篇三条澄清

1. **子代理是三级解析，不是一层**。`subagents/` 6 文件：先按**名字**找，再按**类型**，最后落到**配置**；`SubagentStatus` 四态 + `_subagent_should_stop`。原版还有租约（`collab_subtask_lease_seconds`），**本项目不做**——单进程没有租约的需求。
2. **沙箱默认是拒绝**。`sandbox/` 7 文件：`SandboxProvider(ABC)` + `_resolve_provider_class(use)` 动态选实现；`is_host_bash_allowed` **默认返回拒绝**；`build_shell_argv` 再分平台包装（`_linux_wrapper_argv` / `_windows_wrapper_argv`）。本项目直接宿主执行，**这是安全边界缺失**，不是"简化"。
3. **审批只有三档，且取消不是真中断**。`allow / ask / deny`（对齐 EvoFlow `AskForApproval`），记录在 `run_approvals` 单表。取消是"打标记"，**不会真停掉已经在跑的模型调用**——这一点在第二篇 6.1 已经写清，不要在本篇重复承诺"取消即停止"。

## 本篇综合练习（文档级，不跑代码）

场景：用户让 Agent"删掉 build 目录下的旧产物"。

1. 这条请求会走到哪个工具？（`terminal_tool`）
2. `_DANGEROUS_PATTERNS:38` 会不会命中 `rm -rf`？
3. 命中后走三档里的哪一档？
4. 如果用户点"批准"，执行时还有没有第二道检查（`_check_dangerous:153`）？
5. 执行完的审计记录落在 `middleware/tool_audit.py:28` 的哪条路径？

把五步写在一张表里，标注每步在**本项目**是"有 / 无 / 有但未接"。
