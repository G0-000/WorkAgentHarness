## 场景

Agent 要执行 `rm -rf build && npm run build`。

这里有三种可能的运行位置：

1. **宿主机**：直接在你的 Mac 上跑——最快，但也能删你的文件；
2. **本地容器**：在沙箱里跑——安全一点，但慢、镜像要预热；
3. **远端**：在服务器上跑——最隔离，但要配置凭据和网络。

同一个 Agent 在不同机器上该用哪种，取决于**配置**，不是代码里写死。这就是"provider 抽象 + 策略"要解决的事。

## 本章要完成的功能

## 本节业务问题

| 问题 | 后果 |
|---|---|
| 实现里写死"在本地跑" | 换到服务器没有办法 |
| 不做 provider 抽象 | 每加一种运行环境就要改所有工具 |
| 命令字符串直接丢给 shell | 注入、转义、管道语义全不可控 |
| 权限只看配置不看默认 | 没配的时候默认最宽松 = 最危险 |
| 平台差异不处理 | Windows 的 argv 语义和 Linux 不同，包装失效 |
| 无关闭/重置 | 测试之间 provider 泄漏 |

## 调用流程

```text
终端工具要执行命令
  ▼
① 权限判定   is_host_bash_allowed(config) → 允许宿主 / 必须沙箱
  ▼
② 选 provider get_sandbox_provider() → SandboxProvider 实例（单例）
  ▼
③ 装配 argv   build_shell_argv(command)
  ▼
④ 分平台包装  wrap_argv_for_sandbox → _linux_wrapper_argv / _windows_wrapper_argv
  ▼
⑤ 执行       run_sandboxed(...) → SandboxRunResult
  ▼
⑥ 返回       退出码 + stdout + stderr → 交给工具结果协议（第三篇 8.2）
```

## WorkAgentHarness 现状与设计

**现状**：第三篇的 `terminal_tool.py` 直接在**宿主机**跑（`subprocess`），只有 `_check_dangerous` 做正则拦截。没有沙箱。

| 缺口 | 设计方案 | 边界 |
|---|---|---|
| provider 抽象 | `sandbox.py`：`class SandboxProvider(ABC)` + `HostProvider` 一个实现 | 不做容器/远端 |
| 选择 | `get_provider(use: str)`，`use="host"` 唯一合法值 | 未知值抛错，不静默降级 |
| 权限 | `is_host_bash_allowed(config)`：默认 **False**（未配置不允许宿主） | 对齐"默认最严" |
| 命令装配 | `build_argv(command)`：`shlex.split` 后检查首词 | 只支持单条命令，不支持管道 |
| 结果 | `RunResult(exit_code, stdout, stderr, duration_ms)` | 对齐 `SandboxRunResult` |
| 平台 | 只处理 POSIX | 不做 Windows 包装 |

**关键改动方向**：第三篇是"裸跑 + 正则拦"，本章要把"正则拦"升级为"**provider 闸门 + 命令装配**"两层。这一层的差异必须写清楚，否则读者以为第三篇已经安全了。

## 与 EvoFlow 的差异

| 项 | EvoFlow | 本项目 |
|---|---|---|
| provider 种类 | 宿主直通 / 本地沙箱 / 远端（可插拔） | 仅宿主 |
| 选择机制 | `_resolve_provider_class(use)` 动态解析 | 字符串白名单 |
| 默认策略 | `is_host_bash_allowed(config=None)` 有兜底 | 默认拒绝 |
| argv 包装 | 分 Linux/Windows | 仅 POSIX |
| 生命周期 | `reset` / `shutdown` / `set` | 不做单例管理 |
| 危险拦截 | 安全模块 + 审批（第 26 章） | 正则（第三篇）+ 闸门（本章设计） |
