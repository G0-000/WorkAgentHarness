## 场景

一个会话有三种状态，用户能感知到：

1. **开工前**：这次会话只给了"查资料"工具，但 Agent 却想跑 shell——**绑定**决定它能不能。
2. **执行中**：Agent 要跑 `git push --force`——**审批**决定是弹窗问用户、还是直接拒、还是放行。
3. **不想要了**：用户点了"停止"，但子进程还在跑——**取消 + 清理**决定它能不能真的停下。

三件事独立又咬合：绑定不对，审批问错人；审批不落库，重启后状态丢失；取消只标记不杀进程，任务会继续烧资源。

## 本节业务问题

| 问题 | 后果 |
|---|---|
| 工具不按会话绑定 | 只读会话也能跑 shell |
| 绑定模式不持久化 | 重启后回到默认宽松模式 |
| 审批只有"允许/拒绝" | 没法表达"这次允许、下次别问" |
| 审批决策不落库 | 事后查不到谁批了 `rm -rf` |
| 取消只置标记 | 子进程继续跑，用户以为停了 |
| 取消不清理派生任务 | 子代理还在跑，父任务已取消 |

## 调用流程

```text
会话开始
  ▼
① 取会话键    resolve_chat_session_key / resolve_thread_id_from_runtime
  ▼
② 读持久模式  get_persisted_session_mode → resolve_persisted_binding_mode
  ▼
③ 挂工具      agent_tools → 只挂该模式允许的工具
  ▼
④ 危险命令    decide_shell_approval(policy, command) → ApprovalDecision
  │             ├ allow  → 执行
  │             ├ ask    → 弹窗（用户批/拒）
  │             └ deny   → 直接拒
  ▼
⑤ 落库        persist → decision_as_dict(decision)
  ▼
⑥ 用户取消    task_cancellation → cancellation_checks 在各检查点生效
  ▼
⑦ 连带清理    cancel_background_tasks_for_parent_thread
```

## WorkAgentHarness 现状与设计

**现状**：
- **无绑定**：`make_lead_agent` 每次挂同一套工具（第三篇的 4 个）。
- **无审批**：只有第三篇 `ToolAuditMiddleware` 做审计（记录），**不拦**。
- **取消**：`run_repository` 有 `cancel` 状态，但注释已写明"cancel ≠ 真中断"。

| 缺口 | 设计方案 | 边界 |
|---|---|---|
| 绑定 | `binding.py`：`SessionMode = read_only / default / full`，决定工具集合 | 不做 scenario 维度 |
| 持久化 | `session_mode` 列存在 `sessions` 表 | 不复用新表 |
| 审批档位 | 三档：`allow / ask / deny`，对齐 `AskForApproval` | 不做 `ask_for_approval` 的子档 |
| 决策对象 | `ApprovalDecision(action, reason, command)` | 对齐字段 |
| 落库 | `run_approvals(run_id, command, action, reason, created_at)` | 单表 |
| 取消 | 复用 `run_repository.cancel` + CLI 收到 SIGINT 时写 cancel | 仍**不真杀进程**（要写清楚） |
| 清理 | 取消后杀子进程：`proc.terminate()` | 仅前台进程，后台会话不做 |

**必须写清楚的一条**：本项目的 cancel 仍是"标记 + 下次检查点生效"，**不是真中断**。第三篇已经标过，本章不重复承诺。

## 与 EvoFlow 的差异

| 项 | EvoFlow | 本项目 |
|---|---|---|
| 绑定维度 | 会话键 + scenario 多维度 | 会话模式三档 |
| 绑定来源 | 持久化 + 运行时双解析 | `sessions` 表一列 |
| 审批档位 | `AskForApproval` 枚举，策略映射 | 三档同名 |
| 审批持久化 | 独立 `persist.py` | `run_approvals` 单表 |
| 取消机制 | 任务级取消 + 多检查点 | run 级标记 |
| 连带取消 | 父子线程级联 | 只杀前台进程 |
| 审计 vs 审批 | 两者分离 | 第三篇只有审计，本章补审批 |
