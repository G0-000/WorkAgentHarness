## 场景

用户说："这个功能前后端都要改，你安排人做。"

主 Agent 不能自己一个人干完，它要：

1. **挑人**：从已有的子代理里选——有专门写后端的、专门写前端的；
2. **派活**：给每个子代理一个提示词、一套工具、一个超时；
3. **收结果**：两个子代理都回话后，合并成一份答复给用户；
4. **兜底**：一个跑飞了（循环不停）或超时，得能停它。

这里最容易出问题的是第 1 步和第 4 步：**选错人 → 做完是错的；停不下来 → 一直烧钱**。

## 本节业务问题

| 问题 | 后果 |
|---|---|
| 子代理按字符串硬编码挑 | 改名后全线崩 |
| 子代理无超时 | 一个卡住的代理拖垮整轮 |
| 无停止判定 | 子代理循环调用工具直到上下文爆掉 |
| 结果无状态机 | 分不清"成功但空"和"失败" |
| 无租约 | 重试时同一个子任务被并行跑两遍，写冲突 |
| 汇总只拼文本 | 两个子代理的冲突结论没人处理 |

## 调用流程

```text
主 Agent 决定委派
  ▼
① 解析    resolve_subagent_type(name) → get_subagent_config(name)
  ▼
② 装配    _agent_config_to_subagent_config → 提示词 + 工具 + 超时
  ▼
③ 占租约  collab_subtask_lease_seconds → is_subtask_background_executor_active
  ▼
④ 执行    executor → SubagentResult（status + output）
  ▼
⑤ 判停    _subagent_should_stop(result) → 停止 / 继续
  ▼
⑥ 汇总    主 Agent 合并多份 SubagentResult
  ▼
⑦ 清理    cancel_background_tasks_for_parent_thread
```

## WorkAgentHarness 现状与设计

**现状**：没有子代理。当前只有单个 `make_lead_agent`，所有工具都在一个 Agent 里。

| 缺口 | 设计方案 | 边界 |
|---|---|---|
| 注册表 | `subagents/registry.py`：`SUBAGENTS = {"backend": ..., "frontend": ...}` 静态字典 | 不做动态发现 |
| 配置形状 | `SubagentConfig(name, system_prompt, tools, timeout_seconds)` | 对齐原版字段 |
| 状态 | `SubagentStatus`：`ok / failed / stopped / timeout` 四态 | 不做 `pending`（本项目同步执行） |
| 停止判定 | 复用第三篇 `goal_auto_continue.py` 的 `MAX_STEPS=8` 思路，子代理也有步数上限 | 不用租约表 |
| 汇总 | 主 Agent 拿 `list[SubagentResult]`，按 `name` 排序拼接 | 不做冲突检测 |
| 租约 | **不做**（本项目单进程） | 多进程时才需要 |

## 与 EvoFlow 的差异

| 项 | EvoFlow | 本项目 |
|---|---|---|
| 注册来源 | 从 agent 配置派生（`_agent_config_to_subagent_config`） | 静态字典 |
| 类型解析 | `resolve_subagent_type` 带兜底 | 字典直查，查不到报错 |
| 超时 | 配置项（`_timeout_for_subagent`） | 固定 120 秒 |
| 状态 | `SubagentStatus` 枚举 | 四态，少 `pending` |
| 租约 | `collab_subtask_lease_seconds` + 活跃判定 | 不做 |
| 连带取消 | `cancel_background_tasks_for_parent_thread` | 不做 |
| 汇总 | 完整协作账本 | 简单排序拼接 |
