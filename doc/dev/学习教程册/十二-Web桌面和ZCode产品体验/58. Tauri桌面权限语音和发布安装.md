## 场景

用户装了桌面版。它和网页版的区别：

- 能做网页做不到的事：读本地文件、调本地程序、听麦克风；
- 也因此更需要管：一个网页拿到"读文件"权限是灾难，桌面壳不能随便给。

所以 Tauri 这一层的核心不是"打包"，而是**权限清单**：应用声明要哪几个能力，用户/系统来批。

## 本章要完成的功能

## 本节业务问题

| 问题 | 后果 |
|---|---|
| 权限声明过宽 | 一个聊天应用要"读全部文件" |
| 运行时不再校验 | 声明了不校验，等于没声明 |
| 语音不判时长 | 用户按住 10 分钟，一次上传 50MB |
| 语音不判格式 | 任意文件当音频 |
| 无失败回退 | 转写失败，消息丢了 |
| 发布无签名 | 用户装的时候被系统拦 |

## 可核实的后端侧事实

| 层 | 文件与真实符号 | 作用 |
|---|---|---|
| ① 端口 | `app_server/embed.py:17` `resolve_app_server_listen_port()` | 桌面壳起后端时选端口 |
| ② 基址 | `:28` `resolve_gateway_base_url_for_embed()` | 桌面壳访问的基址 |
| ③ 协程 | `platform/isolated_loop.py:14` `run_coroutine_on_fresh_loop(coro)` | 嵌入场景的循环隔离 |
| ④ Windows | `platform/asyncio_windows.py` | 平台差异 |

**`resolve_app_server_listen_port` 存在**说明"端口自动选择"是内嵌场景的真实需求（桌面壳起后端时不能假定 8000 空闲）。

**不可核实的部分**：Tauri 的 `tauri.conf.json`、capabilities 清单、Rust 侧命令、语音前端录音——**都不在这个仓**。本章这四块按通用设计写，不标"EvoFlow 原有"。

## 调用流程

```text
桌面 App 启动
  ▼
① 选端口     resolve_app_server_listen_port
  ▼
② 起后端     子进程（stdio RPC 或 HTTP）
  ▼
③ 建基址     resolve_gateway_base_url_for_embed
  ▼
④ 权限校验   前端调用受限 API 前，按 capabilities 判
  ▼
⑤ 语音       录音 → 上传 → 转文本 → 当作 user message
  ▼
⑥ 失败回退   转写失败 → 提示 + 保留原文音频路径
```
