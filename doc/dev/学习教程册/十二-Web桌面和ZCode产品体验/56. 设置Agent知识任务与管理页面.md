## 场景

第 55 章是"用户日常用"。本章是"用户偶尔改配置"：

- 改模型供应商
- 新建一个 Agent（给它起名、配工具）
- 建知识库、传文件
- 看自动化任务
- 看主动任务待办

这些页面的共同点：**每个都是一组 CRUD**，但每个都有自己的校验规则。

比如"Agent 名字"：不能重名、不能超长、不能带奇怪字符。漏了任何一条，后面都会崩。

## 本节业务问题

| 问题 | 后果 |
|---|---|
| 名称不校验 | 重名、超长、非法字符 |
| 显示文本不消毒 | 用户输入带 HTML，XSS |
| 错误不分类 | 找不到 vs 冲突 vs 参数错，都返回 500 |
| 删除不清理父目录 | 留下一堆空目录 |
| 详情与列表同一接口 | 每次列表都查全量字段 |

## EvoFlow 源码阅读路径

| 层 | 文件与真实符号 | 作用 |
|---|---|---|
| ① 名称校验 | `admin/agents.py:36` `_validate_agent_name(name, *, enforce_max_len=True)`；`:43` `_normalize_agent_name(name)`；`:47` `_require_agent_code(data)` | **校验 + 归一 + 必填** |
| ② 显示消毒 | `:64` `_sanitize_display_text(...)` | 防 XSS |
| ③ 错误分类 | `admin/errors.py:6` `class AdminError(Exception)`；`:15` `NotFoundError(AdminError)`；`:20` `ConflictError(AdminError)`；`:25` `ValidationError(AdminError)` | **三个子类** |
| ④ 技能页 | `admin/skills.py:20` `_skill_row(skill, *, detail=False)`；`:66` `_find_skill(name)`；`:77` `_resolve_skills_base_path()`；`:86` `_prune_empty_parents_under_custom(...)` | 列表/详情分开 + 删后清空目录 |
| ⑤ 其他页 | `admin/`：`models.py`、`knowledge.py`、`tasks.py`、`automation.py`、`items.py`、`employees.py`、`apps.py`、`profile.py` | 一域一文件 |
| ⑥ UI 扩展 | `admin/ui_extensions_registry.py:27` `ExtensionValidationError(ValueError)`；`:31` `ExtensionNotFoundError(LookupError)`；`:35` `ExtensionIOError(RuntimeError)` | 扩展页注册 |

**`_skill_row(skill, *, detail=False)` 的 `detail` 参数**是"列表/详情分开"的实现：列表只要摘要，详情才查全量。没有这个，列表接口会慢。

逐层追读要点：先看 `errors.py` 三个子类（决定了错误怎么呈现），再看 `agents.py` 的三个校验函数。

## 调用流程

```text
用户点"新建 Agent"
  ▼
① 必填检查    _require_agent_code(data) → 缺 code 直接 ValidationError
  ▼
② 名称归一    _normalize_agent_name(name)
  ▼
③ 名称校验    _validate_agent_name(name, enforce_max_len=True)
  │              └ 重名 → ConflictError；非法 → ValidationError
  ▼
④ 显示消毒    _sanitize_display_text(desc)
  ▼
⑤ 落库
  ▼
⑥ 列表返回    _skill_row(..., detail=False) → 摘要
  ▼
⑦ 删除        _prune_empty_parents_under_custom → 清空目录
```

## WorkAgentHarness 现状与设计

**现状**：无 Web、无管理页、无 Agent 管理（Agent 由代码构造）。

| 缺口 | 设计方案 | 边界 |
|---|---|---|
| 设置页 | 不做 | 配置走文件 |
| Agent 管理 | 不做（`make_lead_agent` 由代码定义） | — |
| 名称校验 | 若做，只校验：非空 + ≤32 字符 + `[a-zA-Z0-9_-]` | 对齐 `_validate_agent_name` 思路 |
| 错误分类 | `class AdminError` + 三子类（同原版） | 这是**可以直接对齐**的一点 |
| 知识库页 | 不做 | — |
| 任务页 | CLI `wah items` 输出表格 | 无页面 |
| 删除清理 | 不做（无删除功能） | — |

**能对齐的只有一处**：错误三分类（`NotFoundError` / `ConflictError` / `ValidationError`）。这个结构简单、通用，值得照搬。其余全部不做。
