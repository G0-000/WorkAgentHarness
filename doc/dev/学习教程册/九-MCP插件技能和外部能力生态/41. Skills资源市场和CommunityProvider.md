## 场景

同一个 Agent 要能"会写代码"也能"会做财报分析"。这两件事不该写死在提示词里——提示词会越来越长，最后谁也读不懂。

Skills 的做法：把专业知识放成**一个个文件**（`SKILL.md`），只在需要时才注入提示词。

于是问题变成了三个：

1. **怎么发现**：用户说"帮我审一下这个合同"，怎么知道该用哪个 skill？
2. **怎么注入**：把整份 skill 塞进上下文，还是只塞摘要？
3. **怎么防**：别人给的 skill 里如果写了 `rm -rf /`，怎么办？

第 3 点尤其重要——skill 本质上是**会被模型执行的文本**，等于一份可执行的指令。

## 本节业务问题

| 问题 | 后果 |
|---|---|
| 全量注入所有 skill | 上下文瞬间爆掉 |
| 不做选择 | 审合同的场景带上了"做视频"的技能 |
| 无缓存 | 每轮重新扫目录，慢 |
| 不做安全检查 | 恶意 skill 里的危险命令被执行 |
| frontmatter 不解析 | 没法知道 skill 的名字/描述/触发词 |
| 市场无来源校验 | 装了来路不明的 skill |

**`scan_for_security_issues` 带 `is_code` 参数**：说明"代码类 skill"和"文档类 skill"的检查规则不同——代码类要查危险命令，文档类查注入话术。

逐层追读要点：`extract_skill_mentions` 是显式点名（用户说"用 xx skill"），`select_skills_for_turn` 是自动选择，两条路径并存。

## 调用流程

```text
用户输入
  ▼
① 扫描目录    _build_mtime_map → 变了才重扫
  ▼
② 解析        frontmatter → name / description / triggers
  ▼
③ 选择        extract_skill_mentions（显式点名）
  │             └ 无 → select_skills_for_turn（语义匹配）
  ▼
④ 安全检查    scan_skill_directory → 有问题拒绝注入
  ▼
⑤ 注入        format_skill_injection_block → build_skill_injection_message
  ▼
⑥ 执行提示    skill_injection_execution_hint（告诉模型"这是技能，按它做"）
  ▼
⑦ 外部调用    community provider（web_fetch / search）
```

## WorkAgentHarness 现状与设计

**现状**：无 skills 机制。工具只有第三篇那 4 个。

| 缺口 | 设计方案 | 边界 |
|---|---|---|
| 加载 | `skills/<name>/SKILL.md`，启动扫一次 | 不做 mtime 增量 |
| 解析 | 只解析 frontmatter 三个字段：`name` / `description` / `triggers` | 不做完整 YAML |
| 选择 | **只做显式点名**：用户消息里出现 skill 名才加载 | 不做语义匹配 |
| 注入 | 注入 `## 技能：{name}\n{body}` 一段 | 对齐 `format_skill_injection_block` 思路 |
| 安全 | 正则扫危险串（`rm -rf`、`curl | sh`、`os.system`） | 对齐 `scan_for_security_issues` 思路 |
| 外部能力 | **不做**（不接搜索/抓取） | 无网络 provider |
| 市场 | 不做 | — |

**为什么只做显式点名**：语义匹配需要额外模型调用，成本和误判都不划算。原版两条路径并存（`extract_skill_mentions` + `select_skills_for_turn`），本项目只保留确定性的一条。

## 与 EvoFlow 的差异

| 项 | EvoFlow | 本项目 |
|---|---|---|
| 缓存 | mtime map + cache_key | 启动一次 |
| 选择 | 显式 + 语义 | 仅显式 |
| 注入 | 完整 block + 执行提示 | 简化 block |
| 安全扫描 | 目录级 + 代码/文档分流 | 单文件正则 |
| 作用域 | active/bound/scope 三文件 | 不做 |
| 市场 | skillhub_pack / installer | 不做 |
| Community | 10+ provider | 不做 |
