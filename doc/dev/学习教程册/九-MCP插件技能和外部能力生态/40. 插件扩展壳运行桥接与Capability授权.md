## 场景

一个插件想给 Agent 加"发送企业微信消息"的能力。它需要：

1. **一份清单**：叫什么、要什么权限、提供什么工具；
2. **一个运行壳**：插件代码在哪个进程里跑（不能和主进程混）；
3. **一条桥**：主进程怎么调它——这是"桥接"，需要鉴权；
4. **一份授权**：它声明要读文件，主进程得确认"允许"。

四件事里最容易出事的是第 3 条：桥没有鉴权，任何本地进程都能调插件、插件也能反过来调主进程的一切。

## 本节业务问题

| 问题 | 后果 |
|---|---|
| 清单无校验 | 少一个必填字段，运行时报奇怪的错 |
| 无诊断对象 | 用户只知道"装失败"，不知道为什么 |
| 插件与主进程同进程 | 一个插件死循环，整个 Agent 卡死 |
| 桥无 token | 任意本地进程都能调 |
| token 不轮换 | 泄漏后长期有效 |
| 能力不声明 | 插件偷偷读文件 |
| 无启用/禁用 | 装了就得一直跑 |

## EvoFlow 源码阅读路径

| 层 | 文件与真实符号 | 作用 |
|---|---|---|
| ① 清单 | `plugins/manifest.py:77` `class PluginManifest`；`:51` `class PluginManifestError(Exception)`；`:56` `class PluginDiagnostic`；`:150` `is_record(value)` | 结构 + 专用异常 + **诊断对象** |
| ② 枚举 | `plugins/runtime.py:62` `_iter_enabled_plugins(storage_root=None)`；`:78` `enabled_plugin_roots(storage_root=None)` | 只枚举**已启用**的 |
| ③ 技能根 | `:83` `plugin_skill_roots(storage_root=None)` | 插件也能带技能 |
| ④ 桥鉴权 | `plugins/bridge_auth.py:50` `get_bridge_token()`；`:83` `verify_bridge_token(request)`；`:33` `_token_file_path()`；`:43` `reset_bridge_token_cache()` | **token 落文件 + 校验** |
| ⑤ 管理与存储 | `plugins/service.py`；`plugins/storage.py`；`plugins/sources.py`；`plugins/components.py` | 安装、来源、组件 |
| ⑥ 运行实现 | `plugins/trae/`、`plugins/node_repl.py`、`plugins/cua_helper.py` | 具体插件运行时 |

**`PluginDiagnostic` 是本章的核心设计**：不是抛一个笼统的 `ValueError`，而是给出一条可展示的诊断（级别、字段、原因）。没有它，"装失败"对用户就是个黑箱。

逐层追读要点：`bridge_auth` 的 token 存在**文件**里（`_token_file_path`），说明跨进程共享；`verify_bridge_token(request)` 入参是 request，说明校验发生在入口。

## 调用流程

```text
安装插件
  ▼
① 读清单      PluginManifest → 字段校验
  │              └ 失败 → PluginDiagnostic（字段 + 原因）
  ▼
② 落存储      sources / storage → 插件目录
  ▼
③ 启用枚举    _iter_enabled_plugins → enabled_plugin_roots
  ▼
④ 起运行壳    独立进程（node_repl / cua_helper / trae）
  ▼
⑤ 发 token    get_bridge_token → 写 token 文件
  ▼
⑥ 桥调用      插件 → verify_bridge_token(request) → 校验通过才执行
  ▼
⑦ 能力约束    只放行清单里声明过的 capability
```

## WorkAgentHarness 现状与设计

**现状**：无插件。第三篇的 `tools/builtins` 是**内置工具**，不是插件。

| 缺口 | 设计方案 | 边界 |
|---|---|---|
| 清单 | `plugin.json`：`name/version/capabilities/tools[]` | 不做 icon/描述富字段 |
| 校验 | `load_manifest(path)` → 返回 `(manifest, diagnostics[])` | 对齐 `PluginDiagnostic` 思路 |
| 存储 | `.wah/plugins/<name>/` | 不做来源（zip/git） |
| 运行壳 | **不做独立进程**：插件就是 Python 模块，直接 import | 无跨进程桥 |
| 桥鉴权 | **不做**（无进程边界就没有桥） | — |
| 能力 | `CAP_ALLOWED = {"fs_read", "net_get"}`，清单超出即拒 | 静态白名单 |
| 启用/禁用 | 目录名列表 + `enabled.json` | 单文件 |

**必须写清**：本项目**不实现"扩展壳 + 桥 + token"**这一层。原版这套东西存在的前提是"插件在独立进程跑"；本项目插件是同进程模块，风险由第 25 章的沙箱/审批承担。**不能写成"已对齐"**。

## 与 EvoFlow 的差异

| 项 | EvoFlow | 本项目 |
|---|---|---|
| 运行位置 | 独立进程壳（node/cua/trae） | 同进程 import |
| 桥鉴权 | `get_bridge_token` + `verify_bridge_token` | 不做 |
| 清单诊断 | `PluginDiagnostic` 结构化 | 字符串列表 |
| 能力授权 | 清单声明 + 校验 | 静态白名单 |
| 来源 | `sources.py`（多种来源） | 手动放目录 |
| 插件带技能 | `plugin_skill_roots` | 不做 |
