## 场景

你有一个 Agent，别人也有一个 Agent（可能是别家的，跑在别的机器上）。要让它们协作：

1. **你这边**：需要知道对方"能干什么"——这是**能力卡片（agent card）**；
2. **对方那边**：需要知道你"能干什么"，才能决定派什么活；
3. **中间的活**：一次任务怎么传、进度怎么同步、结果怎么回、失败怎么报。

这三件事合起来就是 A2A（Agent-to-Agent）。它跟 MCP 的区别是：**MCP 接的是工具，A2A 接的是另一个会思考的 Agent**。

## 本节业务问题

| 问题 | 后果 |
|---|---|
| 无统一 Adapter | 每接一种外部 Agent 就写一套调用代码 |
| 无能力卡片 | 对方不知道你能干什么，派错活 |
| 任务记录不落库 | 外部任务跑到哪，本地看不到 |
| 状态不同步 | 对方已完成，本地还是"进行中" |
| 无超时/退避 | 对方慢，本地一直等 |
| 失败无归因 | 分不清"对方拒绝"和"网络断" |
| 能力卡片信息泄露 | 把内部工具名全暴露给对方 |

## EvoFlow 源码阅读路径

| 层 | 文件与真实符号 | 作用 |
|---|---|---|
| ① 抽象 | `external_agents/base.py`、`models.py` | 统一接口与数据模型 |
| ② 注册表 | `external_agents/registry.py:19` `register_active_agent(task_id, agent)`；`:30` `get_active_agent(task_id)`；`:45` `unregister_active_agent(task_id)`；`:61` `list_active_agents()` | **按 task_id 管活跃实例** |
| ③ 具体实现 | `external_agents/trae.py` | 一个真实适配器 |
| ④ 能力卡片 | `a2a/agent_card.py:56` `role_to_agent_card(role)`；`:97` `list_agent_cards(*, status="active")`；`:14` `_lookup_skill_metadata(skill_name)`；`:41` `_role_tool_names(agent_code)` | **角色 → 卡片**，含技能与工具名 |
| ⑤ 任务记录 | `a2a/adapter.py:62` `_create_a2a_task_record(...)`；`:100` `_update_a2a_task_state(...)` | 本地落一条 A2A 任务 |
| ⑥ 退避与错误 | `:35` `_meeting_speak_backoff_seconds(attempt, error)`；`:51` `_meeting_speak_user_error(exc)` | 重试与话术 |
| ⑦ 编排 | `a2a/orchestrator.py`、`meeting_conclude.py`、`meeting_tool_speak.py` | 多 Agent 协同 |

**`_role_tool_names(agent_code)` 值得注意**：能力卡片里带的是**这个角色能用的工具名**，不是全部工具——卡片本身就是一份"权限声明"。

逐层追读要点：注册表按 `task_id` 而非 agent 名字键，说明同一个外部 Agent 可能并发处理多个任务。

## 调用流程

```text
要派活给外部 Agent
  ▼
① 取卡片      list_agent_cards(status="active") → 对方能力
  ▼
② 建任务记录  _create_a2a_task_record → 本地一行（状态 pending）
  ▼
③ 注册实例    register_active_agent(task_id, adapter)
  ▼
④ 调用        adapter 发任务 → 对方执行
  ▼
⑤ 同步状态    _update_a2a_task_state → 本地状态跟着变
  ▼
⑥ 失败处理    _meeting_speak_backoff_seconds → 退避重试
  │             └ 仍失败 → _meeting_speak_user_error → 给用户的话术
  ▼
⑦ 收尾        unregister_active_agent(task_id)
```

## WorkAgentHarness 现状与设计

**现状**：无外部 Agent 能力。`WAH-TOOL-009`（ZCode 桥）也未实现。

| 缺口 | 设计方案 | 边界 |
|---|---|---|
| Adapter 接口 | `class ExternalAgent(ABC)`：`send(task) / poll(task_id)` | 只两种方法 |
| 注册表 | 进程内 dict：`task_id → adapter` | 不持久化 |
| 能力卡片 | 本地生成 JSON：`{name, tools[], description}` | 不对外暴露 HTTP |
| 任务记录 | 复用 `runs` 表，`kind="external"` | 不新建表 |
| 状态同步 | **只做轮询**：每 10 秒 `poll` 一次 | 不做回调/推送 |
| 退避 | 指数退避，最多 3 次 | 对齐思路 |
| 实际对接 | **不做**（不接任何真实外部 Agent） | — |

**必须写清**：本章是**纯设计**。没有真实外部 Agent 可接，也没有 HTTP 端点。写这一章的目的是让读者理解"跨 Agent 协作要付出哪些结构代价"，不是让你现在就能跑通。

## 与 EvoFlow 的差异

| 项 | EvoFlow | 本项目 |
|---|---|---|
| 适配器 | `base.py` + `trae.py`（真实对接） | 只有抽象 + 假实现 |
| 注册表 | 按 task_id，含并发 | 进程内 dict |
| 能力卡片 | `role_to_agent_card`（含技能与工具） | 简化 JSON |
| 任务记录 | A2A 专用表 | 复用 `runs` |
| 状态同步 | 状态机 + 事件 | 轮询 |
| 编排 | `orchestrator` + 会议 | 不做 |
| 退避话术 | 专用函数 | 通用提示 |
