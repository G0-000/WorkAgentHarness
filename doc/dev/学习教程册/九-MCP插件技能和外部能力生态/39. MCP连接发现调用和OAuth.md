## 场景

用户想接 GitHub 的 MCP server，让 Agent 能读 issue、提 PR。

要接上，得走五步：

1. **配**：写一条 server 配置（命令、参数、环境变量）
2. **连**：启动子进程，走 stdio 握手
3. **发现**：调 `tools/list` 拿到工具清单
4. **包装**：把 MCP 工具变成 Agent 能调用的工具（含 schema 转换）
5. **鉴权**：有些 server 要 OAuth，token 过期要能刷

第 5 步是最容易出问题的：token 过期后如果只报"调用失败"，用户根本不知道是要重新授权。

## 本节业务问题

| 问题 | 后果 |
|---|---|
| 配置变更不感知 | 改了 server 参数，还跑旧的 |
| 无 fingerprint | 无法判断"配置是否变过" |
| 超时一刀切 | 慢 server 的慢工具全超时 |
| 不区分连接错误 | 网络断了报成"工具失败" |
| MCP 结果不做预算 | 一个 `list_issues` 返回 200 条，撑爆上下文 |
| OAuth token 不管 | 过期后所有调用失败，原因不明 |
| 多 server 命名冲突 | 两个 server 都有 `search` 工具 |

## EvoFlow 源码阅读路径

| 层 | 文件与真实符号 | 作用 |
|---|---|---|
| ① 单 server 参数 | `mcp/client.py:11` `build_server_params(server_name, config)` | 名字 + 配置 → 连接参数 |
| ② 多 server 配置 | `:56` `build_servers_config(extensions_config)` | 汇总成一份 |
| ③ 配置加载 | `mcp/tools.py:32` `load_mcp_config()`；`:101` `mcp_config_fingerprint()`；`:76` `_merge_trusted_project_servers(...)` | **fingerprint 是配置版本号** |
| ④ 超时 | `mcp/pool.py:45` `call_timeout_sec()`；`:55` `server_timeout_sec_from_config(raw_cfg)` | 全局默认 + server 级覆盖 |
| ⑤ 错误分类 | `:106` `looks_like_connection_error(exc)`；`:98` `_walk_exception_tree(exc)` | **区分连接错误与工具错误** |
| ⑥ OAuth | `mcp/oauth.py:26` `class OAuthTokenManager`；`:17` `class _OAuthToken`；`:181` `build_oauth_tool_interceptor(...)` | token 管理 + 拦截 |
| ⑦ 其他 | `annotations.py`、`result_budget.py`、`workspace_scope.py`、`market.py`、`status.py` | 注解、结果预算、工作区范围 |

**`_walk_exception_tree` 值得单看**：MCP 的异常会被多层包装（anyio → mcp → 自定义），必须递归走一遍异常链才能判断根因是不是连接问题。

逐层追读要点：`mcp_config_fingerprint` 用在哪（缓存失效？工具清单重建？）。

## 调用流程

```text
启动 → 读配置
  ▼
① 加载      load_mcp_config → _merge_trusted_project_servers
  ▼
② 算版本    mcp_config_fingerprint → 变了则重建连接
  ▼
③ 建参数    build_server_params(名字, 配置) → build_servers_config
  ▼
④ 连接      子进程 stdio → initialize
  ▼
⑤ 发现      tools/list → 工具清单 → 包装成 Agent 工具
  ▼
⑥ 调用      超时（call_timeout_sec / server 级覆盖）
  │             └ 异常 → looks_like_connection_error → 分类报错
  ▼
⑦ OAuth     OAuthTokenManager 注入 token → 失效则刷新
  ▼
⑧ 结果预算   result_budget 截断
```

## WorkAgentHarness 现状与设计

**现状**：无 MCP。第四篇提到的 `WAH-TOOL-009`（ZCode 桥）也未实现。

| 缺口 | 设计方案 | 边界 |
|---|---|---|
| 配置 | `mcp_servers.json`：`{name: {command, args, env}}` | 只支持 stdio |
| 连接 | `subprocess` + JSON-RPC over stdio，只实现 `initialize` / `tools/list` / `tools/call` | 不做 SSE/HTTP transport |
| fingerprint | 配置 JSON 的 sha256，变了就重建 | 对齐 `mcp_config_fingerprint` |
| 超时 | 全局 30 秒，server 可覆盖 | 对齐 `server_timeout_sec_from_config` |
| 错误分类 | 连接错误 → `[McpConnection]` 前缀；工具错误 → `[McpError]` | 对齐 `looks_like_connection_error` |
| 命名冲突 | 工具名加前缀 `server__tool` | 不对齐原版（原版另有机制） |
| OAuth | **不做** | 只支持无鉴权 server |
| 结果预算 | 复用第三篇 `truncate_text` | 不做 token 预算 |

## 与 EvoFlow 的差异

| 项 | EvoFlow | 本项目 |
|---|---|---|
| transport | stdio + 更多 | 仅 stdio |
| 配置隔离 | `_merge_trusted_project_servers`（信任层） | 单一文件 |
| 超时 | 全局 + server 级 | 同 |
| 错误分类 | `looks_like_connection_error`（异常树） | 按异常类型粗分 |
| OAuth | `OAuthTokenManager` + 拦截器 | 不做 |
| 结果预算 | `result_budget` | 字符截断 |
| 市场 | `market.py` | 不做 |
