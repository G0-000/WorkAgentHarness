## 本篇三条澄清

1. **状态必须三分，不能二分**。`已落地`（有代码 + 有入口 + 跑通）、`有代码未接`（有代码但入口没接，跑不了）、`未实现`（没有）。**只有第一类能写"已通过"**。本章列出 3 项"有代码未接"：SSE HTTP 服务、终端会话接线、上下文折叠摘要验证。
2. **12 步链路表是核心资产**。入口 → 配置 → 模型 → Agent → 工具目录 → 工具结果 → 审计 → 压缩 → 事件 → 持久化 → 恢复 → 取消。每一格都要能点到**本项目真实符号 + 文件 + 行号**，不是"大概在某个模块"。
3. **差异不重复解释**。前十二篇的每章都有差异表；第 60 章只**汇总**（模块数、工具、沙箱、子代理、协作、知识库、主动、渠道、UI、观测十个维度），不重述理由。

## 本篇综合练习（文档级，不跑代码）

场景：用户说"把 `/tmp/反馈.csv` 里的差评挑出来，整理成报告，发到我的飞书"。

1. 这句话要经过哪 10 步？
2. 每一步在本项目的文件与函数是什么？
3. 哪几步在**本项目**是断的？
4. 断的那几步，缺的是"代码"还是"入口"还是"依赖"？
5. 如果要补齐"发飞书"这一步，最小代价是什么？

五问写表。**第 3 问答不出来，说明前十二篇只是"读过"，没"走通"**。
