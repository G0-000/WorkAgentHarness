## 场景

同一句"给我写个广告"，用户用一百次会有一百种结果——因为每次都是模型自由发挥。

但有些场景必须**稳定**：广告投放前要过审、模板不能变、参数要能填。

Workflow 解决的就是这个：把一个固定流程写成**参数化模板**——

```
步骤 1：按 "{{产品名}}" 生成主标题
步骤 2：按 "{{卖点}}" 生成三条副文案
步骤 3：按 "{{渠道}}" 调整长度
```

用户只填三个参数，流程跑出来的是同一套结构。这就是"确定性"。

## 本节业务问题

| 问题 | 后果 |
|---|---|
| 模板参数不校验 | 用户漏填，跑到一半才报错 |
| 步骤结构不归一 | 同一份模板前后端理解的字段不一致 |
| 参数不转义 | 参数里带 `{{}}`，渲染出意外结果 |
| 默认值不应用 | 用户不填就空着 |
| 步骤与具体模型绑定 | 换模型模板就废 |
| 无 Stage | 界面不知道用户现在在做哪一步 |
| 外部输入不缓存 | 每次刷新都打外部接口 |

## 调用流程

```text
用户选模板 + 填参数
  ▼
① 归一      normalize_parameter / normalize_step → 合法结构
  ▼
② 补默认    apply_parameter_defaults
  ▼
③ 渲染      _render_steps → _render_text / _render_value（逐字段替换）
  ▼
④ 绑定判定  is_workflow_bound_task(task)
  ▼
⑤ 派发      dispatch_workflow_task_sync → 逐步执行
  ▼
⑥ 校验      _dispatch_result_ok(parsed)
  ▼
⑦ 阶段      set_thread_stage(kind="workflow", data={...}) → 界面同步
```

## WorkAgentHarness 现状与设计

**现状**：没有 Workflow。所有任务都是"一句话交给模型"。

| 缺口 | 设计方案 | 边界 |
|---|---|---|
| 模板存储 | `workflows(name, params_json, steps_json)` | 单表 |
| 归一 | `normalize_parameter` / `normalize_step` 同名 | 只做 dict/list 两种形态 |
| 渲染 | `{{name}}` 单层替换，不做表达式 | 不做条件/循环 |
| 默认值 | 参数带 `default` 字段 | 对齐 `apply_parameter_defaults` |
| 派发 | 渲染出 `list[str]` 步骤，逐步交给 `RunService` | 不做并行 |
| Stage | `thread_stage(thread_id, kind, data_json)` 表 | 不做外部输入 |
| 外部输入 | **不做**（含 `fetch_news_feeds`） | 无网络抓取 |

**要写清的一条**：原版的 App Center 是**完整工作流应用生态**（`app_generator` 能生成应用、`app_canvas` 有画布、`app_openai_compat` 对外兼容），本项目只做"参数化模板 + 顺序执行"这一层。

## 与 EvoFlow 的差异

| 项 | EvoFlow | 本项目 |
|---|---|---|
| 模板来源 | 内置 + 生成（`app_generator`） | 手写 JSON |
| 步骤执行 | `dispatch_workflow_task_sync`（含异步桥接） | 顺序调用 `RunService` |
| 渲染能力 | `_render_value` 支持嵌套 | 只支持标量 |
| 参数校验 | `normalize_parameter` + 结构校验 | 同名归一，校验更松 |
| 应用生态 | App Center（画布/生成/兼容层） | 不做 |
| Stage | `set_thread_stage`（kind + data） | 同形状，单表 |
| 外部输入 | `fetch_news_feeds` | 不做 |
