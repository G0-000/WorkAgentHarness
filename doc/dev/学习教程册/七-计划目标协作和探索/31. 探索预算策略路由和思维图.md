## 场景

用户问："这个报错是怎么回事？"

Agent 要去找答案，但**找是有成本的**：每次搜索、每次读文件都烧 token 和时间。三种典型失控：

1. **无限探索**：搜了 40 次还没找到，仍在搜；
2. **选错工具**：该 `grep` 的时候去读了 20 个文件；
3. **无全局视图**：查了 10 个线索，自己都忘了哪几个已经排除。

所以要有三样东西：**预算（能花多少）、路由（该用哪个工具）、思维图（已经排除什么）**。

## 本节业务问题

| 问题 | 后果 |
|---|---|
| 无预算 | 一个查错任务烧掉整月额度 |
| 预算不分 thread | 一个会话用完，别的会话也停 |
| 不做任务类型分类 | 文件查找类问题也走"深度研究"链路 |
| 工具矩阵不收敛 | 每个任务都能用 10 个工具，模型乱选 |
| 思维图不记"已排除" | 反复查同一个死胡同 |
| 图节点状态不归一 | 前端显示"进行中"和"已完成"混在一起 |

## 调用流程

```text
任务进来
  ▼
① 分类      classify_task_type_heuristic(text) → task_type
  ▼
② 选工具    search_tool_matrix[task_type] → 工具子集
  ▼
③ 记预算    _thread_key(thread_id) → _Attempt +1 → 超限则停
  ▼
④ 探索      工具调用 → 结果
  ▼
⑤ 记图      思维图节点：已查 / 已排除 / 待查（normalize_node_status）
  ▼
⑥ 巡检      _scan_orphans → 补父节点或清理
  ▼
⑦ 收口      _format_apply_summary → 给用户看的结论
```

## WorkAgentHarness 现状与设计

**现状**：无预算、无路由、无思维图。第三篇的 `goal_auto_continue.py` 的 `MAX_STEPS=8` 是唯一的"上限"，但它是**步数**不是**探索成本**，而且存在进程内 dict（重启即丢）。

| 缺口 | 设计方案 | 边界 |
|---|---|---|
| 预算 | `exploration_budget(thread_id, attempts, window_start)`，上限 20 次/会话 | 不做 token 计费 |
| 记账 | 每次工具调用 +1，同 thread 累加 | 不做 root 维度 |
| 分类 | 复用启发式：含"在哪/哪个文件/路径"→ `file_lookup`；含"为什么/怎么"→ `research` | 不做模型分类 |
| 工具矩阵 | 静态 dict：`task_type → [tool_names]` | 不做动态学习 |
| 思维图 | `mind_nodes(thread_id, node_id, kind, status, parent_id, note)` | 不做可视化 |
| 状态 | `pending / exploring / done / excluded` 四态 | 对齐 `normalize_node_status` 思路 |
| 孤儿 | 启动时扫一次，挂到根节点下 | 对齐 `_scan_orphans` |

## 与 EvoFlow 的差异

| 项 | EvoFlow | 本项目 |
|---|---|---|
| 预算维度 | thread + root 双维度 | thread 单维 |
| 预算持久化 | 有独立记账 | 单表 |
| 分类 | 启发式 + 标签推断 | 启发式，两档 |
| 工具矩阵 | `search_tool_matrix` + `action_bias` | 静态 dict |
| 思维图 | 完整图（节点、边、孤儿、mermaid） | 扁平节点表 |
| 图可视化 | `diagram.py` 支持 mermaid 识别 | 不做 |
| 强制约束 | `mind_map_enforce` | 不做 |
