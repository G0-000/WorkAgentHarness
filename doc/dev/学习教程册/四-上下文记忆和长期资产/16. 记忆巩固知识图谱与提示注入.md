## 场景

用了一个月之后，Agent 的长期记忆里堆了 400 条：既有"用户偏好 4 空格缩进"，也有"项目用了 FastAPI""db.py 里有 3 张表""上次跑挂了一次"。

下一轮对话，这些全部被拼进提示词——**花了 3000 token 讲了一堆它不需要知道的事**，真正该记住的偏好反倒被淹掉了。

本章要解决的就是：**什么该从对话里提炼成记忆、提炼后怎么存、往提示词里拼的时候怎么筛**。

## 本章要完成的功能

| 功能 ID | 要达成的行为 | 用户可见结果 |
|---|---|---|
| `WAH-MEM-004` | 记忆巩固：从对话里抽取事实，带分类与置信度，写进长期记忆 | 说过一次的偏好，下次自动生效 |
| `WAH-MEM-005` | 实体引用与注入过滤：记忆条目挂到具体实体上；注入前筛掉不该进的 | 提示词不被无用记忆撑爆 |

## 本节业务问题

| 问题 | 后果 |
|---|---|
| 什么都当事实存 | 400 条里 380 条是废话，偏好被淹 |
| 没有置信度 | 你说的"可能用 tab 吧"和"必须 4 空格"等价 |
| 没有分类 | 分不清"偏好"和"知识"，无法按类型决定留不留 |
| 注入时不筛 | 长对话时上下文被记忆吃掉一半 |
| 记忆没有归属坐标 | 同一个项目换目录后记忆找不到，或串到别的项目 |

逐层追读要点：

1. **入口**：谁触发巩固（轮次结束？压缩时？定时？）。
2. **调用者**：`updater` 是被中间件调还是被后台任务调。

## 调用流程

```text
轮次结束 / 达到阈值
  ▼
① 拼对话        format_conversation_for_update(messages)
  ▼
② 模型抽取      MEMORY_UPDATE_PROMPT / FACT_EXTRACTION_PROMPT
  ▼
③ 校验          category ∈ 五类？confidence 0–1？content 非空？
  ▼
④ 写长期        updater: get_memory_data → 合并 → _save_memory_to_file
  ▼
⑤ 下一轮注入     _standing_fact_allowed(fact, chat_compact) 逐条筛
  │   · knowledge/module/api/config/flow/file → 丢掉
  │   · preference/behavior → 保留
  │   · context：≤160 字且 conf≥0.8 → 保留
  ▼
⑥ 冻结          get_frozen_standing_memory(thread_id, builder)
  ▼
⑦ 进提示词      format_memory_for_injection(...)
```

## WorkAgentHarness 现状与设计

**现状（已落地）**：`memory/extract.py` + `memory/injection.py` + `memory/middleware.py`，与第三篇的消息落库分离。

| 落地项 | 实现 | 边界 |
|---|---|---|
| 抽取 | `extract_facts(text)` 规则抽取，输出 `FactCandidate(content, category, confidence)` | 不调模型，句式命中才产出 |
| 分类 | 仅 `preference` / `behavior` / `context`；知识类直接返回空 | `knowledge` / `goal` 不进记忆 |
| 置信度 | 显式句式 1.0；含糊词 0.6；其余 0.8 | 未做模型级置信度校准 |
| 注入过滤 | `standing_fact_allowed` 5 条规则；`format_memory_for_injection` 拼块 | 保留"context ≤160 字 + conf≥0.8" |
| 注入形态 | `MemoryRuntimeMiddleware.before_model` 插入 pinned 的 `memory_injection` 消息 | 不拼 system prompt；每 thread 只注入一次 |
| 冻结 | 不做；用 `_injected_threads` 做一次性注入 | 无失效/重算缓存 |
| 实体引用 | `EntityRef` 两类 `user` / `workspace`，非法 id 抛 ValueError | 无 `agent` / `employee` |

## 与 EvoFlow 的差异

| 项 | EvoFlow | 本项目 |
|---|---|---|
| 巩固触发 | 模型抽取（`MEMORY_UPDATE_PROMPT`） | 规则抽取（fake，不调模型） |
| 分类 | 五类 `preference/knowledge/context/behavior/goal` | 三类，`knowledge`/`goal` 不进长期 |
| 注入过滤 | `_standing_fact_allowed` 十余条规则 | 保留主干 5 条 |
| 冻结缓存 | `standing_freeze.py`（三函数） | 不做 |
| 实体类型 | 四类 `user/agent/employee/workspace` | 两类 `user/workspace` |
| 知识图谱 | `knowledge/owned/kg.py`（知识库侧，`kg_*` 表）+ `kg_pipeline.py` 抽三元组；**记忆侧已退役** | 本章不做（属第 21 章）；只做 `EntityRef` 引用 |
| token 计数 | `_count_tokens` 走 tiktoken `cl100k_base` | 字符数近似 |

**必须写明的一点**：知识图谱在本项目里属于第 21 章（知识库 `knowledge/owned/`），不在记忆侧。旧文档把两者并列，是章节分配的错位；做记忆巩固时**不要**顺手去造图谱。
