## 本章要做出的东西

本章讨论三类"高危能力"的边界，**本篇不实现它们**：

- 后台命令与终端会话（能跑 shell、能长时间驻留）
- 浏览器桥（带登录态、能点真实按钮）
- 整机操作（Computer Use，能操作任何 App）

目标不是"做出一个能跑命令的工具"，而是**把风险面讲清楚并把边界落成代码**。8.1 已经实现了终端工具（拦截 / 前台 / 后台 / 超时 / 截断），8.2 只做原版形态对照，说明浏览器与 CUA 为什么不在本项目实现。

## 本章总流程与小节

```text
模型 tool_call: terminal(command, background, timeout, workdir)
  ▼
① 安全护栏      _check_dangerous → 8 条正则 → 命中返回警告（不执行）
  │             force: 前缀 = 用户已确认，跳过护栏
  ▼
② 路径解析      _resolve_cwd(workdir)
  ▼
③ 分流          _should_auto_background
  ├─ 后台 → _spawn_background(start_new_session=True) → pid + 日志路径
  └─ 前台 → _foreground_timeout(1..120) → _run_subprocess
  ▼
④ 结果整形      _format_subprocess_output
                 stdout / [stderr] / [exit_code] / 超长头尾截断
```

浏览器与 CUA 不在这条链上：原版把它们放在 gateway 的 REST 桥（`browser_bridge.py`、`browser_snapshots.py`、`cua_bridge.py`），由浏览器扩展与桌面端调用，不属于 harness 工具层。

## EvoFlow 源码阅读顺序

注意层次：**`app/gateway/routers/` 是 HTTP 桥，`packages/harness/evoflow/tools/` 才是工具层**。

1. `packages/harness/evoflow/tools/host_direct/terminal_tool.py`：命令执行主文件（8.1 对齐对象）。
2. `packages/harness/evoflow/tools/host_direct/terminal_session.py`：线程级 shell 状态。
3. `app/gateway/routers/background_bash.py`：后台命令的 HTTP 桥（不是工具）。
4. `app/gateway/routers/browser_bridge.py` / `browser_embed.py`：浏览器会话的创建、隔离与销毁。
5. `app/gateway/routers/browser_snapshots.py`：快照结构（截图 + 元素 id）。
6. `app/gateway/routers/browser_stream.py` + `packages/harness/evoflow/tools/builtins/browser_stream.py`：浏览器操作的流式回传（两侧各有一份）。
7. `app/gateway/routers/cua_bridge.py`：整机操作（Computer Use）的边界与动作确认。
8. `packages/harness/evoflow/tools/zcode_port/`：外部工具协议如何接进内部目录。

逐层追读并记笔记：
1. **入口**：谁触发命令/浏览器动作；权限从哪来。
2. **调用者**：是真实产品路径还是诊断工具。
3. **核心行为**：白名单、审批、超时的决策点在哪。
4. **状态**：会话表、进程表、快照缓存的 owner 与过期策略。
5. **返回**：输出截断策略；失败如何分类。
6. **证据闭环**：找测试（超时、越权、进程泄漏），给每条判断标路径/符号。

## WorkAgentHarness 仿写顺序（规划）

### L1：只做一个可解释的最小闭环

用 fake browser / fake command session：
- 定义"会话"数据形状（id、状态、输出缓冲）
- 定义"动作"枚举（open / click / type / run）
- 不接真实进程与浏览器

### L2：接真实入口与状态

完成"会话创建 → 查看输出 → 截图 → 结束"的完整生命周期，会话状态落库。

### L3：按功能路线补齐

接工具/桌面入口及用户授权；把白名单、审批、超时逐项接线。

### L4：验证失败和边界

多会话隔离、断连清理、目标窗口、超时、权限边界、进程泄漏。

## 关键风险清单

| 能力 | 头号风险 | 最小防线 |
|---|---|---|
| 后台命令 | `rm -rf /`、超时挂死 | 命令白名单 + 进程组 kill + 输出上限 |
| 浏览器 | 登录态被滥用、提示注入 | 站点白名单 + 快照里指令视为不可信 + 破坏性动作审批 |
| 整机操作 | 误点支付/删除、操作错窗口 | 应用白名单 + 动作前截图确认 + 全程录屏 |
| ZCode 桥 | 外部工具权限不可控 | 接入时声明能力，运行时按声明校验 |

## 分层练习与出口（验收标准）

1. 命令白名单：`rm -rf /` 返回 `[CommandNotAllowed]`，不执行。
2. 超时：`sleep 120` 在 5s 内被终止，无进程残留（`ps` 验证）。
3. 浏览器站点白名单：未授权域名返回 `[SiteNotAllowed]`。
4. 快照可用：模型能凭元素 id 完成一次输入 + 点击。
5. 破坏性动作审批：点"提交订单"产生 `interrupt`，不批准不执行。
6. 会话隔离：两个任务并发打开浏览器，cookie 不串。
7. 提示注入：页面正文含恶意指令时工具不执行、模型不照做（记录实际表现）。

**本章出口**：能区分后台进程、浏览器、CUA 和 ZCode RPC 的职责边界，并说出每类的第一道防线。
