# 第 10 章 · 第 1 节｜后台命令与终端会话

> **定位：本篇扩展（可选）。** 代码已实现、可跑通（`tools/host_direct/terminal_tool.py` + `terminal_session.py`，已注册到 `ToolCatalog`）；主线四章（6/7/9/10）不依赖本节，本篇验收也不要求本节通过。

## 场景

你让助理去楼下便利店买东西。你会说"买瓶牛奶"，不会让他自己拿你的银行卡、自己决定去哪家店、自己刷多少额度。

命令工具比"读文件"危险一个量级：它可能删东西、装东西、改系统状态、跑很久不回来。这一节要解决的问题不是"怎么执行一条命令"——那是一个 `subprocess.run` 的事——而是**在什么条件下拒绝执行、超时怎么收场、长任务怎么不把整个 run 卡死**。

## 这一节要实现什么功能

让 Agent 在受控前提下执行 shell 命令，具体是四件事：

| 能力 | 行为 |
|---|---|
| 危险命令拦截 | 命中危险模式时**不执行**，返回警告并告诉模型"确认要跑就加 `force:` 前缀" |
| 前台执行 | 同步执行、拿到 stdout/stderr/exit_code，超时转成可读结果而不是抛异常 |
| 后台执行 | 长任务（`npm install`、`pytest`）自动或显式转后台，立刻返回 pid + 日志路径 |
| 输出控制 | 超过上限时保留头尾各一半，中间标注"已截断 + 总长度" |

## 调用流程

```text
模型 tool_call: terminal(command="pytest -q", timeout=60)
  ▼
① force 前缀判断            terminal_tool
  ├─ 以 "force:" 开头 → 剥掉前缀，标记 force_mode=True
  └─ 否则 force_mode=False
  ▼
② 安全护栏（仅未 force 时）   _check_dangerous
  ├─ 遍历 _DANGEROUS_PATTERNS 8 条正则
  ├─ 命中 → 直接 return 警告文本（命令不执行）
  └─ 未命中 → 继续
  ▼
③ 后台还是前台               _should_auto_background
  ├─ background=True 或命中长任务模式
  │    → _spawn_background：Popen(start_new_session=True)，返回 pid + 日志路径
  └─ 否则走前台
  ▼
④ 前台执行                    _foreground_timeout → _run_subprocess
  ├─ 超时上限 = min(max(1,timeout), 120)
  ├─ subprocess.run(shell=True, capture_output=True, timeout=…)
  ├─ TimeoutExpired → 转成 "[Timeout] 前台等待 x s 后结束" + exit_code=124
  └─ 正常 → _format_subprocess_output
  ▼
⑤ 结果整形                    _format_subprocess_output
  ├─ stdout 去 ANSI 控制符
  ├─ stderr 单独加 "[stderr]" 标注
  ├─ exit_code≠0 时补 "[exit_code=n]"
  └─ 超过 8000 字符 → 头半 + 尾半，中间标注总长度
```

## 关键实现

### 危险模式表（8 条，每条的意图不同）

```python
_DANGEROUS_PATTERNS: list[tuple[re.Pattern, str]] = [
    # 删除根目录 / 当前目录 / 通配符全删：最典型的误操作
    (re.compile(r"^\s*(rm|rmdir|del|deltree|rd)\s+(-rf?\s+)?/?(\*|\.\s*$|/|\\[\\/]?\s*$)"),
     "destructive_root"),
    # 格式化 / 分区 / 裸写磁盘
    (re.compile(r"^\s*(mkfs|fdisk|dd|format)\s"), "destructive_disk"),
    # 把根目录权限放开给所有人
    (re.compile(r"^\s*chmod\s+-R?\s*777\s+/"), "permission_risk"),
    # 立即关机 / 重启
    (re.compile(r"^\s*shutdown\s+-[rh]?\s*(now|\+0)"), "system_shutdown"),
    (re.compile(r"^\s*reboot\s*$"), "system_reboot"),
    # 提权后删除：比普通删除更危险
    (re.compile(r"^\s*sudo\s+rm\s+-rf\s+/"), "sudo_destructive"),
    # 直接覆盖磁盘设备
    (re.compile(r"^\s*>\s*/dev/sd"), "disk_overwrite"),
    # 下载脚本直接管道给 shell 执行：远程代码执行
    (re.compile(r"^\s*curl\s+[^\s]+\s*\|\s*(bash|sh|zsh|python)"), "pipe_curl_to_shell"),
]
```

注意这里**没有**"白名单"：原版走的是"默认允许、命中黑名单就拦"，因为白名单维护成本高、模型合法命令千变万化。这跟"审批三态"是完全不同的思路。

### 判定函数返回字符串，不返回枚举

```python
def _check_dangerous(command: str) -> str | None:
    """命中危险模式返回警告文本，否则返回 None（原版 :553）。"""
    for pattern, danger_id in _DANGEROUS_PATTERNS:
        if pattern.search(command):
            return (
                f"[DangerousCommand] safety guard ({danger_id}):\n{command[:200]}\n\n"
                "确认要执行时，在原命令前加 'force:' 再调用一次。"
            )
    return None
```

为什么返回字符串而不是 `ALLOW/ASK/DENY`：
- 字符串里的原因直接进了模型上下文，模型知道"我为什么被拦"；
- 枚举值模型看不见，它只会反复重试同一条命令；
- `force:` 前缀是一句自然语言约定，不需要中间件配合发 interrupt 事件。

### 超时不抛异常

```python
try:
    proc = subprocess.run(command, shell=True, cwd=…, capture_output=True, text=True, timeout=timeout)
except subprocess.TimeoutExpired as exc:
    # 超时不抛异常给模型，转成可读结果：告诉它超了多少秒、怎么做
    waited = round(time.monotonic() - started, 1)
    return f"{out}\n[Timeout] 前台等待 {waited}s 后结束（上限 {timeout}s），长任务请用 background=True", 124
```

如果直接把 `TimeoutExpired` 抛出去，LangGraph 的工具节点会把它吞成一条普通文本，模型看到的是"工具坏了"而不是"我该换后台执行"。

### 后台执行必须脱离进程组

```python
proc = subprocess.Popen(
    command, shell=True, cwd=…,
    stdout=log_file, stderr=subprocess.STDOUT,
    start_new_session=True,  # 脱离当前进程组，父进程退出后仍继续
)
```

`start_new_session=True` 是后台能力的前提：不带它，主进程退出时子进程会收到同一进程组的信号，`npm install` 跑到一半被杀。

## 知识点

### 为什么超时上限是 120 秒，而不是让模型随便传

模型对时间的直觉很差，它经常传 `timeout=600` 然后这 10 分钟里整个 run 就挂在那里。`_foreground_timeout` 把上限硬封在 120 秒，真正的长任务只有一条路：转后台。

### 输出截断为什么留头又留尾

命令输出通常"头是启动信息、尾是错误结论、中间是刷屏的进度"。只留头会丢掉报错，只留尾会丢掉上下文。所以头尾各 4000 字符。

### 前台 / 后台的区别不是"快慢"

| | 前台 | 后台 |
|---|---|---|
| 返回值 | 命令输出本身 | pid + 日志路径 |
| 谁持有输出 | 工具调用栈 | 日志文件 |
| 失败怎么发现 | exit_code | 去读日志 |
| 典型命令 | `git status`、`ls`、`echo` | `npm install`、`pytest`、`vite dev` |
