把 Agent 的运行过程从"一次性结果"变成"可观察的事件流"，并让入口能边收边渲染：

- **已实现**：`stream_agent_run` 事件生产 + `RunService.execute_stream` 生命周期 + CLI `--stream` 终端消费。
- **待实现**：SSE 传输、断线恢复（`Last-Event-ID`）、Web 端渲染、工具活动面板。

## 跟着写代码：事件翻译与生命周期

### 1. 事件翻译（events/stream.py）

```python
for mode, chunk in agent.stream(
    {"messages": input_messages},
    {"configurable": {"thread_id": thread_id}},
    stream_mode=["messages", "updates"],
):
    if mode == "messages":
        message_chunk, _meta = chunk
        if isinstance(message_chunk, (AIMessage, AIMessageChunk)):
            if isinstance(message_chunk.content, str) and message_chunk.content:
                yield {"type": "text_delta", "text": message_chunk.content}
    elif mode == "updates":
        for _node, payload in (chunk or {}).items():
            for message in (payload or {}).get("messages", []):
                if isinstance(message, AIMessage):
                    for call in message.tool_calls or []:
                        yield {"type": "tool_call", "name": call["name"], "args": call["args"]}
                elif isinstance(message, ToolMessage):
                    yield {"type": "tool_result", "name": message.name,
                           "ok": not str(message.content).startswith("[")}
```

### 2. 生命周期在 RunService

```python
yield {"type": "run_start", "run_id": run_id, "thread_id": session_id}
answer_parts = []
for event in stream_agent_run(self._agent, [("user", text)], thread_id=session_id):
    if event["type"] == "text_delta":
        answer_parts.append(event["text"])
    yield event
answer = "".join(answer_parts).strip()
self._sessions.add_message(session_id, "assistant", answer)
self._runs.complete(run_id, _now_utc())
yield {"type": "run_end", "status": "completed", "answer": answer}
```

留意：流式下没有"最后一条消息"，最终回答靠**拼接 text_delta** 得到，再写库。

### 3. 事件不重复发终态

`run_start` / `run_end` 只由 `RunService` 发，`events` 层不发。否则一次运行会出现两个结束事件，前端重复收尾。

## 分层练习与出口

- **L1（已完成）**：收到 token 和结束事件。验收：`--stream --once "你好"` 能看到 `thread/run`、文本、换行。
- **L2**：固定事件 schema 与顺序。验收：`--stream --once "计算 99*3"` 顺序为 `tool_call → tool_result → text_delta`。
- **L3**：补工具/错误/取消/终态事件和 UI 解码。验收：失败工具事件 `ok=False`；取消有 `run_end(cancelled)`。
- **L4**：断流、重连、恢复游标、重复/乱序。验收：带 `Last-Event-ID` 重连不重不漏。

**本章出口**：事件从生产者经过传输到页面逐项对应，每个事件都能说出"谁产生、谁消费、失败怎么办"。
