## 本章要做出的东西

给 Agent 加一层"横切能力"：不写进每个工具函数，而是挂在图的固定位置，对所有工具统一生效。

- **已实现**：工具审计中间件（`ToolAuditMiddleware`）——记录谁调了工具、耗时多久、结果多大。
- **待实现**：上下文预算与裁剪、自动后续动作、压缩与恢复。

## EvoFlow 源码阅读顺序

1. `agents/middlewares/`：有哪些中间件、各自挂哪个钩子（before_model / after_model / wrap_tool_call）。
2. `context/`：上下文组装、预算估算、压缩策略。
3. `core/scheduler/`：工具调度（prefetch、post-edit、search follow-up）。
4. `scheduler/`：本地调度与自动后续动作的触发条件。

逐层追读并记笔记：
1. **入口**：中间件在哪个装配点挂上；顺序由谁决定。
2. **调用者**：每个中间件的调用频率（每轮 / 每次工具 / 每次请求）。
3. **核心行为**：预算超限的裁剪顺序；压缩的摘要策略；自动继续的停止条件。
4. **状态**：压缩后的历史存在哪；重启后是否能恢复"压缩过"的事实。
5. **返回**：中间件短路（不调模型/不调工具）时返回什么。
6. **证据闭环**：找"约束不丢""死循环停止"的测试，给每条判断标路径/符号。

## 跟着写代码：wrap_tool_call

```python
class ToolAuditMiddleware(AgentMiddleware):
    def wrap_tool_call(self, request, handler):
        tool_name = getattr(request, "tool_call", {}).get("name", "unknown")
        started = time.perf_counter()
        logger.info("tool.start name=%s", tool_name)
        try:
            result = handler(request)          # 下一层：工具本身
        except Exception as exc:
            elapsed = (time.perf_counter() - started) * 1000
            logger.warning("tool.fail name=%s elapsed_ms=%.1f error=%s",
                           tool_name, elapsed, type(exc).__name__)
            raise                              # 不吞异常，让 RunService 决定终态
        elapsed = (time.perf_counter() - started) * 1000
        logger.info("tool.end name=%s elapsed_ms=%.1f content_chars=%d",
                    tool_name, elapsed, len(str(getattr(result, "content", ""))))
        return result
```

三个要点：
1. `handler` 是"下一层"，可以嵌套多个中间件。
2. 异常必须重新抛出——吞掉会让 run 状态错误。
3. 只记异常类型名，不记 `str(exc)`。

## 分层练习与出口

- **L1（已完成）**：加一个调用前后中间件。验收：日志里能看到 `tool.start` / `tool.end`。
- **L2**：上下文预算和历史裁剪。验收：预算调小后触发裁剪，system prompt 与最近 3 轮保留。
- **L3**：对照各类 middleware 与 prefetch / post-edit / search follow-up，找真实 caller。
- **L4**：顺序、短路、失败回退、压缩保真、并发。验收：两个中间件顺序可预测；压缩后约束不丢；自动继续有上限。

**本章出口**：能区分 Agent 中间件、本地工具调度、定时自动化三者的职责。
