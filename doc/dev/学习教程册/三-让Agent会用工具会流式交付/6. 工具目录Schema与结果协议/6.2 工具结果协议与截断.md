# 第 6 章 · 第 2 节｜工具结果协议与截断

## 场景

你去取快递。不管包裹里是大件家具还是小盒子，快递员给你的一定是**一个贴着单子的包裹**：单号、重量、状态都写在上面。你不需要知道里面是怎么包的。

这一节做的事一样：不管工具内部返回的是数字、文本还是报错，出口一律包成同一种"包裹"（`ToolResult`）：成功没、内容是什么、错了算什么类别、有没有被截断。上层只看这个包裹，不关心里面怎么装的。

## 这一节要实现什么功能

把所有工具输出收敛成一套结构：成功/失败标记、错误码、是否截断、附带元数据；超长结果截到 8000 字符。

**可验收的行为**：`计算 1/0` 返回 `[InvalidExpression]` 前缀且不整轮失败；读一个 2 万字符文件时返回内容被截断并标 `truncated=True`。

## 本节业务问题

工具返回值不统一会带来三个问题：

1. **上层要写类型分支**：这个工具返回 `dict`，那个返回 `str`，那个抛异常——Agent、事件流、UI 各写一套解析。
2. **失败信息不可控**：直接把异常原文塞给模型，可能带路径、密钥、堆栈，还会让模型误以为可以重试。
3. **超长输出撑爆上下文**：读一个 20 万字符的日志文件，整段进 prompt 直接超预算。

需要一层"结果协议"：统一结构 + 稳定错误类别 + 截断上限。

## 涉及文件

| 文件 | 职责 |
|---|---|
| `tools/result.py` | `ToolResult`、`shape_result`、`truncate_text`、`MAX_RESULT_CHARS` |
| `tools/builtins/calculator.py` | 失败时返回 `[InvalidExpression]` 前缀 |
| `tools/builtins/workspace_file.py` | 失败时返回 `[NotFound]` / `[PathNotAllowed]` 等类别 |
| `events/stream.py` | 按 `[` 前缀判断 `ok`，决定事件里的成功标记 |

## 调用流程

```text
工具函数产出一段文本
  ▼
shape_result(tool_name, ok, content, error_code, metadata)
  ├─ truncate_text(content, 8000)
  │    ├─ ≤ 8000 → 原样
  │    └─ > 8000 → 头部 + "…（已截断，原文共 N 字符）"
  ├─ metadata 合并 {"tool": tool_name, ...}
  └─ 返回 ToolResult
  ▼
LangGraph 包成 ToolMessage(content=截断后文本)
  ▼
模型下一轮读到这段文本
  ▼
事件层看到 content 以 "[" 开头 → ok=False → 前端显示红色失败标记
```

## 关键函数与知识点

### `ToolResult`（result.py）

| 字段 | 含义 | 谁用 |
|---|---|---|
| `ok` | 成功与否 | 事件流、UI、统计 |
| `content` | 给模型的文本（已截断） | 模型 |
| `error_code` | 稳定类别，如 `InvalidExpression` | 日志、UI、告警 |
| `truncated` | 是否截断 | UI 提示"内容不完整" |
| `metadata` | 工具名等附加信息 | 日志、调试 |

### `truncate_text`：截断不是丢弃

```python
def truncate_text(text: str, limit: int = MAX_RESULT_CHARS) -> tuple[str, bool]:
    if len(text) <= limit:
        return text, False
    head = text[:limit]
    return f"{head}\n…（已截断，原文共 {len(text)} 字符）", True
```

- 保留头部：模型仍能看到开头，通常足以判断"这个文件读错了/内容不对"。
- 明确标注总长度：模型知道后面还有内容，可以选择"分段读"或"换个更精确的路径"。
- 上限 8000 字符：约 2000–4000 token，留足空间给其他上下文。

### 错误类别的约定

```text
[InvalidExpression] 表达式语法错误           ← 模型可以换个写法重试
[PathNotAllowed] 不允许绝对路径              ← 模型知道要改相对路径
[NotFound] 文件不存在                        ← 模型知道路径写错
[ReadError] PermissionError                  ← 模型不该重试，应改策略
```

- **统一 `[Code] 原因` 格式**：人可读，机器也可解析前缀。
- **不用异常栈**：栈信息对模型没有价值，只会浪费 token 并暴露内部路径。

### 一个容易被忽略的坑

```python
shaped = shape_result("read_text_file", ok=True, content=text)
return shaped.content      # 只返回文本，ToolResult 结构在工具边界丢失
```

`@tool` 装饰器要求函数返回字符串或可序列化对象，所以内置工具只能返回 `shaped.content`；`ToolResult` 的完整结构留给内部调用（单测、目录自检）。这不是缺陷，但要明确"哪一层还拿得到结构化结果"。
