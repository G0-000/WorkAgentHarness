# 第 9 章 · 第 1 节｜Middleware 调用链与工具审计

## 场景

你经营一家餐厅，后厨有几十个厨师（工具）。你不可能站在每个厨师旁边记"谁几点开始做菜、做了多久、糊了几次"。你会在厨房门口装一个打卡机（middleware）：所有厨师进出都经过它，自动记录。

这一节做的事一样：`ToolAuditMiddleware` 挂在工具节点外层，每次工具调用自动记开始、耗时、结果长度、是否报错。不用改任何一个工具函数。

## 这一节要实现什么功能

在工具调用外面套一层中间件：记录开始、结束/失败、耗时与结果规模，不改工具返回值。

**可验收的行为**：跑一次 `计算 6*7`，日志出现 `tool.start name=calculator` 与 `tool.end ... elapsed_ms=... content_chars=...`；工具抛错时出现 `tool.fail error=ValueError` 且整轮仍按失败处理。

## 本节业务问题

工具越来越多后，三个问题必须回答：

1. **谁在什么时候调了什么工具**——出问题时能定位。
2. **每次工具调用多久、返回多大**——发现慢工具和超大输出。
3. **日志和业务代码分离**——不能每个工具里都写一遍 `print`。

Middleware 就是解决这三件事的挂载点。

## 涉及文件

| 文件 | 职责 |
|---|---|
| `middleware/tool_audit.py` | `ToolAuditMiddleware`：`wrap_tool_call` 前后打点 |
| `middleware/__init__.py` | 导出中间件 |

## 调用流程

```text
Agent 决定调用 calculator
  ▼
图执行到工具节点
  ▼
ToolAuditMiddleware.wrap_tool_call(request, handler)
  ├─ logger.info("tool.start name=calculator")
  ├─ started = perf_counter()
  ▼
handler(request)                  # 下一层：工具本身（或多个 middleware 链）
  ├─ calculator 执行
  └─ 返回 ToolMessage("14")
  ▼
回到 wrap_tool_call
  ├─ elapsed = 0.3 ms
  ├─ logger.info("tool.end name=calculator elapsed_ms=0.3 content_chars=2")
  └─ return result
  ▼
模型收到工具结果，继续生成回答
```

## 关键函数与知识点

### `wrap_tool_call`：一次包裹，所有工具生效

```python
def wrap_tool_call(self, request, handler):
    tool_name = request.tool_call.get("name", "unknown")
    started = time.perf_counter()
    logger.info("tool.start name=%s", tool_name)
    try:
        result = handler(request)
    except Exception as exc:
        logger.warning("tool.fail name=%s error=%s", tool_name, type(exc).__name__)
        raise
    ...
    return result
```

- **`handler` 是下一层**：可能是真正的工具，也可能再套一层 middleware。这就是"洋葱模型"。
- **异常必须重新抛**：中间件只观测，不改语义。吞掉异常会让 `RunService` 以为成功，run 状态就错了。

### Middleware 与工具函数的职责划分

| 关注点 | 放哪 | 原因 |
|---|---|---|
| 业务逻辑（怎么算） | 工具函数 | 每个工具独有 |
| 日志、计时、审计 | middleware | 所有工具通用 |
| 参数校验（业务级） | 工具函数 | 和业务规则绑定 |
| 权限、审批、限流 | middleware | 横切关注点 |

判断标准：**"换一个工具还需要写一遍吗？"** 需要 → middleware；不需要 → 工具函数。

### 为什么只记错误类型名

```python
logger.warning("tool.fail name=%s error=%s", tool_name, type(exc).__name__)
```

`str(exc)` 可能包含用户输入、文件路径、甚至密钥片段。日志会被收集、导出、给人看——不能当垃圾桶。

### 与第 10 章事件流的分工

| | middleware 日志 | 事件流 |
|---|---|---|
| 消费方 | 运维、排查 | 前端 UI |
| 内容 | 工具名、耗时、字符数 | 工具开始/结束、参数摘要 |
| 时机 | 每次调用 | 每次调用 |
| 用途 | 事后审计 | 实时展示"Agent 在干什么" |

两者都需要，但**不能互相替代**：日志是给人排查的，事件是给界面渲染的。

## 跟着做与验收
