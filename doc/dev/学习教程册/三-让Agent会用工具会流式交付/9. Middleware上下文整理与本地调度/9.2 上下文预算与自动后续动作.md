# 第 9 章 · 第 2 节｜上下文预算与自动后续动作

## 场景

你搬家，一次只能搬一车。东西太多时，你不能硬塞——得决定"这趟先搬什么、哪些下次再来"。如果塞爆了，车开不动。

这一节讨论上下文预算：对话越来越长、工具结果越来越多，prompt 迟早装不下。需要一套"决定带什么"的规则，以及"工具连续调用要不要自动继续"的调度规则。

**本篇只实现了工具审计中间件；本节讲清目标与验收，不假装已经做完。**

## 这一节要实现什么功能（目标，当前未实现）

在上下文将超预算时自动裁剪/压缩历史，并在任务未完成时按规则自动继续，且有硬性停止条件。

**可验收的行为（目标）**：构造超预算历史 → 触发裁剪且关键指令保留；连续失败 N 次后停止自动继续；达到最大步数停止。

**当前状态**：无预算估算、无裁剪、无自动继续，本节只定义目标流程与验收。

## 本节业务问题

| 问题 | 表现 |
|---|---|
| 上下文超预算 | 请求被供应商拒绝，或费用暴涨 |

## 目标调用流程（未实现）

```text
每轮模型调用前（before_model）
  ▼
① 估算当前上下文 token
  ├─ system prompt + 历史消息 + 工具 schema + 工具结果
  └─ 得到 used / budget
  ▼
② 超预算？→ 裁剪策略
  ├─ 优先保留：system prompt、最近 N 轮、当前任务约束
  ├─ 可压缩：早期对话 → 摘要（带"这里有省略"标记）
  ├─ 可丢弃：已消费完的工具结果大段正文
  └─ 绝不丢：用户明确要求记住的事实
  ▼
③ 组装最终消息列表 → 调模型
  ▼
工具调用返回后（after_model / wrap_tool_call）
  ├─ 模型还有未完成的 tool_calls → 自动继续下一轮
  ├─ 连续失败 N 次 → 停止并报告
  └─ 达到步数上限 → 停止，避免死循环
```

## 关键知识点

### 预算是"四份账单"

```text
总预算 = system prompt + 历史消息 + 工具 schema + 工具结果
```

容易被忽略的是**工具 schema 本身也占 token**：注册 30 个工具，每轮都要把 30 份 schema 发给模型。工具越多，留给对话的空间越少。

### 裁剪顺序要可解释

好的裁剪是有优先级的，不是"从后往前砍"：

| 优先级 | 内容 | 处理 |
|---|---|---|
| P0 | system prompt、当前任务目标 | 永不裁剪 |
| P1 | 最近 3–5 轮对话 | 保留原文 |
| P2 | 更早的对话 | 压缩成摘要 |
| P3 | 已消费的工具结果大段正文 | 只留结论 |
| P4 | 重复的工具 schema | 按需加载（tool_search 思路） |

### 压缩必须留"省略标记"

```text
[已省略 12 轮对话，摘要：用户在做 WorkAgentHarness 第三篇，已完成工具目录和计算工具]
```

没有标记的压缩是危险的：模型以为看到了全部历史，可能重复问已经答过的问题，或违背早前的约束。

### 自动后续动作的两个停止条件

```text
最大工具调用步数（如 25 步）
最大连续失败次数（如 3 次）
```

没有上限的自动继续 = 死循环 + 账单爆炸。

### 压缩与恢复是一对

压缩后如果进程重启，恢复时要能说明"历史被压缩过"。否则模型会以为"之前没聊过"。

## 跟着做与验收（本篇为待实现项）

1. **token 估算**：给出一个 50 轮对话，打印每轮的 used / budget，确认估算偏差在可接受范围（对照供应商返回的实际用量）。
2. **裁剪生效**：把预算调到很小，确认超出时触发裁剪，且 system prompt 与最近 3 轮完整保留。
3. **省略标记**：压缩后检查消息里是否有"已省略 N 轮 + 摘要"标记。
4. **约束不丢**：在第 1 轮说"以后都用中文"，第 30 轮压缩后，确认模型仍用中文回答。
5. **自动继续**：让模型连续调用 3 个工具，确认每次调用后自动进入下一轮，不需要人工点"继续"。
6. **上限生效**：构造一个会无限调工具的场景，确认 25 步后停止并返回明确原因。
7. **恢复**：压缩后重启进程，用同一 thread 继续，确认模型知道"历史被压缩过"。
