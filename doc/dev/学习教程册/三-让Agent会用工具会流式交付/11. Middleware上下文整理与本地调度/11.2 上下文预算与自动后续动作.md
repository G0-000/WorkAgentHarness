# 第 11 章 · 第 2 节｜上下文折叠与自动续跑

## 场景

两个真实场景，都发生在长任务里：

**场景一：上下文越来越长。** 一个跑了 40 轮的排障会话，消息已经堆到两万多字符。模型每次都要重读全部历史，慢、贵，而且开始"忘记"最早的需求。你想让它忘掉中间的细节、记住结论。

**场景二：模型话没说完就停了。** 你让它"先跑测试，再修问题，再跑一遍"，它跑完测试说了句"下一步要修复失败用例"就结束了这一轮。你不想手动再说一次"继续"。

这两个场景对应两个中间件，都在 `middleware/` 下：一个在**模型调用前**折叠历史，一个在**模型调用后**决定要不要再跑一轮。

## 这一节要实现什么功能

| 能力 | 中间件 | 钩子 | 行为 |
|---|---|---|---|
| 上下文折叠 | `ContextCompactionMiddleware` | `before_model` | 超过阈值把早期消息折成一段摘要，保留最近 N 条 |
| 自动续跑 | `GoalAutoContinueMiddleware` | `after_model` | 判定本轮"没做完"就跳回模型节点，最多 8 轮 |

两个中间件都**不调用模型**：折叠用本地规则生成摘要，续跑用结构化标记判定，保证离线可测。

## 涉及文件

| 文件 | 说明 |
|---|---|
| `middleware/context_compaction.py` | 折叠中间件 + 四个观测函数 + 两个 ContextVar |
| `middleware/goal_auto_continue.py` | 续跑中间件 + 步数计数 + 判据 |
| `middleware/__init__.py` | 导出（与 `ToolAuditMiddleware` 同级） |
| `agents/lead_agent/agent.py` | `make_lead_agent(middleware=[...])` 把中间件挂到图上 |

## 调用流程

```text
用户消息
  ▼
┌─────────────────────────────────────────────┐
│ before_model：ContextCompactionMiddleware    │
│  ① consume_skip_compaction_once()            │
│     └─ 本次要跳过 → 直接 return None         │
│  ② 算总字符数 _total_chars(messages)          │
│     └─ ≤ 12000 → return None（不折）         │
│  ③ 条数 ≤ 6 → return None（再折就没了）       │
│  ④ head = messages[:-6]，recent = messages[-6:]
│  ⑤ RemoveMessage 删 head + 插摘要消息         │
│     └─ 记 _fold_counts = (折叠前, 折叠后)      │
└─────────────────────────────────────────────┘
  ▼
模型节点（model）
  ▼
┌─────────────────────────────────────────────┐
│ after_model：GoalAutoContinueMiddleware      │
│  ① key = runtime.context["thread_id"]        │
│  ② steps = _STEPS[key]                       │
│  ③ steps ≥ 8 或 已做完 → {"jump_to": "end"}  │
│  ④ 否则 _STEPS[key] += 1                     │
│     └─ {"jump_to": "model",                  │
│          "messages": [HumanMessage("继续…")]} │
└─────────────────────────────────────────────┘
  ▼
  ├─ jump_to = "model" → 回到模型节点（不经过用户）
  └─ jump_to = "end"   → 本次 run 结束
```

## 关键实现

### 折叠必须用 RemoveMessage

```python
# 用 RemoveMessage 删掉旧消息，再插入一条摘要消息；
# 直接返回新列表会被 add_messages reducer 追加，而不是替换。
removals = [RemoveMessage(id=getattr(m, "id", "")) for m in head if getattr(m, "id", None)]
summary = HumanMessage(content=_fold_summary(head), name="context_summary")
return {"messages": removals + [summary]}
```

LangGraph 的 `messages` 通道是 `add_messages` reducer：你返回的列表是**增量**，不是全量。想"删掉早期 2 条"只有 `RemoveMessage` 一条路。

### 续跑的步数不能存 ContextVar

这是本轮踩到的真实坑：

```python
# 反例（会无限续跑）
_step_count: ContextVar[int] = ContextVar("auto_continue_steps", default=0)
```

现象：模型一直跳回 model 节点，最后 `GraphRecursionError: Recursion limit of 10000 reached`。

原因：LangGraph 每跳一个节点都新建一次执行上下文，`ContextVar` 的写入不跨节点保留，计数永远读到 0。

改成按 thread 的字典：

```python
# 续跑计数按 thread 存。
# 为什么不用 ContextVar：LangGraph 每跳一个节点都会新建执行上下文，
# ContextVar 的写入在跨节点时不保留，实测会导致计数永远为 0 → 无限续跑。
_STEPS: dict[str, int] = {}

def _thread_key(runtime: Any) -> str:
    context = getattr(runtime, "context", None) if runtime is not None else None
    try:
        thread_id = str(context.get("thread_id") or "").strip() if context else ""
    except AttributeError:
        thread_id = ""
    return thread_id or "__default__"
```

原版是把步数记在 goal 行（数据库）里的，本质是同一个思路：**跨节点的状态必须落到节点外面**。

### 未完成判据不能含"继续"

```python
# 注意不要放"继续""接着"——用户输入里出现这两个词时，模型回显也会带上，
# 会被误判成永远未完成，进而无限续跑（实测会撞 GraphRecursionError）。
_UNFINISHED_MARKERS = ("TODO", "待办", "尚未完成", "下一步")
```

第一次实现时标记表里放了 `"继续"`，用户输入"继续"→ 模型回显"已收到（第 1 轮）：继续"→ 判据命中 → 续跑 → 模型再回显 → 又命中，直到递归上限。

判据要选**模型不会顺手复述**的词。

## 知识点

### 为什么折叠放 before_model，续跑放 after_model

| | before_model | after_model |
|---|---|---|
| 时机 | 消息要发给模型之前 | 模型回答之后 |
| 折叠放这里 | 本轮就要用上裁剪后的上下文，放 after 只能影响下一轮 | — |
| 续跑放这里 | — | 只有看到模型的回答，才知道它做没做完 |

### 折叠 vs 截断

| | 折叠（fold） | 截断（truncate） |
|---|---|---|
| 做法 | 旧消息压成摘要 | 直接丢掉早期消息 |
| 保留 | 结论、决策、约束 | 只剩最近几轮 |
| 风险 | 摘要本身可能失真 | 丢掉最早的需求 |

原版选折叠，是因为 Agent 长任务里"最早的约束"往往最重要（比如"不要改这个文件"）。

### jump_to 与图状态持久化

`hook_config(can_jump_to=["model","end"])` 让中间件能把控制权交回模型节点。好处是：**跳转发生在图内部，checkpoint 照常记录**。如果自己写 `while` 循环反复 `invoke`，每一步都在图外面，恢复时步数、状态全丢。

## 跟着做与验收

| 验收 | 命令要点 | 实际结果 |
|---|---|---|
| 折叠生效 | 8 条 3000 字符消息过 `before_model` | 返回 3 条（2 条删除 + 1 条摘要） |
| 折叠计数 | `compaction_fold_msg_counts()` | `(8, 7)` |
| 续跑不误触发 | FakeChatModel 回复"已收到：继续" | 消息数 2，续跑 0/8 |
| 续跑到上限 | 模型恒回"下一步要做 A" | 消息数 10 后停在 end，无递归超限 |
