# 第 9 章 · 第 2 节｜文件工具与宿主边界

## 场景

你给助理一把钥匙，只开储藏室的门。他能进储藏室拿东西，但进不了你的卧室。这把钥匙不是靠"助理自觉"限制的——是锁本身只认储藏室。

这一节做的事一样：给模型一个读文件工具，但**边界写在代码里**：只允许读工作区根目录下的文件。绝对路径、`../` 逃逸、指向外部的软链接，全部拒绝。

## 这一节要实现什么功能

让 Agent 只能读工作区内的文本文件：拒绝绝对路径、拒绝 `../` 逃逸、拒绝目录当文件读，错误按类别返回。

**可验收的行为**：`/etc/passwd` → `[PathNotAllowed] 不允许绝对路径，请使用工作区内的相对路径`；`../../../etc/passwd` → `[PathNotAllowed] 路径越出工作区范围`；读目录 → `[NotAFile] 目标不是文件`；读不存在 → `[NotFound] 文件不存在`；读二进制 → `[NotText] 不是 UTF-8 文本文件`。

## 本节业务问题

文件工具是"宿主边界"最典型的例子：工具跑在你的机器上，能碰真实文件系统。模型决定"读哪个文件"，所以边界不能靠提示词，必须靠代码。

需要三件事：

1. **路径归一化**：把用户/模型给的字符串解析成绝对路径，再判断是否在根目录内。
2. **只在根目录内**：`/etc/passwd`、`../../../etc/passwd`、软链接逃逸都要挡住。
3. **只读**：本篇不提供写文件，避免"模型改坏用户代码"这种不可逆事故。

## 调用流程

```text
模型 tool_call: read_text_file(path="backend/config.yaml")
  ▼
resolve_in_workspace("backend/config.yaml")
  ├─ 空路径 → ValueError
  ├─ 绝对路径 → ValueError
  ├─ root = $WORKAGENT_WORKSPACE 或 cwd
  ├─ target = (root / path).resolve()
  └─ target 不在 root 下 → ValueError
  ▼
文件检查：exists / is_file / read_text(utf-8)
  ├─ 不存在 → "[NotFound]"
  ├─ 是目录 → "[NotAFile]"
  ├─ 非 UTF-8 → "[NotText]"
  └─ OSError → "[ReadError] 类型名"
  ▼
shape_result 截断到 8000 字符
  ▼
返回文本给模型
```

## 关键函数与知识点

### `resolve_in_workspace`：三道关

```python
candidate = Path(path.strip())
if candidate.is_absolute():
    raise ValueError("不允许绝对路径，请使用工作区内的相对路径")

root = workspace_root()
target = (root / candidate).resolve()
if root not in target.parents and target != root:
    raise ValueError("路径越出工作区范围")
return target
```

| 关卡 | 拦住的输入 | 原理 |
|---|---|---|
| 拒绝绝对路径 | `/etc/passwd`、`~/.ssh/id_rsa` | 绝对路径不受根约束 |
| `resolve()` 展开 | `../../../etc/passwd` | `resolve` 把 `..` 和软链接都算成真实路径 |
| `parents` 判断 | 任何指向 root 外的真实路径 | 归一化后比对前缀，绕过不了 |

**关键点**：必须"先 `resolve` 再判断"。如果先判断字符串前缀再 `resolve`，`foo/../../etc/passwd` 能骗过前缀检查。

### 为什么不用 `os.path.commonprefix`

```python
# 错误写法
if not target.startswith(str(root)):
```

`/work/root2/file` 的字符串前缀包含 `/work/root`，会被误判为合法。`Path.parents` 比对是路径级比较，不是字符串级。

### 只读工具的错误类别设计

```text
[PathNotAllowed] 不允许绝对路径        → 模型知道改相对路径
[NotFound] 文件不存在                  → 模型知道路径写错
[NotText] 不是 UTF-8 文本文件          → 模型知道别硬读二进制
[ReadError] PermissionError            → 模型不该重试，应报告用户
```

模型看到这些前缀，能自己决定"换路径 / 放弃 / 报告"，不需要整轮 failed。

### 为什么本篇只做读（写文件与终端放到第 10 章）

| 能力 | 为什么后做 |
|---|---|
| 写文件 | 不可逆；需要备份、审批、diff 预览 |
| 执行 shell | 任意命令；需要白名单、超时、输出上限、沙箱 |
| 浏览器控制 | 涉及登录态和外部副作用；需要独立进程与权限隔离 |

这些在第 10 章讨论，本篇只做"读"，先把边界思想立住。

## 跟着做与验收

1. 正常：`read_text_file("backend/config.yaml")` 返回文件内容。
2. 越界：`read_text_file("/etc/passwd")` → `[PathNotAllowed] 不允许绝对路径`。
3. 逃逸：`read_text_file("../../../etc/passwd")` → `[PathNotAllowed] 路径越出工作区范围`。
4. 软链接：在工作区内建一个指向 `/tmp` 的软链接，读取应被拒。
5. 二进制：读一个 `.png`，应返回 `[NotText]`。
6. 大文件：读一个 2 万字符的文本，确认截断并带总长度标注。
7. 对照 EvoFlow 的 `tools/host_direct/`，列出它如何处理工作区根、写文件审批和命令执行，写进本章未实现项。

## 与 EvoFlow 的差异

| 项 | EvoFlow | 本项目 |
|---|---|---|
| 文件工具拆分 | `tools/host_direct/` 下读、写、编辑分开成多个文件 | `tools/builtins/workspace_file.py` 一个文件，只有 `read_text_file` 与 `list_directory` |
| 路径守卫 | `workspace_path_guard.resolve_tool_workdir(workdir, runtime=…)` | `resolve_in_workspace(path)`（**本项目自造**，见台账第八节） |
| 写能力 | 有写/改文件工具，配审批 | **不做**：只读 |
| 工作区根 | 由 runtime / 会话决定 | `WORKAGENT_WORKSPACE` 环境变量，缺省 `Path.cwd()` |

完整台账见 [EvoFlow 对照台账与差异建议](../../EvoFlow对照台账与差异建议.md)。
