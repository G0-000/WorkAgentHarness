# 第 47 章｜从用户任务贯通全部功能域

> 所属篇：全量集成和完整复刻验收
> 功能范围：`全课程收口`
> 导航：[教程册总目录](../README.md) · [本篇导读](README.md) · [课程索引](../../学习手册/课程目录.md) · [功能路线](../../学习手册/功能单元路线.md) · [唯一状态清单](../../学习手册/功能清单.md)

## 本章目标
把“每章可运行”收敛为“完整产品能从真实入口完成用户任务”。选择至少三个跨域场景，例如：对话+工具、上传文档+知识问答、定时任务+渠道通知；场景以实际实现的功能 ID 为准。

## 收口顺序
1. 从唯一清单筛出适用 ID，标出已验收、待验收、有依据排除、未实现；不能用章节读过替代状态。
2. 对每个场景画入口→应用装配→核心用例→存储/外部服务→事件/UI 的调用图，确认没有误走 demo/mock。
3. 注入模型超时、存储失败、断连、取消、重启、权限拒绝和渠道失败，检查实体终态一致。
4. 对照启动注册、配置、迁移、Web/桌面路由、渠道/CLI、部署/许可，查“有代码无 caller”“有 UI 无后端”。
5. 回到 EvoFlow 快照复查核心包、route、渠道、UI、技能、发布；差异写理由，不要求内部目录同构。
6. 更新图和代码说明，确保它们与 WorkAgentHarness 当前 commit 相符。
7. 准备 15 分钟讲解：演示一个正常路径、一个失败路径、权限边界与恢复路径，按文档从干净环境复现。

## 最终交付
完整功能矩阵、三个端到端场景记录、差异/排除清单、架构图、启动恢复说明和讲解稿。只有适用功能有实现或有证据的排除，才称行为完整对齐。
