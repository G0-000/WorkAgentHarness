## 场景

用户配了一条自动化："每天 9 点，把昨天客户反馈整理成周报，存到 `reports/`。"

这条配置要回答四个问题：

1. **做什么**（提示词）
2. **什么时候做**（定时，第 35 章）
3. **结果存哪**（输出路径——**这条最容易漏**）
4. **做过了没**（运行历史）

第 3 点看着简单，实际很麻烦：如果输出路径是"用户填的字符串"，模型会生成 `2026-01-32` 这种不存在的日期，或者文件名里带 `/` 直接建目录失败。

## 本章要完成的功能

| 功能 ID | 要达成的行为 | 用户可见结果 |
|---|---|---|
| `WAH-AUTO-001` | Automation 定义：提示词 + 定时 + 输出模板 + 状态 | 能配、能改、能停 |
| `WAH-AUTO-003` | 运行历史：每次执行的开始/结束/结果/产物 | 能看到"昨晚跑没跑、跑到哪" |

## 本节业务问题

| 问题 | 后果 |
|---|---|
| 输出路径由模型自由发挥 | 日期非法、文件名带 `/`、覆盖别人的文件 |
| 输出目录不按自动化隔离 | 两条自动化互相覆盖 |
| 扩展名不归一 | `report.md` 和 `report.txt` 混存 |
| 无运行历史 | 失败了没人知道 |
| 历史只记成功 | 失败原因查不到 |
| 定义与执行状态混在一行 | 改了配置，不知道上次是按哪版跑的 |

## EvoFlow 源码阅读路径

| 层 | 文件与真实符号 | 作用 |
|---|---|---|
| ① 输出根 | `automation/output_paths.py:26` `resolve_automation_outputs_root()` | 统一的输出根目录 |
| ② 路径安全 | `:15` `_slug_segment(text, *, fallback="report")`；`:33` `_normalize_ext(ext)` | **文本 → 安全路径段**；扩展名归一 |
| ③ 模板渲染 | `:40` `_format_output_template(...)`；`:66` `resolve_automation_deliverable_path(...)` | 模板变量替换 → 最终路径 |
| ④ 运行开始 | `proactive/duty_runs.py:39` `start_duty_run(...)`；`:26` `_new_run_id()` | 每次执行建一条 run |
| ⑤ 运行更新 | `:118` `update_duty_run(...)` | 状态/结果写回 |
| ⑥ 运行查询 | `:176` `get_duty_run(run_id)`；`:30` `_row_to_dict(row)` | 读历史 |
| ⑦ 执行判定 | `proactive/engine.py:120` `_is_execution_failure(result)` | 什么算失败 |

**`_slug_segment` 值得单独看**：它把任意文本变成合法路径段（去非法字符、限长、空时用 fallback）。**这是"让模型生成文件名"能安全落地的前提**——没有它，模型给什么就写什么。

逐层追读要点：`start`/`update`/`get` 三个方法是运行历史的完整生命周期；`_format_output_template` 支持的变量要逐个确认。

## 调用流程

```text
定时触发（第 35 章）
  ▼
① 建 run     _new_run_id → start_duty_run（status=running）
  ▼
② 执行       提示词 → Agent
  ▼
③ 判成败     _is_execution_failure(result)
  ▼
④ 算路径     _slug_segment → _normalize_ext → _format_output_template
  │             → resolve_automation_deliverable_path
  ▼
⑤ 落文件     写入输出根下
  ▼
⑥ 收尾       update_duty_run（status + result + artifact_path）
```

## WorkAgentHarness 现状与设计

**现状**：无自动化。所有任务都是"用户说一句、跑一次"。

| 缺口 | 设计方案 | 边界 |
|---|---|---|
| 定义 | `automations(id, prompt, schedule_expr, output_template, enabled)` | 单表 |
| 输出根 | `<cwd>/.wah/automation/<automation_id>/` | 按 id 隔离 |
| 路径安全 | `slug_segment(text)`：去 `/\:*?"<>|`、限 60 字、空则 `report` | 对齐 `_slug_segment` |
| 扩展名 | `normalize_ext`：只允许 `.md` / `.txt` / `.json` | 白名单 |
| 模板变量 | 只支持 `{date}` / `{title}` / `{id}` 三个 | 不做任意表达式 |
| 运行历史 | `automation_runs(id, automation_id, status, started_at, ended_at, result, artifact_path)` | 单表 |
| 失败判定 | 结果为空或含 `[Error` 前缀 → 失败 | 对齐 `_is_execution_failure` 思路 |

**要写清的一条**：定义表与运行表**必须分开**。定义被改过之后，运行历史里那条应该记录"当时用的哪版提示词"——原版用 run 行快照，本项目至少记 `prompt_snapshot`。

## 与 EvoFlow 的差异

| 项 | EvoFlow | 本项目 |
|---|---|---|
| 输出隔离 | `resolve_automation_outputs_root` + 模板 | 按 automation_id 分目录 |
| 路径清洗 | `_slug_segment` | 同名思路，字符集更窄 |
| 扩展名 | `_normalize_ext` | 三格式白名单 |
| 模板 | `_format_output_template`（多变量） | 三变量 |
| 运行历史 | `duty_runs`（start/update/get） | `automation_runs` |
| 失败判定 | `_is_execution_failure` | 两种简单规则 |
| 快照 | 有 | 只快照提示词 |
