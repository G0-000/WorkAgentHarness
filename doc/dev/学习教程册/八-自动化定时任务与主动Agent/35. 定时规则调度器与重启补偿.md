## 场景

用户说："每周一早上 8 点提醒我复盘。"

系统里存的是人能读的规则（每周一 8 点），但执行引擎需要的是它认识的形式。中间要有转换：

- 有些人填的是 `RRULE:FREQ=WEEKLY;BYDAY=MO;BYHOUR=8`（日历标准）
- 老数据里可能是自定义字符串（`"weekly_monday_8"` 之类）
- 引擎真正要的是 cron 表达式

再加上一个现实问题：**机器关机了怎么办**。周一的 8 点，电脑没开，这条要不要补跑？补跑几次？补跑会不会重复？

## 本节业务问题

| 问题 | 后果 |
|---|---|
| 只认一种格式 | 用户填 RRULE，直接存进去，运行时解析失败 |
| 不做旧格式迁移 | 老数据全废 |
| 不识别"关闭"状态 | 停用的任务照样触发 |
| 无 tick 驱动 | 靠 sleep 循环，精度差、难测试 |
| 重启不补偿 | 关机期间的任务永久丢失 |
| 无脑补偿 | 关机 3 天，一次补跑 3 遍 |
| 无事件触发 | 只能按时间，不能"文件一变就跑" |

## 调用流程

```text
用户填规则
  ▼
① 判关闭    is_schedule_off(value) → 停用则不入调度
  ▼
② 判格式    looks_like_legacy_rrule(value)
  │             ├ 旧 → legacy_rrule_to_cron
  │             └ 新 → _parse_rrule_parts → cron
  ▼
③ 入库      统一存 cron
  ▼
④ tick      runner 每 N 秒扫一次 → 到期任务入队
  ▼
⑤ 事件      EventTriggerBus → 文件/消息变化触发
  ▼
⑥ 重启补偿   比对"上次执行时间"与"本应执行时间" → 决定补不补、补几次
```

## WorkAgentHarness 现状与设计

**现状**：无定时。CLI 是"跑一次就退"，进程不在就不会有任务。

| 缺口 | 设计方案 | 边界 |
|---|---|---|
| 规则格式 | **只支持 cron 五段**，不支持 RRULE | 用户填 RRULE → 报错并提示转换 |
| 关闭 | `schedule` 为空或 `off` → 停用 | 对齐 `is_schedule_off` |
| 驱动 | CLI 常驻模式：`while True: sleep(30); 扫到期` | 不做事件触发 |
| 到期判定 | 存 `next_run_at`，tick 时比对 | 不做实时计算 cron |
| 重启补偿 | `catch_up` 策略：只补最近 1 次，超过 24 小时不补 | 明确"最多补 1 次" |
| 重复保护 | `last_run_at` + 幂等键（`automation_id + scheduled_at`） | 对齐幂等思路 |
| 事件触发 | **不做** | 无文件监听 |

**必须写清**：本项目**不做 RRULE**。原版有完整迁移链（`legacy_rrule_to_cron`），我们直接要求 cron——这是能力缩减，不是"已对齐"。

## 与 EvoFlow 的差异

| 项 | EvoFlow | 本项目 |
|---|---|---|
| 规则格式 | RRULE + 旧格式 + cron（可迁移） | 仅 cron |
| 关闭语义 | `is_schedule_off` | 空值 / `off` |
| 驱动 | tick + 事件总线 | 仅 tick（30 秒） |
| 事件触发 | `EventTriggerBus` | 不做 |
| 补偿 | 有判定 | 只补最近 1 次，24 小时窗口 |
| `scheduler/` 含义 | **工具编排**，不是 cron | 本项目不做工具编排 |
