## 本篇三条澄清

1. **`scheduler/` 不是定时调度器**。`scheduler/engine.py:52 class LocalToolScheduler`、`task_plan.py:16 TaskOp`、`tool_executor.py:24 execute_op` —— 这是**一次任务内的工具编排**（预取、编辑后 lint、重试）。**真正的定时在 `proactive/schedule.py`**（`is_schedule_off:35`、`looks_like_legacy_rrule:49`、`legacy_rrule_to_cron:56`、`migrate_stored_schedule:118`）。按目录名找 cron 会找到错的地方。
2. **主动 Agent 的核心是"决策闸门"**，不是定时。`proactive/decision_gate.py:55 class DecisionGate` 决定"这次要不要说话"；`cycle_limits.py:39 effective_max_initiatives(role)` 决定"说几条"；`round_token:55` 防同日重复。**没有闸门，每 30 分钟发一条"一切正常"，两天就被关掉。**
3. **输出路径必须清洗**。`automation/output_paths.py:15 _slug_segment(text, *, fallback="report")` + `:33 _normalize_ext(ext)`。让模型生成文件名，不清洗就会出 `2026-01-32` 和带 `/` 的名字。本项目只允许 `.md/.txt/.json` 三种扩展名。

## 本篇综合练习（文档级，不跑代码）

场景：用户配"每天早上 9 点，把昨天客户反馈整理成报告，推到我飞书"。

1. 这条配置涉及哪几张表（定义、运行历史、待办）？
2. 定时规则存成什么格式？如果用户填 RRULE，本项目怎么办？
3. 电脑关机 3 天，第 4 天开机：
   - 补不补？
   - 补几次？窗口多大？
   - 怎么保证不重复？
4. 报告生成后，推飞书的哪一步会判"用户已退订"？
5. 用户点了飞书里的"处理"，任务中心的待办怎么变？

五问写表，每格标"原版 / 本项目 / 差异性质（缩减 or 不做）"。

## 本篇出口

能解释"一条自动化从配置到产出再到通知，中间有哪几处会因关机、退订、重复而失败，各靠什么机制兜住"。
