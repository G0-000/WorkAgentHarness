## 场景

一个公司买了 50 个席位：

- 每个员工的 Agent 要能装"公司定制插件包"（**组织分发**）；
- 只有付了钱的功能能用（**License**）；
- 管理员要能改组织配置、看审批（**Admin**）；
- 员工申请"要访问某个敏感知识库"，要有人批（**审批**）。

四件事彼此独立，但都建立在第 48 章的身份与第 49 章的认证之上。

## 本节业务问题

| 问题 | 后果 |
|---|---|
| 分发包无清单 | 装了不知道装了什么 |
| License 不绑机器 | 一份 License 到处复制 |
| License 不判过期 | 过期还能用 |
| Admin 无权限检查 | 普通用户能改组织配置 |
| 审批无状态机 | 批了还能再批、撤回没痕迹 |
| 审批与执行不联动 | 批了但没执行，或没批却执行了 |

## 调用流程

```text
组织分发
  清单 → installer 装 → registry 记实例 → 派生产物（list_artifacts）
  ▼
License
  启动 → machine_id → get_license_status
          ├ 过期/无效 → is_premium_active = False
          └ 付费功能入口 → require_premium() → 抛/拒
  ▼
Admin
  入口 → require_org_admin（第 48 章）→ 放行到 platform_actions
  ▼
审批
  用户申请 → 建 approval（pending）
  ▼
  管理员 → list_approvals(status="pending") → 批准/拒绝
  ▼
  执行侧 → 读审批结果 → 决定是否执行（第 26 章审批三档）
```

## WorkAgentHarness 现状与设计

**现状**：无组织、无 License、无 Admin、审批只有第 26 章的三档。

| 缺口 | 设计方案 | 边界 |
|---|---|---|
| 组织分发 | **不做** | 无组织概念 |
| License | **不做** | 开源项目无付费能力 |
| Admin | 不做（CLI 无管理面） | — |
| 审批 | 复用第 26 章 `allow/ask/deny`，**不做审批单** | 无 pending 列表、无多人批 |
| 审批记录 | `approvals(id, action, status, decided_at)` 单表（若要做） | 单表 |

**必须写清**：本章 4 个功能里，本项目**只打算做"审批记录表"**，其余三项（组织分发、License、Admin）明确不做。原因是：本项目是单机单用户，这三项没有使用前提。

## 与 EvoFlow 的差异

| 项 | EvoFlow | 本项目 |
|---|---|---|
| 组织分发 | `organizations/` 六文件 | 不做 |
| License | `license/` 九文件 + 机器绑定 | 不做 |
| 能力门禁 | `require_premium()` | 无 |
| Admin | `admin/` 40 文件 | 不做 |
| 审批 | 列表 + 富化行 + 角色解析 | 仅三档，无单 |
| 审批联动 | 与执行联动 | 三档在工具调用时判 |
