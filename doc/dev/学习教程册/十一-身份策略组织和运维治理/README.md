## 本篇三条澄清（第 53 章另有一节说明）

1. **认证和护栏是两件事**。认证（`webui/auth.py:59 hash_password` / `:133 generate_jwt` / `oidc.py`）在门口；护栏（`guardrails/builtin.py:6 class AllowlistProvider`）在屋里。而且护栏是**白名单**（只有清单里的放行），不是黑名单——黑名单永远漏。
2. **会话可见性必须成对做**。`authz/session_ownership.py:46 stamp_session_ownership`（写入时盖章）+ `:126 session_visible_to_principal`（读取时判）+ `:15 acl_session_list_filter_sql`（列表 SQL 过滤）。三处缺一处就漏：只判读取，历史数据没章判不了；只盖章，列表还是全表返回。
3. **Eval 是"AI 应用的单测替代"**。`eval/business_quality.py` 做业务口径打分，**不是字符串匹配**——完全匹配在 AI 场景下 100% 失败（换个说法意思一样）。`eval_engine.py:44 _new_alert_id` 说明它还会告警。

## 本篇综合练习（文档级，不跑代码）

场景：10 人团队，A 的会话 B 不能看，公司公告所有人可见。

1. `Principal` 要几个字段才能表达"这个人属于哪个组织"？
2. 作用域怎么分层（个人 / 组 / 组织）？
3. 判"B 能不能看 A 的会话"，要查哪两处？
4. 如果只做了"读取时判断"，历史会话会出现什么问题？
5. 这套东西在**单机单用户**的本项目里，有使用场景吗？

五问写表，最后一列填"本项目是否需要 / 为什么"。
