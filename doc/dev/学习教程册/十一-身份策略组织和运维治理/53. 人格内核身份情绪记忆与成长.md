# 第 53 章｜人格内核：身份、情绪、记忆与成长

> 本篇唯一一个「不接工具、不接渠道，只改 Agent 自己」的模块：它决定员工 Agent 第二天还记得你、说话带什么情绪、答应过谁什么、会不会自己长出新技能。

## 前置依赖与学习顺序

- **前置**：第 52 章出口；本篇开始条件（篇导读「开始条件」）。
- **功能 ID**：`WAH-PERSON-001`。
- **顺序**：按本章十节顺序——场景 → 功能 → 业务问题 → 源码路径 → 调用流程 → 现状设计 → 差异 → 实作单 → 出口 → 验收。
- **状态**：设计完成，未实现、未验收；学到这里再按「未来验收条件」开跑。

## 本章场景

早上 9 点，老板在飞书里问员工 Agent「上周那个对账脚本跑通了吗」。

- 它先记起来：这是上周三答应过的事（**承诺**），还欠着。
- 它说话的语气有点歉疚（**情绪激素**），不是机械的「已完成」。
- 它翻出上周四自己写的一篇复盘（**收工反思**），里面记着「卡在时区转换」。
- 它顺手把这次踩的坑写成一条 lesson 追加进 SOUL（**经验教训**），下周不会再犯。
- 晚上 11 点，它跑一次夜间整理，把反复出现的做法固化成一项技能（**技能自生长**）。
- 老板在管理页面看到一条脱敏摘要：最近状态、未完成承诺、成长曲线（**人格简报**）。

这六件事，全部来自 `person_kernel.py` 一个文件。

## 本章学习目标

1. 能说出人格内核的**六个子域**：身份、情绪、关系承诺、代谢、成长、反思；
2. 能从 `prompt.py` 找到人格内容的**全部注入点**：身份、SOUL 两处直接注入，情绪经 `get_agent_affect_block` wrapper 注入，记忆/手艺各一处；并解释为什么要「注入」而不是直接拼字符串；
3. 能解释 SOUL 的**去重机制**：为什么要把身份段从 SOUL 里先删掉再注入；
4. 能区分「业务消息表」「checkpoint」「人格状态表」三类存储，它们各存在哪；
5. 能指出哪些行为是**用户可见**的（语气、记忆、承诺、成长页），哪些只是内部调度。
