## 场景

用户说："昨天那个任务怎么跑了 4 分钟？"

没有观测数据，只能猜。有了数据，可以直接看：

- 哪个模型的调用最慢（`latency_waterfall`）
- 哪个工具卡住了（`tool_timing`）
- 缓存命中率（`cache_metrics`）
- 这次花了多少钱（`cache_pricing`）
- 上下文被压缩过几次（`compaction_file_log`）

关键点：**这些数据不能是"事后补记"**，必须在调用发生时**异步落盘**——不能因为写日志把主流程拖慢。

## 本节业务问题

| 问题 | 后果 |
|---|---|
| 同步写日志 | 主流程被 IO 拖慢 |
| 无 trace_id | 一条链路的数据串不起来 |
| 只记总耗时 | 不知道慢在哪一步 |
| 不记成本 | 月底账单看不懂 |
| 日志不轮转 | 磁盘写满 |
| 无面板 | 数据多但没人看 |

逐层追读要点：先看 `recorder.py` 的 `_store_for_config()` 怎么决定"存不存"（可能有关闭开关）。

## 调用流程

```text
模型调用前
  ▼
① 记开始    recorder（异步）
  ▼
② 调用      实际模型
  ▼
③ 记结束    耗时 + token 用量 + 成本
  │             └ _fire_and_forget → 不阻塞返回
  ▼
④ 落盘      sqlite_store
  ▼
⑤ 查询      latency_waterfall → 拆解
  ▼
⑥ 面板      dashboard → 展示
```

## WorkAgentHarness 现状与设计

**现状**：有 `middleware/tool_audit.py`（审计工具调用），但**不记耗时、不记成本**。

| 缺口 | 设计方案 | 边界 |
|---|---|---|
| 记录 | `observe(event)` → 异步队列 → 批量写 | 对齐 `_fire_and_forget` 思路 |
| 存储 | 复用现有 `.db`，新增 `obs_events` 表 | 单表 |
| trace_id | 用 `run_id` 作为 trace_id | 不做嵌套 span |
| 工具耗时 | `tool_audit` 前后打时间戳 | 复用已有中间件 |
| 成本 | **不做**（不接价格表） | — |
| 压缩记录 | **不做** | — |
| 面板 | 不做（CLI 一个 `--stats` 输出） | — |

**要写清的一条**：本项目**不做成本与缓存指标**。这两项需要价格表和 provider 元数据，本项目没有。

## 与 EvoFlow 的差异

| 项 | EvoFlow | 本项目 |
|---|---|---|
| 文件数 | 30+ | 1（`obs.py`） |
| 写入方式 | fire-and-forget | 异步队列 + 批量 |
| 轨迹瀑布 | `latency_waterfall` | 无 |
| 成本 | `cache_pricing` | 不做 |
| 缓存指标 | `cache_metrics` | 不做 |
| 面板 | `dashboard` | 无 |
| 压缩记录 | 两文件 | 不做 |
