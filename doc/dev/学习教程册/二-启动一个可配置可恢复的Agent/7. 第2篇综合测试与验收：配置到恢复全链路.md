## 场景

第 3–6 章分别讲配置、Agent 构建、持久化、生命周期，但真实用户只做一件事：**在终端敲一句话，隔天再用同一个会话接着聊**。这条链要一次走通，中间任何一环断开，后面所有工具、记忆、渠道都无从谈起。

本章把四章串成一条真实入口路径，不重复每章的验收表。

## 串联路径

`config.yaml` → `load_chat_model_config`（7 条校验）→ 模型工厂 → `make_lead_agent` → `RunService.execute` → `sessions/messages/runs` 三表 + checkpointer → 同 thread 续跑 → stdio JSON-RPC 入口。

四个入口（交互 / `--once` / `--stream/--sse` / `--mode app-server`）共用同一个 `RunService`，差别只在谁读输入、谁写输出。

### 适用失败路径（本层真实可复现）

| 场景 | 入口 | 实测结果 | 说明 |
|---|---|---|---|
| 配置缺 `model` 字段 | 直接调 `load_chat_model_config` | `ValueError: models.chat 配置字段无效: ChatModelConfig.__init__() missing 1 required positional argument: 'model'` | 在加载层暴露，配置错误不进入运行期 |
| `provider: nope` | 同一个 loader | **loader 不报错**，通过校验 | 分层边界：loader 只验类型与非空，不验 provider 真实性 |
| `provider: nope` | 到模型工厂 | `ValueError: 不支持的模型 provider: nope`（`models/factory.py:117`） | 错误在工厂层暴露，不在配置层 |

第三条是本篇最重要的边界证据：**"配置校验通过"不等于"provider 可用"**。CLI 直跑 `no_model` 时异常被吞、stdout 为空、退出码 1，所以失败路径必须直调 loader，不能只看终端。
