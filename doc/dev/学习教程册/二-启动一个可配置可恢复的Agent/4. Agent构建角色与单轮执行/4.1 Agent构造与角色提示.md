# 第 4 章 · 第 1 节｜Agent 构造与角色提示

## 场景

你雇了个助理。告诉他"你是我的编程助理，回答要简洁"，再给他一台电脑（模型），他就能干活——开机、打字是电脑的事。

这一节把模型（电脑）、角色提示（岗位说明）、工具（工具箱）组装成一个能干活的对象。组装好以后，你只跟他说话。

## 学习目标

| 层级 | 目标 |
|---|---|
| 主目标 | 能说清 `make_lead_agent` 为什么只做"装配"、不做"创建"；能说出它注入的 4 类依赖各自对应什么 |
| 次目标 | 能区分"角色提示进入图"与"模型按提示改变行为"是两件事 |

## EvoFlow 源码阅读路径

`make_lead_agent` 在原版**同名存在**，但签名和体量完全不同：

| 环节 | 去哪里读 | 读什么 |
|---|---|---|
| 装配入口 | `evoflow/agents/lead_agent/agent.py:996` → `make_lead_agent(config: RunnableConfig, runtime: ServerRuntime \| None = None)` | 接的是**运行时配置 + 服务运行时**，不是模型实例 |
| 图构造 | 同文件 `:1431`、`:1876` 两处 `create_agent(...)` | 两处构造对应不同路径（挂载前 / 重挂载后），注释里写明"tools 列表必须两边都更新" |
| 提示组织 | `evoflow/agents/lead_agent/prompt_blocks.py`、`prompt_blocks_zh.py`、`prompt_blocks_en.py` | 提示不是一个大字符串，而是可组合的 **block 列表**，还有中英双语 |
| 动态提示 | `evoflow/agents/lead_agent/dynamic_prompt_run.py` | 提示在运行期按上下文动态生成，不是常量 |
| 工具画像 | `evoflow/agents/lead_agent/intent_tool_profile.py` | 按意图裁剪工具集 |
| 图缓存 | `evoflow/agents/lead_agent/graph_cache.py` | 图被缓存复用，不是每次重建 |

**关键结论**：原版 `lead_agent/` 是 **10+ 个文件的子系统**（动态提示、图缓存、意图工具画像、双语提示块）；本项目把它压成 **1 个文件 + 1 个常量**。这是本章最大的一处收窄，后面章节逐步补回。

## 关键函数与知识点

### `make_lead_agent`（`agents/lead_agent/agent.py`）

```python
def make_lead_agent(
    model: BaseChatModel,
    *,
    checkpointer: BaseCheckpointSaver | None = None,
    system_prompt: str = DEFAULT_SYSTEM_PROMPT,
):
    # 只装配，不创建：模型必须由调用方传入
    return create_agent(
        model=model,
        tools=[],                    # 第 4 章：本篇不加工具
        middleware=[],               # 第 4 章：本篇不加中间件
        checkpointer=checkpointer,   # None=单轮；saver=可恢复
        system_prompt=system_prompt,
    )
```

四个要点：

1. **依赖注入，不在内部装配**：模型、checkpointer、prompt 全部由调用方传入。换 fake / 真实模型不需要改这里。
2. **`tools=[]` / `middleware=[]` 是范围选择**：是"本篇没加"，不是"库不支持"。别假设传 `None` 会自动变成 `[]`。
3. **`DEFAULT_SYSTEM_PROMPT` 单独抽常量**：角色指令与模型参数（temperature、provider）属于两个配置边界，改一个不该影响另一个。
4. **`checkpointer` 可选**：同一个入口既服务单轮（`None`），又服务 thread 恢复（saver），不用写两套构造代码。

### 一个容易踩的坑：prompt 生效 ≠ 回显变化

`FakeChatModel._generate` **不读 system prompt**——它只拿 `messages` 里的 human 消息做回显。所以"改 prompt，fake 的回显前缀跟着变"这种事**不会发生**。

要验证 prompt 真的进了图，只能看**图内的消息列表**：

```python
result = agent.invoke({"messages": [("user", "你好")]})
# result["messages"][0].type == "system"
# result["messages"][0].content == 你设置的 prompt
```

要验证"模型按提示改变行为"，必须换真实模型。这是两件事，本章只验证前者。

## 与 EvoFlow 的差异

| 项 | EvoFlow | 本项目 |
|---|---|---|
| 函数签名 | `make_lead_agent(config: RunnableConfig, runtime: ServerRuntime \| None)` | `make_lead_agent(model, *, checkpointer, system_prompt)` |
| 装配输入 | 运行时配置对象 + 服务运行时，内部再去取模型 | 直接收模型实例 |
| 文件规模 | `agents/lead_agent/` 10+ 文件 | `agents/lead_agent/agent.py` 单文件 |
| 提示 | `prompt_blocks` 可组合块 + 中英双语 + `dynamic_prompt_run` 动态生成 | 一个 `DEFAULT_SYSTEM_PROMPT` 常量 |
| 工具 | `intent_tool_profile` 按意图裁剪 | 固定 `tools=[]` |
| 图构造 | 两处 `create_agent`（挂载 / 重挂载），带 `graph_cache` | 一处，每次新建 |
