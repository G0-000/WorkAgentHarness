# 第 3 章 · 第 2 节｜凭证边界与密钥脱敏

## 场景

车能跑起来还不够：油卡不能贴在挡风玻璃上。密钥要能被读到、被展示成“打过码的样子”，出错时也不能整串打进日志。

## 学习目标

| 层级 | 目标 |
|---|---|
| 主目标 | 能说清 API key 从哪来、在哪一层被校验、在哪一层被脱敏 |
| 次目标 | 能复现“缺 api_key”的两条路径，并说明为什么都在配置加载阶段报错 |

## EvoFlow 源码阅读路径

| 环节 | 去哪里读 | 读什么 |
|---|---|---|
| 脱敏 | `evoflow/models/credential_sanitize.py` → `sanitize_api_key()` / `is_masked_api_key()` / `resolve_credential_reference()` | 密钥脱敏与引用解析 |
| 凭证自动加载 | `evoflow/models/credential_loader.py` | 从 Claude Code / Codex CLI 的**文件凭证**读 token（OAuth） |

**关键结论**：原版 `credential_loader.py` 管 CLI 凭证文件，本项目同名模块管 API key 解析与脱敏——**同名不同职责**。

## 本项目实现路径

```text
config/loader.py::load_chat_model_config(path)
  ├─ _expand_env()                  # ${VAR} / $VAR 展开，缺失即报错
  └─ provider == "openai-compatible" 且 api_key 为空 → ValueError
models/credential_loader.py
  ├─ resolve_api_key(config)        # 环境变量优先，其次 config.api_key
  ├─ mask_api_key(key)              # 展示用：前4 + **** + 后4
  └─ sanitize_error(message)        # 异常文本里的密钥打码
```

## 关键函数与知识点

### `credential_loader.py` 三件套

| 函数 | 行为 |
|---|---|
| `resolve_api_key(config)` | 环境变量 `WORKAGENT_MODEL_API_KEY` 优先，其次 `config.api_key` |
| `mask_api_key(key)` | 前 4 位 + `****` + 后 4 位；长度 ≤ 8 全 `*` |
| `sanitize_error(message)` | 正则 `sk-[A-Za-z0-9_-]{8,}` → `[REDACTED]` |

容易误解的点：provider 为 `openai-compatible` 时，**loader 已保证 `config.api_key` 非空**（否则配置加载阶段就失败）。所以“其次 `config.api_key`”这条兜底，实际作用是用环境变量**覆盖** YAML 里的占位值。

### 密钥缺失到底在哪一步报错

| 配置写法 | 报错位置 | 消息 |
|---|---|---|
| `provider: openai-compatible`，YAML 无 `api_key` 或为空 | `config/loader.py`（配置加载） | `openai-compatible provider 需要 api_key` |
| `api_key: ${WORKAGENT_MODEL_API_KEY}`，环境变量未设 | `config/loader.py` → `_expand_env` | `缺少必需的环境变量: WORKAGENT_MODEL_API_KEY` |
| 以上都通过，运行期环境变量被清空 | `models/credential_loader.py` → `resolve_api_key` 返回空串，`ChatOpenAI` 构造时报 SDK 错误 | 供应商错误，已被 `sanitize_error` 脱敏 |

**三条都在模型真正发请求之前**，但只有前两条是本项目能给出明确契约错误的。

## 跟着做

1. 把 `api_key` 从 YAML 删掉，观察报错原文。
2. 用 `${WORKAGENT_MODEL_API_KEY}` 占位但不设环境变量，观察第二条报错。
3. 用 `mask_api_key` 打印一次，确认只露头尾。

## 本节验收

| 项 | 通过标准 | 对应测试 |
|---|---|---|
| 缺 api_key | 报“openai-compatible provider 需要 api_key” | `test_ch03_config.py::test_openai_compatible_requires_api_key` |

| 真实额度 | 不要求 | — |

## 与 EvoFlow 的差异

| 项 | EvoFlow | 本项目 |
|---|---|---|
| 凭证加载 | `models/credential_loader.py`：Claude Code / Codex CLI 的文件凭证（OAuth） | 同名模块，职责不同：`resolve_api_key` 解析 API key |
| 脱敏 | `models/credential_sanitize.py`：`sanitize_api_key` / `is_masked_api_key` / `resolve_credential_reference` | `credential_loader.py` 里：`mask_api_key`（展示）+ `sanitize_error`（异常文本） |
