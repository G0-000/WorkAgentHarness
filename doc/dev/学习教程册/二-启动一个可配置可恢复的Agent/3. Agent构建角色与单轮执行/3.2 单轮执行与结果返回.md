# 第 3 章 · 第 2 节｜单轮执行与结果返回

## 本节业务问题

把用户文本转换为 Agent 输入，再从图结果中取出 assistant 回复。协议入口不应该自己调用模型，也不应依赖 LangGraph 内部节点结构。

## 涉及文件

| 文件 | 职责 |
|---|---|
| `agents/lead_agent/agent.py` | `make_lead_agent` 构造的 Agent 可调用对象 |
| `execution/run_service.py`（第 4 章） | 正式接管：校验 → 写消息 → invoke → 取答案 → 写终态 |

## 调用流程

```text
用户文本（CLI/API/测试）
  ▼
输入校验：text.strip() 非空          # 空输入在调用模型前拒绝
  ▼
agent.invoke(
    {"messages": [("user", text)]},   # 输入形状：消息列表
    config?                           # 无 checkpointer 时不传 thread_id
)
  ▼
result["messages"]                    # 图执行后的完整消息列表
  ▼
answer = str(result["messages"][-1].content)   # 最后一条是 assistant 回复
  ▼
返回 answer 给入口输出
```

## 关键函数与知识点

### `agent.invoke` 契约

- **输入**：`{"messages": [("user", text)]}`——消息列表是 LangGraph Agent 的标准输入形状。
- **输出**：`result["messages"]` 是执行后的全部消息（含 user 原样 + assistant 回复），**最后一条**才是本次回复。
- **无持久化配置时**：一次调用的图状态不跨进程保留；第 4 章加 `thread_id` + checkpointer 后才可恢复。

### `answer_once`（章节正文中的薄函数）

```python
def answer_once(agent, user_text: str) -> str:
    if not user_text.strip():
        raise ValueError("用户输入不能为空")   # 边界在调用模型前失败
    result = agent.invoke({"messages": [("user", user_text)]})
    return str(result["messages"][-1].content)
```

- 它只表达"文本进、文本出"的边界，不处理协议和存储；第 4 章 `RunService.execute` 就是在这个边界上加 session/run 生命周期。

### fake model 的观察价值

- `FakeChatModel` 回显**消息轮数 + 最新输入**；它只能证明装配与输入传递正确，不替代真实 LLM 的语义评估。
- 同一 thread 恢复后轮数递增 → 可据此区分"真的恢复状态"和"只是把历史重新拼了一遍"。
