# 第 3 章 · 第 2 节｜单轮执行与结果返回

## 本节业务问题

把用户文本转换为 Agent 输入，再从图结果中取出 assistant 回复。协议入口不应该自己调用模型，也不应依赖 LangGraph 内部节点结构。

## 调用流程

```text
text → 输入校验 → agent.invoke({messages: [user]})
     → 最后一条消息 → answer → 入口输出
```

## 代码解释

- `agent.invoke` 接收消息列表；无持久化配置时，一次调用的图状态不会跨进程恢复。
- 第 4 章的 `RunService` 将复用此调用，但会增加 session、消息和 run 生命周期。
- fake model 回显消息轮数和最新输入；它只能证明装配与输入传递，不替代真实 LLM 的语义评估。
- WorkAgentHarness 对应代码见 [Agent 构造](../../../../../backend/packages/harness/workagentharness/agents/lead_agent/agent.py) 和 [RunService](../../../../../backend/packages/harness/workagentharness/execution/run_service.py)。

## 跟着做与验收

从 CLI 输入一条非空消息，追到 `agent.invoke` 并确认只输出最终 assistant 文本；空文本应在调用模型前被拒绝。对照 EvoFlow Gateway route 的输入 schema、权限依赖、调用者与 response/event 返回方式，记录本篇单轮实现尚未覆盖的流式和协议行为。
