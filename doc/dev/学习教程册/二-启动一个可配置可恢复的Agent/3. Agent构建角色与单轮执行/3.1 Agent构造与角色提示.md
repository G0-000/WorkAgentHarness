# 第 3 章 · 第 1 节｜Agent 构造与角色提示

## 本节业务问题

模型只负责生成回复；Agent 把模型、角色提示、工具和状态机制组合成可执行图。本篇先用 lead agent 做最小实现，工具和 middleware 留到对应功能单元。

## 涉及文件

| 文件 | 职责 |
|---|---|
| `agents/lead_agent/agent.py` | `make_lead_agent` 装配入口 + 默认系统提示 |
| `models/factory.py`（上一章） | 提供已构造的 `BaseChatModel`，Agent 不自己建模型 |
| `agents/checkpointer/provider.py`（第 4 章） | 可选注入 SQLite checkpointer |

## 调用流程

```text
CLI/App Server 装配层
  ▼
create_chat_model(config)             # 第 2 章工厂，Agent 不接触供应商
  ▼
make_lead_agent(
    model,
    checkpointer=None,                # 第 4 章才传 SqliteSaver

  ▼

    model=model,          # 已注入的模型实例

    checkpointer=checkpointer,  # None = 单轮；saver = 可恢复
    system_prompt=system_prompt,  # 角色指令与模型参数分离
)
  ▼
返回可调用 Agent（LangGraph 图）
```

## 关键函数与知识点

### `make_lead_agent`（agent.py）

```python
def make_lead_agent(
    model: BaseChatModel,
    *,
    checkpointer: BaseCheckpointSaver | None = None,
    system_prompt: str = DEFAULT_SYSTEM_PROMPT,
):
    return create_agent(
        model=model, tools=[], middleware=[],
        checkpointer=checkpointer, system_prompt=system_prompt,
    )
```

1. **依赖注入，不在内部装配**：模型、checkpointer、prompt 全部由调用方传入；换 fake/真实模型不需要改 Agent 构造代码。
2. **`DEFAULT_SYSTEM_PROMPT`**：固定角色指令，单独一个常量，和模型参数（temperature、provider）属于不同配置边界。
3. **`tools=[]` / `middleware=[]` 是明确的范围选择**：是"本篇没加"，不是"库不支持"；不要假设传入 `None` 的行为。
4. **可选 `checkpointer`**：同一个构造入口既服务第 3 章单轮（None），又服务第 4 章恢复（saver），不重写 Agent。
