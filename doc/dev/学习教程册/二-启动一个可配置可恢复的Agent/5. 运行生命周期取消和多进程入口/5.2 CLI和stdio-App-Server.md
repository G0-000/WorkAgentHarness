# 第 5 章 · 第 2 节｜CLI 和 stdio App Server

## 本节业务问题

CLI 与 App Server 是不同输入/输出协议，但应复用同一 `RunService`。CLI 负责命令参数和终端展示；stdio server 负责 JSON-RPC framing 和响应，不直接操作 Agent。

## 涉及文件

| 文件 | 职责 |
|---|---|
| `cli/main.py` | 入口装配 + argparse + 终端循环/`--once` |
| `app_server/stdio_rpc.py` | JSON-RPC 2.0 教学子集：读一行、回一行 |
| `execution/run_service.py` | 两个入口共用的核心用例 |

## 调用流程

```text
命令行参数：--config / --db / --thread / --once / --mode
  ▼
装配层（cli/main.py main()）
  ├─ load_chat_model_config(args.config)   # 配置
  ├─ open_database(args.db)                # 业务库
  ├─ open_checkpointer(args.db)            # checkpoint 长连接
  ├─ create_chat_model(chat_config)        # 模型
  ├─ make_lead_agent(model, checkpointer=saver)   # Agent
  ├─ SessionRepository / RunRepository
  └─ RunService(agent, sessions, runs)     # 核心用例
  ▼
mode = "cli"
  ├─ --once → 执行一次并打印，立即退出
  └─ 交互 → 循环 input()，/exit 退出
mode = "app-server"
  └─ serve_stdio(service, sessions)
       ├─ initialize     → serverInfo + capabilities
       ├─ server/ping    → {ok: true}
       ├─ turn/start     → sessions.create → service.execute
       ├─ 未知方法        → -32601
       ├─ 无效 JSON       → -32700
       ├─ 无效参数        → -32602
       ├─ 内部异常        → -32603（不回显内部细节）
       └─ notification（无 id）→ 不返回响应
```

## 关键函数与知识点

### `main`（cli/main.py）

```python
parser.add_argument("--config", default="config.yaml")
parser.add_argument("--db", default="data/workagentharness.db")
parser.add_argument("--thread", help="继续已有 session/thread")
parser.add_argument("--once", metavar="TEXT")
parser.add_argument("--mode", choices=("cli", "app-server"), default="cli")
```

1. **所有依赖在入口装配**：`RunService` 不自己读配置、不开数据库；换入口只换协议适配，核心用例不变。
2. `owner_id = "local-user"` 是显式占位：用户鉴权留到治理篇，字段先保留。
3. 连接关闭在 `finally`：`checkpoint_conn.close()` + `database.close()`，中断/异常都释放。

### `serve_stdio`（stdio_rpc.py）

```python
def _response(request_id, result=None, error=None) -> dict:
    """统一 JSON-RPC 响应封装：error 与 result 互斥。"""
```

- **一行一个请求/响应**：`for line in source` → `json.loads(line)` → 分派 → 写回一行。
- **错误码语义**：`-32700` 无效 JSON、`-32602` 无效参数、`-32601` 未知方法、`-32603` 内部错误（不把内部异常或密钥回显给宿主）。
- **notification 不响应**：`"id" in request` 才写响应，符合 JSON-RPC 2.0。
- `turn/start` 内部：`sessionId` 缺省时 `uuid4().hex` 生成；先 `sessions.create` 再 `service.execute`，与 CLI 同一链路。

## 跟着做与验收

先按篇 README 运行 CLI，再把同一输入改由 stdio RPC 发送。检查两入口生成的 run 和业务消息一致；测试非法 JSON、未知方法、空文本和 EOF 清理。随后按 EvoFlow 实际协议补齐初始化状态、配置、thread/turn、事件流、interrupt、并发和关闭行为，再连接真实桌面宿主。
