# 第 5 章 · 第 1 节｜Run 生命周期和取消边界

## 本节业务问题

一次 Agent 执行是一条 Run。Run 要有唯一 id、明确状态转换、可追踪错误类别和资源关闭逻辑。将 run 标成 cancelled 不等于模型请求、工具或后台任务已经停止。

## 涉及文件

| 文件 | 职责 |
|---|---|
| `persistence/run_repository.py` | run 表 SQL 与终态转移约束 |
| `execution/run_service.py` | 编排 Agent + 两个 Repository + 异常翻译 |
| `persistence/schema.py` | runs 表 DDL（status CHECK 约束） |

## 调用流程

```text
RunService.execute(owner_id, session_id, text)
  ▼
空文本校验                           # ValueError，未建 run
  ▼
run_id = uuid4().hex                # 每次尝试单独编号；重试不复用
  ▼
runs.start(run_id, session_id, owner_id, now)   # status='running'
  ▼
sessions.add_message(session_id, "user", text)  # 消息写入纳入生命周期
  ▼
agent.invoke(messages, thread_id=session_id)
  ├─ 成功
  │   ├─ sessions.add_message(assistant)
  │   └─ runs.complete(run_id, now)             # → completed
  ├─ Exception
  │   └─ runs.fail(run_id, type(exc).__name__, now)  # → failed，只存异常类型名
  └─ KeyboardInterrupt
      └─ runs.cancel(run_id, now)  +  re-raise   # → cancelled，中断交还入口
```

## 关键函数与知识点

### `RunRepository.finish`（run_repository.py）

```python
cursor = self._conn.execute(
    "UPDATE runs SET status = ?, error_code = ?, updated_at = ? "
    "WHERE id = ? AND status = 'running'",
    (status, error_code, now, run_id),
)
self._conn.commit()
if cursor.rowcount != 1:
    raise RuntimeError(f"run 不存在或已经结束: {run_id}")
```

1. **`WHERE status = 'running'` 是幂等保护**：两个并发结束回调不能把同一 run 都更新成终态；第二个会 `rowcount=0` 抛错。
2. `finish` 只接受 `completed/failed/cancelled` 三种终态，非法值直接 `ValueError`。
3. `complete` / `cancel` / `fail` 是对 `finish` 的薄封装，调用点只表达意图。

### `RunService.execute`（run_service.py）

- **错误类别而非异常原文**：`error_code = type(exc).__name__`，避免把可能含敏感请求内容的 `str(exc)` 原样存库。
- **`KeyboardInterrupt` 单独捕获**：先 `cancel` 形成明确终态，再 `re-raise` 交还入口（CLI 才能正确退出）。
- 返回 `RunResult(run_id, status, answer, error_code)`：入口层只读这个结果，不关心 Agent 内部。

### 取消边界（本节最重要的认知）

```text
标记 cancelled（当前实现）  ≠  真正取消（目标行为）
  ├─ 当前：Ctrl+C → 数据库状态置 cancelled
  └─ 目标：cancellation token 穿透 Agent → 模型请求/工具/子代理/后台进程真正停止
```

当前实现是同步最小版，且**消息和 run 不是同一个事务**：`user` 消息已写入时若 Agent 异常，会留下"有 user 无 assistant"的半轮数据。

## 跟着做与验收

验证 completed、failed、cancelled 各一条 run；尝试重复终态写入必须失败。然后实现可传播 cancellation token，证明耗时调用确实停止，并验证断连、重复请求、进程退出和资源释放。只看数据库 status 不算取消验收。
