# 第 2 章 · 第 1 节｜配置契约和配置加载

## 本节业务问题

模型选择不是散落在 CLI 里的字符串分支。先把 YAML 和环境变量转成有类型、有校验的配置对象，再交给模型工厂。这样错误会在调用模型前出现，也不会把密钥写入代码。

## 涉及文件

| 文件 | 职责 |
|---|---|
| `config/model_config.py` | 定义配置契约 `ChatModelConfig`（frozen dataclass） |
| `config/loader.py` | YAML 读取、`${ENV}` 展开、字段校验的单一入口 |
| `backend/config.yaml` | 默认配置：`fake` provider，学习阶段不需要网络/密钥 |

## 调用流程

```text
backend/config.yaml（或 --config 指定路径）
  ▼
load_chat_model_config(path)          # loader.py 唯一公开入口
  ▼
yaml.safe_load → raw                  # 只做解析，不信任任何字段类型
  ▼
chat = raw["models"]["chat"]          # 取 chat 段；缺失 → ValueError
  ▼
_expand_env(chat)                     # 递归展开独占字段 ${NAME}
  │                                    # 环境变量缺失 → 只报变量名，不泄露值
  ▼
ChatModelConfig(**chat)               # frozen dataclass：多余/缺失字段在此暴露
  ▼
校验链：provider 非空 → model 非空
       → openai-compatible 必须有 api_key
       → temperature ∈ [0, 2]
  ▼
返回不可变 ChatModelConfig
```

## 关键函数与知识点

### `ChatModelConfig`（model_config.py）

```python
@dataclass(frozen=True)
class ChatModelConfig:
    provider: str        # 工厂选择 adapter 的键：fake / openai-compatible
    model: str           # 供应商定义的模型名
    base_url: str = ""   # OpenAI 兼容地址；官方默认可留空
    api_key: str = ""    # 运行时才有值；配置文件写 ${ENV} 占位符
    temperature: float = 0.2
```

- `frozen=True`：装配后不可被某个请求悄悄改写，配置来源单一。
- `api_key` 是敏感字段：日志只允许记录 provider/model，禁止打印整个 config 对象。

### `load_chat_model_config`（loader.py）

- 校验顺序固定：文件存在 → 顶层是对象 → `models.chat` 是对象 → 构造 dataclass → 字段业务校验。每一步失败都在调用模型**之前**给出可解释错误。
- `_ENV_PATTERN = r"^\$\{([A-Z0-9_]+)\}$"`：只匹配**独占整个字段**的 `${NAME}`，`abc${X}` 这类拼接文本不展开，避免误改写。
- `_expand_env` 递归处理 dict/list/str；`os.environ.get(name)` 为空直接 `raise ValueError(f"缺少必需的环境变量: {name}")`，错误里只有变量名、没有秘密值。

## 本节验收

给出一份配置字段表；成功配置产生类型化对象；缺文件、缺字段、缺环境变量、越界温度分别产生可解释错误。不能以"YAML 能解析"作为本节通过条件。
