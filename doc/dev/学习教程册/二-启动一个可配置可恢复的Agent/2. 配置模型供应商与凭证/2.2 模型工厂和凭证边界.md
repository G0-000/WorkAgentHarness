# 第 2 章 · 第 2 节｜模型工厂和凭证边界

## 本节业务问题

Agent 只需要统一的 chat model 接口，不应知道请求最终发给哪家供应商。工厂负责从配置选择模型实现；凭证由配置层注入，调用日志不能打印密钥。

## 涉及文件

| 文件 | 职责 |
|---|---|
| `models/factory.py` | `create_chat_model` 工厂 + `FakeChatModel` 离线实现 |
| `models/resolver.py` | 模型/provider 解析：运行时覆盖 > 环境变量 > 配置默认 |
| `models/credential_loader.py` | 凭证加载、密钥脱敏、异常脱敏 |

## 调用流程

```text
create_chat_model(config, runtime_model=None, runtime_provider=None)
  ▼
resolve_effective_config(config)      # resolver.py：合并运行时覆盖
  │                                    #   provider: 覆盖 > $WORKAGENT_MODEL_PROVIDER > config.provider
  │                                    #   model:    覆盖 > $WORKAGENT_MODEL_NAME > config.model
  ▼
按 effective.provider 分支
  ├─ "fake"
  │   └─► FakeChatModel()              # 离线、确定性，不访问网络
  │
  ├─ "openai-compatible"
  │   └─► ChatOpenAI(
  │          model=effective.model,
  │          base_url=effective.base_url or None,
  │          api_key=resolve_api_key(effective),   # credential_loader.py
  │          temperature=effective.temperature,
  │          timeout=30, max_retries=0)
  │        │
  │        ▼ 构造异常
  │        → ValueError(sanitize_error(str(exc)))  # sk-… → [REDACTED]
  │
  └─ 其他 → ValueError("不支持的模型 provider: …")
```

## 关键函数与知识点

### `FakeChatModel._generate`（factory.py）

```text
输入 messages
  ▼
过滤出所有 human 消息（user_messages）
  ▼
latest = user_messages[-1].content     # 最后一条用户输入
  ▼
返回 f"已收到（第 {len(user_messages)} 轮）：{latest}"
```

- 轮数来自**当前传给模型的消息历史长度**——同一 thread 恢复时历史变长、轮数递增，正好用来观察 checkpoint 是否生效。
- `_llm_type` 返回 `workagentharness-fake`，满足 LangChain `BaseChatModel` 子类标识要求。

### `resolve_effective_config`（resolver.py）

- 三个函数：`resolve_provider` / `resolve_model_name` / `resolve_effective_config`。
- 优先级阶梯：**运行时参数 > 环境变量 > 配置默认**，对应 EvoFlow resolver 阶梯前两级。
- 返回**新的** `ChatModelConfig`（frozen 不可变），不改原配置对象；factory 只消费这一个结果。

### `credential_loader.py` 三件套

| 函数 | 行为 |
|---|---|
| `resolve_api_key(config)` | 环境变量 `WORKAGENT_MODEL_API_KEY` 优先，其次 `config.api_key`（已由 loader 展开） |
| `mask_api_key(key)` | 前 4 位 + `****` + 后 4 位；长度 ≤ 8 全 `*` |
| `sanitize_error(message)` | 用 `sk-[A-Za-z0-9_-]{8,}` 正则把疑似密钥替换为 `[REDACTED]` |

- 密钥来源唯一约定：配置文件写 `${WORKAGENT_MODEL_API_KEY}`，loader 展开；**禁止字面量密钥进 YAML**。
- 真实 provider 构造失败时，异常消息先脱敏再抛，密钥不会进终端/日志。

## 跟着做

1. 先以 `fake` 从 CLI 发起请求，记录答案格式和模型没有联网的证据。
2. 把未知 provider 传给工厂，确认失败位置和错误类别。
3. 给 `create_chat_model` 传 `runtime_model="其他模型"`，确认覆盖配置默认；再设 `WORKAGENT_MODEL_NAME` 环境变量观察优先级。
4. 读 EvoFlow `models/resolver.py`、`models/credential_loader.py`、`models/factory.py`，逐项记录 WorkAgentHarness 还缺哪些模型解析与供应商行为。
5. 真实 provider 只能在本机设置环境变量后验证；不要把密钥放进 YAML、终端记录或学习笔记。
