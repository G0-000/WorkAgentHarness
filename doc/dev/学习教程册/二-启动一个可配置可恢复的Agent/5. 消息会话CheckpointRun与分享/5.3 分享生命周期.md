## 场景

你写了篇博客，想发给朋友看，但不想公开。你生成一个"私密链接"发给朋友，朋友不用登录就能看。过了一周你觉得不合适，随时把这个链接作废。

这一节做的事一样：把你和 Agent 的对话生成一个临时 token，别人拿着 token 就能看你的对话记录。token 有过期时间、能撤销、能控制看哪些内容。**本篇先不做这个功能，只讲清楚它要解决什么问题。**

## 这一节要实现什么功能（目标，当前未实现）

给已完成的会话生成一条只读分享链接，能撤销、能设过期；被分享者只读消息，不能继续对话。

**可验收的行为（目标）**：创建分享 → 用 token 读到只读消息 → 撤销后同一 token 返回 410；过期时间到后同样拒绝。

**当前状态**：无 `shares` 表、无 repository、无路由，本节只定义行为与验收。

## 本节业务问题

分享不是把 session id 暴露出去。要定义谁可以创建、谁可以访问、token 是否可撤销/过期、分享页面能看到哪些消息，以及源会话删除后的行为。

## 目标调用流程（对齐 EvoFlow 后的理想形态）

```text
创建者发起分享
  ▼
生成随机 token → 哈希后落库（不存明文）
  ▼
记录 owner_id、过期时间、允许访问的消息范围
  ▼
访客带 token 访问分享页
  ▼
校验链：token 存在 → 未过期 → 未撤销 → 在允许范围内
  ▼
返回只读会话视图（不含创建者私有字段）
  ▼
撤销 / 过期 / 删除源 session → 分享失效
```

## 知识点清单

1. **token 设计**：必须高熵随机（不可猜测）；数据库只存哈希，泄露库也不能直接拿 token 冒充。
2. **访问范围**：分享页能看到哪些消息由范围字段决定，不是整个 session 对所有人可见。
3. **生命周期**：过期时间、撤销标记、删除源 session 的级联失效，三个状态要能独立生效且可并发处理。
4. **越权检查**：owner 才能创建/撤销；访客只有 token 且有效才可读。
5. **与 checkpoint/业务消息的关系**：分享读的是**业务消息表**，不是 LangGraph checkpoint 内部状态。
