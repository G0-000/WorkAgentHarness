## 跟着写代码：先让配置变成模型

下面的代码是本章从零建立核心层时的第一版，建议分别保存为 `config/model_config.py`、`config/loader.py` 和 `models/factory.py`。第一步只支持 `fake` 与一个 OpenAI 兼容入口；读懂以后再添加模型参数和供应商差异。

### 1. 定义配置类型：`config/model_config.py`

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class ChatModelConfig:
    """描述如何连接一个对话模型；不负责创建模型，也不打印密钥。"""

    provider: str                 # 工厂选择 adapter 的键，例如 fake/openai-compatible
    model: str                    # 供应商定义的模型名
    base_url: str = ""            # OpenAI 兼容服务地址；官方默认地址可留空
    api_key: str = ""             # 只在运行时保存；配置文件里应写环境变量占位符
    temperature: float = 0.2      # 采样温度；L1 使用固定值便于复现
```

`frozen=True` 让配置加载后不可被某个请求悄悄改写。这里暂不使用 EvoFlow 所有模型字段；新增字段时必须同步配置解析、示例文件和模型工厂。

### 2. 读取 YAML 并展开环境变量：`config/loader.py`

```python
import os
import re
from pathlib import Path

import yaml

from workagentharness.config.model_config import ChatModelConfig

ENV_PATTERN = re.compile(r"^\$\{([A-Z0-9_]+)\}$")


def _expand_env(value: object) -> object:
    """递归展开独占一个字段的 ${ENV_NAME}，不把其他字符串误改写。"""
    if isinstance(value, dict):
        return {key: _expand_env(item) for key, item in value.items()}
    if isinstance(value, list):
        return [_expand_env(item) for item in value]
    if isinstance(value, str):
        match = ENV_PATTERN.fullmatch(value)
        if match:
            name = match.group(1)
            secret = os.environ.get(name)
            if not secret:
                raise ValueError(f"缺少必需的环境变量: {name}")
            return secret
    return value


def load_chat_model_config(path: str | Path) -> ChatModelConfig:
    """把 YAML 的 chat 段验证成类型化配置。"""
    raw = yaml.safe_load(Path(path).read_text(encoding="utf-8")) or {}
    chat = _expand_env(raw.get("models", {}).get("chat", {}))
    if not isinstance(chat, dict):
        raise ValueError("models.chat 必须是对象")
    config = ChatModelConfig(**chat)  # 缺字段或多余字段会在这里暴露
    if not config.model.strip():
        raise ValueError("models.chat.model 不能为空")
    if config.provider == "openai-compatible" and not config.api_key:
        raise ValueError("openai-compatible provider 需要 api_key")
    return config
```

注意：日志里只允许记录 `provider`、`model` 和脱敏后的 endpoint；不要打印 `config` 全对象，因为它含 `api_key`。

配套 `config.yaml`：

```yaml
models:
  chat:
    provider: fake             # 第一轮先用 fake；接真实服务时再切换 provider
    model: tutorial-fake
    temperature: 0
    # provider 改成 openai-compatible 时取消下面两项，并设置环境变量：
    # base_url: https://api.example.com/v1
    # api_key: ${WORKAGENT_MODEL_API_KEY}
```

### 3. 把配置变成模型：`models/factory.py`

```python
from langchain_core.callbacks import CallbackManagerForLLMRun
from langchain_core.language_models import BaseChatModel
from langchain_core.messages import AIMessage, BaseMessage
from langchain_core.outputs import ChatGeneration, ChatResult
from langchain_openai import ChatOpenAI

from workagentharness.config.model_config import ChatModelConfig


class FakeChatModel(BaseChatModel):
    """确定性假模型；不联网，还能用轮数观察 checkpoint 恢复。"""

    # answer 之所以是 Pydantic 字段：LangChain 的 BaseChatModel 继承自 Pydantic 的 BaseModel。
    # 别和 ChatModelConfig 混淆——后者是 frozen dataclass，两者技术选型不同。
    answer: str = "已收到"

    @property
    def _llm_type(self) -> str:
        return "workagentharness-fake"  # LangChain 要求子类标识模型类型

    def _generate(
        self,
        messages: list[BaseMessage],
        stop: list[str] | None = None,
        run_manager: CallbackManagerForLLMRun | None = None,
        **kwargs: object,
    ) -> ChatResult:
        """返回确定性 AIMessage；这里只演示"回显"分支，另两种行为见 2.2。"""
        user_messages = [message for message in messages if message.type == "human"]
        # 轮数 = 本次传给模型的 human 消息条数；不是业务轮次，也不是 runs 表记录数
        response_text = f"{self.answer}（第 {len(user_messages)} 轮）：{user_messages[-1].content}"
        return ChatResult(
            generations=[ChatGeneration(message=AIMessage(content=response_text))]
        )


def create_chat_model(config: ChatModelConfig) -> BaseChatModel:
    """根据配置构造模型；调用方只依赖 BaseChatModel 抽象。"""
    if config.provider == "fake":
        return FakeChatModel()  # L1 不访问外网、不需要密钥
    if config.provider == "openai-compatible":
        return ChatOpenAI(
            model=config.model,
            base_url=config.base_url or None,
            api_key=config.api_key,
            temperature=config.temperature,
            timeout=30,           # 有限超时，避免请求永久挂起
            max_retries=0,         # L1 先让错误暴露；重试策略后续单独设计
        )
    raise ValueError(f"不支持的模型 provider: {config.provider}")
```

**读代码时停下来想一想：**配置加载器负责“读与校验”，工厂负责“选择与构造”，模型对象负责“调用供应商”。如果把这三件事写进一个 CLI 函数，之后加 API、MCP 或第二种 provider 时就会重复分支。

### 4. 第一条可观察调用

```python
config = load_chat_model_config("config.yaml")  # YAML → 类型化配置
model = create_chat_model(config)                # 配置 → fake 或真实模型
reply = model.invoke("请用一句话介绍你自己")       # 统一接口 → AIMessage
print(reply.content)                              # 输出结果；不要打印配置对象
```

### 配置层真实做到的校验（只有这些，不要多写）
`config/model_config.py` 是 `@dataclass(frozen=True)`，**不是 Pydantic**；dataclass 不做运行时类型校验，所以 `config/loader.py` 显式补了下面几关：

| 校验 | 报错 |
|---|---|
| `models.chat` 必须是对象 | `models.chat 必须是对象` |
| 构造失败（缺字段/多余字段） | `models.chat 配置字段无效: …` |
| `provider` / `model` 必须是字符串 | `models.chat.provider 必须是字符串` / `models.chat.model 必须是字符串` |
| `temperature` 必须是数字（布尔不算） | `models.chat.temperature 必须是数字` |
| `provider` / `model` 不能为空白 | `… 不能为空` |
| `openai-compatible` 必须有 `api_key` | `openai-compatible provider 需要 api_key` |
| `temperature` ∈ [0,2] | `models.chat.temperature 必须在 0 到 2 之间` |

**文档不承诺没做的校验**：不校验 `base_url` 合法性、不校验 provider 与 model 组合是否真实存在、不做密钥格式检查。
