# 第 4 章 · 第 2 节｜Checkpoint 与 Thread 恢复

## 本节业务问题

业务消息用于查询和展示；checkpoint 保存图状态，供相同 thread 继续执行。二者的写入者、格式和生命周期不同。

## 涉及文件

| 文件 | 职责 |
|---|---|
| `agents/checkpointer/provider.py` | SQLite 长连接 + LangGraph `SqliteSaver` |
| `agents/lead_agent/agent.py` | 把 checkpointer 注入图构造 |
| `execution/run_service.py` | 每次只提交新消息，但用稳定 `thread_id` 让图读已有状态 |

## 调用流程

```text
open_checkpointer(db_path)
  ▼
sqlite3.connect(db_path, check_same_thread=False)
  ▼
PRAGMA journal_mode=WAL                    # 与业务库同一文件、读写并发
  ▼
saver = SqliteSaver(conn)
  ▼
saver.setup()                              # 由 LangGraph 建它自己的 checkpoint 表
  ▼
make_lead_agent(model, checkpointer=saver) # agent.py 注入 saver
  ▼
agent.invoke(messages, {"configurable": {"thread_id": session_id}})
  ▼
（进程重启后）沿用同一 thread_id 再次 invoke
  ▼
LangGraph 从 checkpoint 恢复图状态 → 轮数递增
```

## 关键函数与知识点

### `open_checkpointer`（provider.py）

```python
def open_checkpointer(db_path: str) -> tuple[sqlite3.Connection, SqliteSaver]:
    Path(db_path).parent.mkdir(parents=True, exist_ok=True)
    conn = sqlite3.connect(db_path, check_same_thread=False)
    conn.execute("PRAGMA journal_mode=WAL")
    saver = SqliteSaver(conn)
    saver.setup()  # 由 saver 建立它自己管理的 checkpoint 表
    return conn, saver
```

1. **checkpoint 表和业务表共用同一个 SQLite 文件，但 schema 各自独立**：业务表由 `schema.py` 建，checkpoint 表由 `saver.setup()` 建，互不混写。
2. **连接由装配层持有并在进程退出时关闭**：`cli/main.py` 的 `finally` 里统一 `checkpoint_conn.close()`；不要在 Agent 构造函数里偷偷开连接。

### `thread_id` 就是 checkpoint 的恢复键

```python
config = {"configurable": {"thread_id": "local-demo"}}
first = agent.invoke({"messages": [("user", "我叫小林。")]}, config=config)
second = agent.invoke({"messages": [("user", "我叫什么？")]}, config=config)
# second 时 LangGraph 已恢复 first 的图状态
```

- 每次只提交**新**的用户消息；完整历史由 LangGraph 从 checkpoint 读回，业务消息表不负责喂历史。
- `RunService.execute` 用 `session_id` 同时作为 `thread_id`：一条会话 = 一个 thread = 一份 checkpoint。

### fake model 的验证价值

- `FakeChatModel` 按**收到的用户消息总数**回复（第 N 轮）。重启进程后沿用原 thread，若返回第 2 轮，说明 checkpoint 恢复的是"消息序列"而非只回显了最后一条。

## 跟着做与验收

发第一条消息，关闭进程，再用原 thread id 发第二条；确认 fake 返回的轮数递增，并检查业务消息表与 checkpoint 分工。再用新 thread id 验证隔离。只有真实重启并复用 SQLite 后仍恢复才算通过。
