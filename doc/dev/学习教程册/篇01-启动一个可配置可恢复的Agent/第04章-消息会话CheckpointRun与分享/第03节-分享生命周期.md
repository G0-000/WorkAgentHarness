# 第 4 章 · 第 3 节｜分享生命周期

## 本节业务问题

分享不是把 session id 暴露出去。要定义谁可以创建、谁可以访问、token 是否可撤销/过期、分享页面能看到哪些消息，以及源会话删除后的行为。

## EvoFlow 证据入口

- Gateway：`backend/app/gateway/routers/share.py`
- 核心持久化：`backend/packages/harness/evoflow/persistence/chat_share_repositories.py`
- 与 session 权限、删除策略相关的调用链还要从 `chat_sessions.py` 和 repository 向两端追踪。

## WorkAgentHarness 当前状态

本篇当前代码没有 share 表、token、repository 或 API。因此本节只建立行为范围和验收任务，不提供虚构的“可运行分享代码”。

## 分步实现与验收

1. 先写只读分享用例：创建 token → 未授权访客读取允许范围内的会话视图。
2. 增加 token 随机性、哈希存储、过期时间、撤销和 owner 检查。
3. 定义删除源 session 后分享的失效行为，并处理并发撤销/读取。
4. 通过真实入口验证有效 token、无效 token、过期 token、撤销 token、越权访问和删除后访问。

只有对照 EvoFlow 的实际行为逐项完成，`WAH-RUN-010` 才能关闭。
