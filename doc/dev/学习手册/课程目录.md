# WorkAgentHarness × EvoFlow 全功能学习课程

> **本课程按产品功能组织，不照搬 M0–M8。** EvoFlow 是第二遍学习的源码教材；AgentFlow 是第一遍实现的复盘样本；WorkAgentHarness 是这次逐章学习、实验和重新实现的项目。学习顺序从单轮对话开始，逐步扩展到长任务、集成、治理和完整产品。
>
> 这份目录回答“先学什么、每章怎么读、怎么仿写、做到什么算通过”。逐项能力和边界以[功能单元路线](功能单元路线.md)为准，实际状态和证据只写在[功能清单](功能清单.md)。EvoFlow 快照、源码范围及容易漏掉的内部/产品域见[功能全景盘点](EvoFlow功能全景盘点.md)。

> 当前首轮行为清单登记 **109 个稳定功能 ID**：均已分配到课程章节；源码查漏同时覆盖 EvoFlow 的 51 个核心包、73 个 Gateway 路由模块、渠道、Web/Desktop 与仓库级技能/发布面。遇到未映射的新入口或用户行为，必须增加 ID 并分配章节；109 是这份快照的当前清点数，不作为永远固定的功能上限。

## 这门课的三份材料

- **课程目录（本页）**：按篇和章说明学习次序、源码入口、练习与章节出口。
- **功能单元路线**：将 EvoFlow 行为拆为稳定功能 ID，规定每个 ID 从最小闭环到完整功能的实现和验收边界。
- **功能清单**：记录每个 ID 当前的源码证据、WorkAgentHarness 实现位置、验收结果、差异和状态；它是唯一状态表。

代码说明放在 [doc/code](../../code/README.md)，开发过程放在 [doc/dev](../README.md)，每章理解变化写入[学习记录](../学习记录/README.md)。AgentFlow 对照查[第一遍复盘](../../第一次学习复盘.md)。

## 每章固定学习法

每章都执行下面的顺序；章节表会给出本章特有的源码入口、实验和出口。

1. **先看产品行为**：从 EvoFlow 用户文档或界面确认谁在什么入口做什么、成功/失败时能看到什么。
2. **冻结三仓库基线**：记录 EvoFlow、AgentFlow、WorkAgentHarness commit；先核对本课程标注路径仍存在。
3. **追真实调用链**：入口/注册 → 参数与身份 → 核心实现 → 状态/数据库/外部服务 → 返回事件或界面；找到调用者、配置、迁移和相关测试。
4. **画现状图再动手**：图只标源码证据已证实的组件和数据流；找不到真实调用者的模块标“待追/内部”，不画成已接线能力。
5. **做 L1 最小闭环**：先用 fake 模型、fixture、内存库或本地服务跑通一条成功行为，并解释每一步状态变化。
6. **逐层完成 L2–L4**：接真实入口和持久化；逐项补齐功能路线中的变体；再验证错误、权限、并发、取消、恢复和平台边界等适用场景。
7. **和第一遍对照并收口**：复盘 AgentFlow 当时的实现/误判；用真实用户入口重跑；把命令、预期、实测、依赖真假、日期和 commit 写回唯一功能清单。

**章节通过条件**：本章涉及的功能 ID 没有未解释缺项；关键行为从真实入口通过；最小实验、完整性边界和对照结论可复现；代码说明、Archify 图、测试和记录对应同一快照。只完成 L1 不算学完本章。
