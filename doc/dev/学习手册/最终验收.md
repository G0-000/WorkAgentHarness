## 2. "适用功能"的判定

不是"EvoFlow 有的全做"，也不是"做不了的都排除"。每个功能域必须落到三档之一，并写理由：

| 档 | 判据 | 处理 |
|---|---|---|
| 适用·必须对齐 | 用户可观察行为（入口、成功/失败、状态、权限、恢复）能被本项目的规模复现 | 必须实现 + 通过验收 |
| 适用·裁剪对齐 | 行为可复现，但实现规模/依赖降级（如无独立 HTTP 服务、无多进程） | 实现等价行为；**裁剪点单列**并写清差异 |
| 适用·替身对齐 | **行为本身是仿写目标**，但当前拿不到真实外部条件（真实 API Key、IM 租户、桌面环境、云账号、第三方服务） | **用 fake / fixture / 本地替身验收该行为**，并逐条记录"真实服务未验证"的范围与原因。**这一档仍属于对齐范围，不算排除** |
| 不适用·有据排除 | 确认该能力**不属于本项目的仿写目标**（例如只服务 EvoFlow 自身商业分发、或与单机单用户形态根本冲突） | 才允许排除。必须写清四件事：缺什么、影响哪些行为、为什么它不是仿写目标、有无更弱但仍可做的替代 |

**"拿不到真实条件"≠"不适用"。** 只要行为是仿写目标，就必须用替身把它验掉；只有"这个行为本身就不是我们要复现的东西"才进第四档。

三个必须写明的区分：

| 写法 | 含义 | 允许出现在结论里吗 |
|---|---|---|
| `已验收（真实服务）` | 真跑了真实依赖 | 允许，须附真实调用输出 |
| `已验收（替身）` | 用 fake/本地替身跑通行为；真实依赖未接 | 允许，**必须同时写"真实服务未验证"** |
| `排除` | 判定不属仿写目标 | 允许，仅限第四档，且四条齐全 |

**伪排除禁令**：不许因为"要真 API Key""要装桌面环境""要开 IM 租户"就把功能写进排除。这类只能进第三档。

**判定依据必须可复核**：给出 EvoFlow 侧文件与符号、本项目侧文件与符号，两边都要能指到具体行。只写"没做"不算。

## 3. 四类核验（每项功能都要过）

| 类别 | 要证什么 | 反例（不算通过） |
|---|---|---|
| 真实入口 | 从用户实际触发的入口进得去（CLI / SSE / 工具调用 / 渠道），不是只在单元测试里调用 | 只有函数存在、只在脚本里 import 过一次 |
| 成功与失败边界 | 正常路径 + 至少一条失败路径（缺配置、越权、超时、限流、格式错） | 只跑 happy path |
| 状态与恢复 | 状态写到哪、重启后能否恢复、恢复的是哪一层（业务表/checkpoint/内存 buffer） | 把"内存 buffer 补发"当持久化恢复 |
| 权限与隔离 | 谁能触发、被拒绝时表现如何 | 默认放行且未验证拒绝 |

**"代码存在"≠"入口接线"≠"边界验收"**，三者必须分别有证据。

### 3.1 验收方法分类：理解验收 / 运行验收

这是**方法**分类，与上面四类核验是**维度**关系：同一功能可以既有理解验收（讲清调用链），又有运行验收（跑通入口），两者都过才算通过。

| 类型 | 适用对象 | 合格证据 | 不要求 | 不能替代什么 |
|---|---|---|---|---|
| **理解验收** | 源码阅读、架构边界、调用链、数据流 | 源码路径+符号（`文件:行`）、调用链图、书面说明、现场讲解 | 命令、运行输出 | 不能替代运行验收——读懂不等于行为一致 |
| **运行验收** | 代码行为、命令、持久化、协议、入口、集成 | 可执行命令或真实入口 + 预期 + 实测 + 依赖真假（真实服务 / fake / 替身） | — | 不能被「我读过代码」顶替 |

判定规则：

1. **每章在验收节首行声明类型**（教程册 60 章已逐章标注，见各章 `## 本章代码测试与验收` 下第一行）。
2. 第 1 章为**理解验收**（仓库结构与快照核对，允许附核对命令）；第 2–18 章为**运行验收**（其中第 2、7、13、18 章是篇级集成运行验收）；第 19–60 章为**理解验收**（本项目无对应实现代码），其「未来运行验收条件」只是登记，**不得写成已通过**。
3. 运行验收必须同时写"预期"和"实测"；依赖是真实服务、fake 还是替身必须注在结论里。只有真实入口跑通才可写 `已验收（真实）`。
4. **部分验收只能作中间态**：逐项写出已通过项（附证据位置）、未完成项（缺什么）、下一步；禁止用"部分通过""基本可用""差不多"当终态。
5. **排除规则**：只有确认「该能力不属于仿写目标」才能排除并写明缺什么/影响什么；外部账号、桌面环境、真实渠道不可用时，用 fake 或本地替身验收并注明"真实服务未验证"，**不得因此排除**。
6. 状态词只有七个：`未学习` / `未实现` / `未验收` / `已验收（真实）` / `已验收（替身）` / `部分验收（列明项）` / `已排除（附理由）`。同一章、同一 ID 只能取一个。

## 4.5 验收进度口径与当前证据

### 三级验收与分母

验收分三级，缺一级都不能算整体对齐：

| 级别 | 位置 | 验什么 | 不通过的表现 |
|---|---|---|---|
| 节级 | 每章末节 `## 本章代码测试与验收` | 本章已学内容：环境、命令、预期、实测、失败路径、未覆盖项 | 只有"怎么验"没有"实测" |
| 篇级 | 每篇末章 `第 N 章｜第 X 篇综合测试与验收` | 本篇真实入口串链、调用链与数据状态、至少一条失败路径 | 复制各章测试表当集成 |
| 课程级 | 第 60 章 | 跨篇端到端 + 全部适用功能有结论 | 用"章节读完"代替行为对齐 |

**"60/60"指 60 个正文章节**（第 1–60 章），不含各篇 README、不含章内拆分小节，不含附录。

| 口径 | 数值 | 说明 |
|---|---|---|
| 正文章节 | 60 | 每章末节固定为 `## 本章代码测试与验收`，逐章数 |
| 其中篇末验收章 | 12 | 第 2、7、13、18、23、27、33、38、43、47、54、59 章 |
| 篇 | 13 | 第 1 篇为导学，第 2–13 篇为实操/设计篇；第 13 篇即课程级验收 |
| 功能 ID | 129 | 只在[功能清单](功能清单.md)维护，章节是容器不是计量单位 |

章节数与 ID 数**不是同一把尺子**：一章可以覆盖多个 ID，一个 ID 也可能跨章引用。所以不能写"60 章 = 60 个功能"。

### 第 1 章为什么"不跑命令也能验收"

## 5. 通过条件（全项目）

1. 冻结 commit 与第 1 节一致，或已明确记录了新一轮快照；
2. 功能清单里**每一个** `适用·必须对齐`/`适用·裁剪对齐` 的 ID 都到 `已验收`，且带四类核验证据；
3. `适用·替身对齐` 的每一项都写明替身方式与"真实服务未验证"的具体范围；
4. `不适用·有据排除` 的每一项都有"缺什么/影响什么/为什么不属仿写目标/弱替代"四条；
5. 第 1 批旅程全部实跑通过，第 2 批按已实现范围实跑；
6. 没有"入口未接线却标已验收"的项，也没有"用替身验过就写成真实验过"的项。

任一条不满足，结论就是**未完成**，不得用"教程读完""章节齐全""代码都在"替代。
