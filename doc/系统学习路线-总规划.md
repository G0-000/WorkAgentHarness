## 0. 怎么使用本规划

### 0.1 这门学习的目标

完成主线后，学习者应能：

1. 从入口追踪用户输入经过配置、模型、Agent、工具、状态存储，到输出的完整路径。
2. 解释 EvoFlow 的关键设计取舍，参考 AgentFlow 第一次学习的得失，并在 WorkAgentHarness 做出从基础到完整覆盖的对应实现。
3. 区分“代码存在”“单元契约通过”“真实入口已集成”“用户场景验收通过”。
4. 识别 EvoFlow、AgentFlow 第一版与 WorkAgentHarness 的差异、简化项和安全边界，不把仿写版的局部实现误认为原版行为。

**最终目标是复刻本规划固定快照中所有适用的一方功能，而不是停在残缺的最小版。** M0–M8 每章都要从最小闭环逐级扩展到本章范围内的完整功能与行为覆盖。供应商私有服务、无法取得的凭据、纯生成产物、第三方依赖内部实现和受许可证约束的资源不照搬；要记录替代实现或排除理由。功能等价不要求目录、代码行或实现方式相同。

### 0.2 每章的递进阶段与完成定义

每个 M 章节都按以下阶段推进；前一阶段通过后继续本章，不把“最小闭环”标为章节完成：

| 阶段       | 目标                                   | 必须留下的证据                      |
| -------- | ------------------------------------ | ---------------------------- |
| A. 盘点与理解 | 从 EvoFlow 实际入口、调用者、配置、状态和测试建立本章功能清单  | 带快照路径的功能清单与现状图               |
| B. 最小闭环  | WorkAgentHarness 实现最小可运行的主成功路径              | 可重复运行的单元/集成验收                |
| C. 功能补齐  | 对照清单补齐本章一方功能、主要配置和用户入口               | 每项标记完成、明确排除或有理由的差异；对应代码与文档路径 |
| D. 深度与边界 | 补齐失败、权限、持久化、并发、取消、重试、幂等、兼容和迁移等适用行为   | 按风险设计的失败/安全/并发/迁移验收          |
| E. 集成与讲解 | 从真实 CLI、HTTP、IM、Web 或后台入口验证，并能讲清源码映射 | 端到端记录、代码讲解、现状图和差异表           |

章节状态统一使用“未开始 / 盘点中 / 最小闭环 / 功能补齐中 / 边界补齐中 / 集成验收中 / 完整对齐 / 有证据的排除”。只有功能清单逐项闭合、适用验收通过、文档与实现一致时，才能标为“完整对齐”。缺项必须保持未完成并列出阻塞原因，不得用“选学”“以后再看”隐藏范围。

#### A–E 与手册 L1–L4 的对应关系

本规划的 A–E 是每章必须经过的**过程检查点**；手册的 L1–L4 是每项功能从简单到完整的**学习成熟度**，两者映射如下：

| 本规划检查点   | 手册阶段                     | 说明                                |
| -------- | ------------------------ | --------------------------------- |
| A. 盘点与理解 | L1 之前完成，并在后续发现新调用关系时持续更新 | 建立本章功能项、源码证据和现状图                  |
| B. 最小闭环  | L1 入门闭环                  | 用最少依赖验证主成功路径                      |
| C. 功能补齐  | L2 基础能力 + L3 完整功能        | 先补真实入口和基础契约，再覆盖功能矩阵中的全部适用能力       |
| D. 深度与边界 | L4 高级边界                  | 验证适用的失败、安全、并发、恢复、迁移和兼容行为          |
| E. 集成与讲解 | 各 L 阶段的局部验证 + L4 后的章节出口  | L4 后从真实入口完成端到端验收和源码讲解；系统级收口见手册 09 |

因此，L3 结束不代表章节通过；还须完成 L4 和 E 阶段出口。

#### 核心术语

| 术语           | 定义                                                     |
| ------------ | ------------------------------------------------------ |
| EvoFlow 一方能力 | 固定快照中由 EvoFlow 项目自身实现、维护和装配的能力；不含第三方库内部功能、私有供应商服务或生成产物 |
| 用户可见行为       | 用户或集成方通过 CLI/API/渠道/UI/后台任务可观察的输入、输出、状态变化、权限结果和错误      |
| 真实入口集成       | 从正常产品入口经过实际装配、权限和核心调用到达目标功能；单测或直接调用内部函数不算              |
| 功能覆盖         | 矩阵中的适用能力有实现映射或有据可查的排除理由，回答“要实现哪些能力”                    |
| 行为等价         | 对相同输入和状态，在成功、错误、权限、持久化等适用场景得到可接受的一致结果；实现方式可不同          |
| 功能等价复刻       | 固定快照中适用的一方能力完成覆盖，且关键行为边界已验证，不要求逐文件或逐行相同                |
| 完整对齐         | 本章功能矩阵逐项闭合，适用边界与真实入口通过，代码/图/文档对应同一快照                   |

### 0.3 每个功能单元的学习闭环

1. **定问题**：它解决什么问题，输入/输出是什么，属于哪个层？
2. **追原版**：先找实际入口、状态/数据结构、调用者和测试；只挑必要文件精读。
3. **复盘 AgentFlow**：对照第一次实现，识别学对、简化和遗漏之处；再为 WorkAgentHarness 设计本章实现路径。
4. **做最小实验**：改一个小行为或独立实现，不先复制大模块。
5. **验证并讲解**：运行适配的测试或手工流程，写出从输入到结果的因果链。
6. **更新文档**：修正路径、命令、状态、图及证据日期。

每次精读可先控制在 3–7 个核心文件，但章节清单必须覆盖该域所有适用功能；通过入口追踪、分组阅读和测试映射逐步完成盘点，不要求逐行通读每个文件，也不能因文件多而缩小功能范围。

### 0.4 状态标记（全项目统一）

| 标记   | 定义                       | 必须附的证据                          |
| ---- | ------------------------ | ------------------------------- |
| 未开始  | 尚未系统学习或 WorkAgentHarness 尚无对应实现 | 标注原版阅读入口和下一步                    |
| 已读懂  | 能讲清职责、调用路径和设计差异          | 代码路径/测试路径 + 学习笔记                |
| 已实现  | WorkAgentHarness 有对应代码，但不代表已集成  | 实现路径 + 边界                       |
| 单测通过 | 被测模块的契约通过                | 精确命令、通过数、日期                     |
| 集成通过 | 多模块从真实应用入口跑通             | 入口、依赖条件、验收记录                    |
| 有意简化 | 与 EvoFlow 不同且是教学决策       | 差异、理由、后续是否计划补齐                  |
| 完整对齐 | 本章清单的所有适用项均完成并通过验证       | EvoFlow→WorkAgentHarness 映射，并记录 AgentFlow 第一版对照、验收记录、排除项理由 |

避免只写“✅ 已对齐”。一个模块可以是“已实现、单测通过、尚未集成”。

## 1. 当前代码地图与学习边界

### 1.1 EvoFlow 的分层

```text
backend/app/                              应用层：Gateway、HTTP/SSE、IM 渠道、进程装配
       │ 允许依赖核心层
       ▼
backend/packages/harness/evoflow/         核心层：Agent、工具、记忆、知识、持久化等
       │ 不应反向 import app.*（规则 R1）
       └── 反向能力通过核心定义的 runtime port，由 app 注册 adapter

evopanel/                                 前端控制面板（网页及桌面相关代码）
```

## 2. 主学习路线：M0–M8

主线遵循真实依赖：环境与入口 → Agent 闭环 → 工具和中间件 → 上下文/记忆/知识 → 委派与执行边界 → 长任务 → 扩展治理 → 应用 Gateway/渠道 → 前端。每章按 §0.2 的阶段从小到全推进。M0 负责盘点；M1–M8 负责各域的全量适用覆盖；§5.3 负责跨域收口与最终完整度审查。

### M0 — 环境与代码地图

> 分章教程：[M0 环境、架构与源码地图](/Users/main/WorkAgentHarness/doc/系统学习手册/M0-环境架构源码地图.md)

**目标**：能在 WorkAgentHarness 运行后端、测试和前端检查，知道核心包、应用层、数据目录分别在哪里。

- **先读 EvoFlow**：根 README、`backend/README.md`、`backend/ARCHITECTURE.md`、`backend/pyproject.toml`、`backend/langgraph.json`；索引不可用时按 §1.3 处理。
- **再看 AgentFlow**：根/后端 `pyproject.toml`、workspace、`langgraph.json`、配置样例、`backend/app/` 和 `backend/packages/harness/agentflow/`。
- **练习**：解释两个包如何安装；指出 CLI、Gateway、LangGraph Server（如适用）各自入口；运行 lint、测试和前端检查。
- **出口条件**：能画出 EvoFlow 与 AgentFlow 第一版的实际目录/入口图，并说明 WorkAgentHarness 的新结构决策和待建部分。
- **完整性要求**：建立并维护 §5.1 所述的全量功能清单，覆盖核心包、应用入口、前端/桌面、后台任务、配置、持久化及运行维护能力；本章的交付是完整地图，不是实现所有代码。
- **常见误区**：不要把 EvoFlow 的全部端口/路由数/页面数当作 M0 要背的内容。

### M1 — 最小 Agent 闭环：配置、模型、状态、持久化

> 分章教程：[M1 Agent、模型、状态与持久化](/Users/main/WorkAgentHarness/doc/系统学习手册/M1-Agent模型状态持久化.md)

**目标**：从配置创建模型，构建最小 Agent，接收一条消息，保留会话状态并能恢复。

- **阅读顺序**：config → models factory/resolver → `agents/thread_state.py` → lead Agent 工厂 → checkpointer → persistence 的 session repo → CLI/图入口。
- **EvoFlow 参考**：`evoflow/config/`、`evoflow/models/`、`evoflow/agents/thread_state.py`、`evoflow/agents/lead_agent/agent.py`、`evoflow/agents/checkpointer/`、`evoflow/persistence/`。
- **AgentFlow 第一版复盘**：`agentflow/config/`、`agentflow/models/`、`agentflow/agents/lead_agent/`、`agentflow/agents/checkpointer/`、`agentflow/persistence/`、`agentflow/cli/`。
- **练习**：用 fake model 跑一轮；同一 thread 再发一轮；重启后检查 checkpoint 与业务会话记录各自保存了什么。
- **出口条件**：能解释“业务会话消息”和“LangGraph checkpoint”不是同一份职责，能定位配置/模型/图/数据库任一环节失败的原因。
- **功能补齐范围**：覆盖快照中的模型 provider/resolver/fallback、配置与密钥边界、Agent 入口和状态 schema、会话/线程生命周期、checkpoint 后端与恢复/清理行为；每个 provider 都映射到对应驱动或有证据的替代/排除，不以一个 fake model 代表本章完成。

### M2 — 工具、中间件与流式输出

> 分章教程：[M2 工具、中间件与流式事件](/Users/main/WorkAgentHarness/doc/系统学习手册/M2-工具中间件流式事件.md)

**目标**：理解模型如何选择工具、工具结果如何返回、横切行为如何进入 Agent，以及 CLI 的流式事件如何解析。

- **阅读顺序**：工具 schema → catalog/分组 → 1–2 个 builtin → result store → middleware 注册与顺序 → Agent `.stream()` 消费者。
- **EvoFlow 参考**：`tools/tool_catalog.py`、工具装配模块、`tools/builtins/`、`tool_result_store.py`、`agents/middlewares/`、Agent 工厂。
- **AgentFlow 第一版复盘**：`agentflow/tools/`、`agentflow/agents/middlewares/`、`agentflow/cli/repl.py`。
- **练习**：新增一个无外部副作用的小工具和一个轻量中间件；测试多事件流与嵌套消息解析。
- **功能补齐范围**：清点本快照所有一方工具类别、catalog/分组与权限、参数校验、执行结果/错误、结果存储、middleware 注册顺序和适用流事件；按类别实现和验收，不需要逐行重写工具，也不能只实现代表工具就标完整。
- **出口条件**：能从“模型工具调用”追到工具执行和工具消息回到模型；能分辨 CLI 流式与 Gateway SSE 的不同层次。
- **学习方法**：可以先挑代表 builtin 验证主闭环，但随后必须将全部一方 builtin 和扩展工具逐项盘点、分组实现、说明外部依赖并验收；代表样例只用于入门，不构成本章完成标准。

### M3 — 会话上下文、记忆与知识

> 分章教程：[M3 上下文、记忆、知识与索引](/Users/main/WorkAgentHarness/doc/系统学习手册/M3-上下文记忆知识索引.md)

**目标**：区分短期会话状态、长期用户记忆和文档知识库，理解各自何时写入、何时检索、如何注入 prompt。

- **阅读顺序**：ThreadState/context → session middleware → memory facade/consolidation → knowledge chunker → embedding interface → retrieval/ranking → prompt injection。
- **EvoFlow 参考**：`agents/middlewares/` 中上下文和记忆相关模块、`memory/`、`knowledge/`、`agents/memory_plugins/`。
- **AgentFlow 第一版复盘**：`agentflow/memory/`、`agentflow/knowledge/`、对应 repositories 与中间件。
- **练习**：一条记忆写入并在后续会话召回；一篇文档切块、向量化、检索并将来源呈现给模型。
- **出口条件**：能解释记忆与知识的生命周期/权限/删除边界，并指出当前简单向量检索的规模限制。
- **扩展覆盖**：基础检索通过后，继续盘点和实现本快照中适用的 owned knowledge、vault、code index、权限、删除、索引更新和恢复能力；逐项映射到本章清单，不作为永久选学项。
- **完整性要求**：对所有记忆/知识来源、存储后端、索引/检索策略、生命周期钩子和用户/组织隔离逐项建立对应关系；无法提供原外部服务时，使用可重复的本地兼容实现并标注差异。

### M4 — 子代理、工具权限与沙箱

> 分章教程：[M4 子代理、执行安全与隔离](/Users/main/WorkAgentHarness/doc/系统学习手册/M4-子代理执行安全与隔离.md)

**目标**：理解任务委派、并发和结果汇总，以及执行文件/命令时的安全边界。

- **阅读顺序**：subagent schema/registry → executor → 并发控制与失败重试 → workspace/path guard → audit → EvoFlow `execution_security/` 与审批流程。
- **EvoFlow 参考**：`subagents/`、`sandbox/`、`execution_security/`、委派相关 tools/middleware。
- **AgentFlow 第一版复盘**：`agentflow/subagents/`、`agentflow/sandbox/`、对应测试和审计存储。
- **练习**：至少四个 fake 子任务并行，以证明配置的并发上限确实生效；再覆盖失败/取消/重试；对越界路径/命令拒绝并产生审计记录。
- **出口条件**：能说明“路径检查”不等同于操作系统级进程隔离；能指出当前学习版支持与不支持的命令边界。
- **完整性要求**：清点委派模式、并发/预算限制、任务结果聚合、隔离和审批策略、审计事件与故障处理；对依赖操作系统或容器的隔离能力说明适配级别，不能把 path guard 宣称为等价沙箱。

### M5 — 计划、长任务、恢复与调度

> 分章教程：[M5 计划、协作、长任务与自动化](/Users/main/WorkAgentHarness/doc/系统学习手册/M5-计划协作长任务自动化.md)

- **EvoFlow 参考**：`collab/`（包含任务计划存储、协作与生命周期）、`agents/goal/`、`scheduler/`（工具调度/执行器，不等于 cron）、`admin/automation_schedule.py`、`app/gateway/automation_runner.py`、`proactive/schedule.py` 等定时触发入口。根目录 `plans/` 是 Plan Bundle/第三方计划能力连接器，不是任务 DAG；阅读时按真实调用者和测试确认边界。

- **练习**：Fake model 创建两步计划；完成一步后模拟进程中断；重启后恢复并验证状态与消息一致性；单独验证一个定时任务。
- **出口条件**：能说清计划、goal、scheduler/cron、automation、proactive 的职责差异；测试覆盖恢复和重复执行风险。
- **覆盖要求**：把任务计划、目标状态、协作状态、恢复、重复执行防护、定时触发、无人值守自动化、作业生命周期逐项纳入清单；各项按快照实际能力映射到本章或相邻章节，不允许因为 AgentFlow 第一版暂缺而从完成定义删除。

### M7 — 应用层：Gateway、端口和 IM Channels

### 文档职责分层

## 6. 学习进度建议

### 阶段 A：理解主闭环（M0–M2）

环境、配置、模型、Agent 状态与 checkpoint；随后理解工具选择、中间件和 CLI stream。完成后应能独立解释和跑通最小 Agent。

### 阶段 B：让 Agent 有可持续能力（M3–M5）

分清记忆/知识，再学委派、安全边界、长任务恢复和调度。先掌握状态/持久化正确性，再扩展工具数量。

### 阶段 C：接触产品边界（M6–M8）

依次学习 MCP/治理、Gateway/IM、Web UI。强调认证真正在何处执行、流式是真流还是缓冲、渠道是否真正总线化、历史是否能恢复。

### 阶段 D：完整覆盖与跨域收口

逐项关闭全量功能清单中的缺口，包括此前归到 M8+ 的 code index、插件/组织、A2A、speech、v4、桌面端和生产运行能力。一次只实现一组有依赖关系的功能，完成相应边界、集成、测试和文档后再推进。所有适用项闭合并通过 §5.3 后，才算完成整条 EvoFlow 学习路线。
