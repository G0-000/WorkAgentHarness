# WorkAgentHarness × EvoFlow 功能式学习总规划

> 本仓库是第二次学习：EvoFlow 是源码教材，AgentFlow 是第一次学习的复盘样本，WorkAgentHarness 是边读、边实验、边重新实现的项目。课程按照实际功能组织，不沿用第一遍 M0–M8 作为本轮章节，也不把课程目录写死。

## 学习目标

从用户可观察的场景出发，追踪入口、领域逻辑、状态和存储，再回到结果；解释 EvoFlow 设计取舍与 AgentFlow 第一遍的得失；在 WorkAgentHarness 先做最小可运行实现，再补齐同一功能域适用的一方功能、入口、配置和边界。

完整学习不等于逐行抄源码或照搬目录，而是对快照中每项适用的一方能力建立证据、实现映射或有依据的排除理由，并验证关键用户行为。目录、文件数、代码存在本身都不是完成度。

## 功能式课程，而非固定章节编号

逐项学习范围和“最小闭环→完整对齐”出口维护在[功能单元路线](dev/学习手册/功能单元路线.md)，唯一活状态表在[功能清单](dev/学习手册/功能清单.md)。课程地图可增补。当前候选域包括对话运行时、工具和流事件、上下文与记忆、知识与代码索引、执行与委派、计划和协作、自动化与主动运行、扩展协议、Gateway 与渠道、治理观测、Web/桌面。它们是按当前源码的初始导航，不代表全量盘点完成。发现新用户行为就增补；边界不合理就拆分/合并并维护稳定 ID。

不要按目录机械分章。一项能力常跨 app、core、数据库、配置、前端和测试；按完整用户行为与验收边界组织。地图是导航，唯一活功能清单记录逐项状态，章节记录学习过程，最终验收只引用 ID。

## 每项功能从基础到完整

| 层次 | 学习活动 | 出口证据 |
|---|---|---|
| 认识问题 | 从场景理解输入、输出、参与组件和状态 | 场景、术语和概念图 |
| 追踪原版 | 从真实 CLI/API/渠道/UI 追调用者、核心逻辑、状态和返回 | 带路径、符号、测试的调用链 |
| 最小闭环 | fake 依赖或本地数据实现最短成功路径 | 可重复实验和明确简化 |
| 功能补齐 | 补真实接口、配置变体、错误、生命周期和产品入口 | 每项有实现映射或有证据的排除 |
| 验证边界 | 覆盖适用的权限、并发、取消、恢复、兼容和观测 | 验收结果及未验证条件 |
| 讲解交付 | 复述入口→逻辑→状态→结果并对比第一遍 | 学习记录、差异、矩阵和图 |

最小闭环是起点，不代表功能完成。已掌握的讲解可以跳过，但不可缩小功能范围或跳过验收。

## 源码盘点与功能清单

完整原子功能范围和每项阶段路线见[功能单元路线](dev/学习手册/功能单元路线.md)；唯一逐行为状态矩阵是[功能清单](dev/学习手册/功能清单.md)。交叉查看应用路由、渠道/CLI 注册、领域调用者、工具装配、配置 schema、数据库迁移、后台任务、Web/桌面路由、测试及面向用户文档。要找到谁调用、用户如何抵达、状态如何变化；孤立代码标记未接线/待核实，不虚构产品行为。

一个目录可包含多个能力，多个目录也可共同实现一个行为。只有生命周期、权限和验收相同才合并。每项记录 EvoFlow 路径/符号/入口/测试、实际行为、配置和依赖、AgentFlow 行为、WorkAgentHarness 路径/commit/状态、验收和差异。外部服务暂不可用时先考虑兼容实现，注明差异与未验证边界。

## 教程结构和状态

每个功能教程围绕七项展开：用户问题与先修概念；EvoFlow 图和实际调用链；关键代码、数据和错误；AgentFlow 第一遍复盘；最小实验及逐项补齐；验收矩阵；关闭出口和差异。功能边界变化时更新地图和链接，不为了守旧编号保留不合理内容。

状态为待盘点、已理解、最小闭环、功能补齐中、边界待验、已验收或有依据排除。每个状态附路径、命令/操作、结果、日期和 commit。代码存在、导入成功或单测通过不等于真实入口已集成。

## 图与全项目收口

先维护一张产品入口—应用层—核心能力—存储/前端全景图。具体学习某项能力时，再生成有源码依据的 Archify 图，放入该功能章节；图标明 commit、真实入口、事件/数据流和未实现部分。不要为尚未盘点的所有章节预先画空图。

全项目只有在适用功能 ID 闭合、真实入口完成验收、排除与差异可解释、实现和文档使用同一快照时才能称为完整。总结端到端场景、mock/真实服务边界、授权和未验证项。本轮路线不以 M0–M8 作为章节；第一次学习材料只用于差异复盘。当前应从任一具体用户场景进入功能单元路线，再逐项更新唯一活清单。起点记录见[学习记录](dev/学习记录/README.md)。
