# 00 — 总路线与学习方法

## 目标与边界

学习目标是在 WorkAgentHarness 中复刻 EvoFlow 当前固定版本内适用的一方功能和行为，不是逐行复制代码。EvoFlow 是事实来源，AgentFlow 是第一次学习结果，WorkAgentHarness 是本次实现目标。供应商私有服务、不可取得的凭据、第三方依赖内部实现、生成产物和受许可证约束资源不复制；提供替代方案并记为差异。不要因 AgentFlow 第一版删减某域而从重学范围删除。

## 先建立三份地图

1. **系统地图**：后端核心包、应用层、前端/桌面端、数据目录、服务进程和外部依赖。
2. **行为地图**：每个用户入口触发哪些模块、数据如何传递、在哪持久化、失败如何返回。
3. **差异地图**：EvoFlow 一方功能 → EvoFlow 入口/实现/测试 → AgentFlow 第一版路径和得失 → WorkAgentHarness 实现路径/状态 → 练习与验收。

每条功能记录要有唯一 ID、所属章节、优先依赖、EvoFlow 证据路径、AgentFlow 第一版路径/状态、WorkAgentHarness 路径/状态、配置、存储、入口、测试、风险和当前阶段。

## 每个功能的四级学习模板

总规划 §0.2 的 A–E 是**学习过程的检查点**，本手册的 L1–L4 是**功能逐步扩展的成熟度**，两者不是两套竞争的顺序。按下表对应：

| 总规划阶段 | 手册阶段 | 如何执行 |
|---|---|---|
| A. 盘点与理解 | L1 之前完成，并在后续发现新调用者时持续更新 | 建立该章功能条目、源码证据和现状图 |
| B. 最小闭环 | L1 入门闭环 | 假依赖跑通主成功路径 |
| C. 功能补齐 | L2 基础能力 + L3 完整功能 | 先补真实入口和基础契约，再按功能矩阵覆盖该域全部适用能力 |
| D. 深度与边界 | L4 高级边界 | 覆盖适用的失败、安全、并发、恢复、迁移和兼容行为 |
| E. 集成与讲解 | L1–L4 的阶段检查 + 每章最终出口 | 各级验证当前增量；L4 后从真实入口完成端到端讲解和证据归档。系统级总收口见 09 |

因此，L3 结束只表示完整功能主体已实现，不代表章节通过；还要完成 L4 和 E 阶段的章节验收。

### L1 入门闭环

画出最短成功路径；用 fake model、fake provider 或临时 SQLite；先完成一个可重复实验。讲明输入、输出、状态变化和副作用。

### L2 基础能力

替换真实配置与持久化；补齐正常错误处理、参数校验、默认值、日志和一个真实入口。练习从 CLI 或单个 API 触发，查看数据库/事件/结果。

### L3 完整功能

依照 EvoFlow 功能清单按类别覆盖所有一方能力，逐一核对配置选项、公开接口、存储对象、生命周期、工具/provider/页面入口及调用者。不是把同一目录逐行重写，而是证明每个用户行为在 WorkAgentHarness 有行为等价实现，或有理由的排除；AgentFlow 第一版只提供比较样本。

### L4 高级边界

根据该功能风险补充并发上限、隔离、权限、取消、超时、重试、幂等、恢复、删除、迁移、兼容、降级和可观测。涉及真实外部服务时提供 fake/local integration 测试并分开记录真实联调状态。

每一级都有对应的局部验证；**E 集成与讲解是 L4 之后单独执行的章节出口**，不能因为前几级做过局部集成检查而跳过。

## 核心术语

| 术语 | 本手册定义 |
|---|---|
| EvoFlow 一方能力 | 固定快照中由 EvoFlow 项目自身实现、维护和装配的功能；第三方库内部功能、私有供应商服务和生成产物不算一方实现 |
| 用户可见行为 | 用户或集成方通过 CLI/API/渠道/UI/后台任务可观察到的输入、输出、状态变化、权限结果和错误 |
| 真实入口集成 | 从正常产品入口经过真实装配、权限和核心调用到达目标功能；单测、import 成功或手工直接调用内部函数不算 |
| 功能覆盖 | 功能矩阵里的适用能力有实现映射或明确排除理由，回答“该做哪些事” |
| 行为等价 | 对相同输入和状态，在成功、错误、权限、持久化等适用场景得到可接受的一致结果；实现方式可以不同 |
| 功能等价复刻 | 固定快照内适用的一方功能完成覆盖，且关键行为边界经过验证；不要求逐文件或逐行相同 |
| 最小闭环 | 为学习某能力而搭建的最短成功路径，仅是 L1，不代表基础或完整功能已实现 |
| 完整对齐 | 本章功能矩阵逐项闭合，适用边界和真实入口通过，讲解/图/测试与同一源码快照一致 |

若使用“已实现”“完整对齐”等状态，必须附实现路径和验收证据；“有证据的排除”需附具体原因与替代方式。

## 源码阅读方法

1. 固定 commit，确认工作树和版本；读取该仓库开发说明。
2. 找入口和注册点，再沿调用链追数据、状态、错误和副作用。
3. 同时看实现、调用方、测试和配置；只读实现很容易把未接线 stub 当产品能力。
4. 记录精读文件的职责，不逐行扫巨大文件。对大型模块按路由/类/事件处理器拆分学习。
5. 先画“EvoFlow 和 AgentFlow 第一版现在确实发生什么”，再画“WorkAgentHarness 要达到什么”；不能用目标图代替运行证据。

EvoFlow 根说明提到 `.codebasewiki/index/` 与导航技能，但当前本地 checkout 缺少 `.codebasewiki/index/index.md` 和 `architecture.md`；M0 按 `backend/ARCHITECTURE.md`、`backend/CLAUDE.md`、入口、测试和调用点导航，并把缺失索引记为资料缺口。AgentFlow 第一版不是 EvoFlow 的事实来源。

## 章节顺序与跨章依赖

```text
M0 地图 → M1 Agent/模型/状态 → M2 工具/中间件
                       ├→ M3 记忆/知识/索引
                       ├→ M4 子代理/安全
                       └→ M5 长任务/自动化
M2–M5 → M6 扩展与治理 → M7 应用服务/渠道 → M8 Web/桌面
M0–M8 → 09 全量差异关闭与系统级验收
```

有些域会跨章节出现，但拆分责任，不重复造概念：MCP transport 在 M6，MCP tools 如何进 Agent 在 M2/M6 联合验收；Gateway 事件在 M7，前端呈现和恢复在 M8；scheduler 工具执行与 cron/automation 分开学习。

## 通过标准

章节状态只能是：未开始、盘点中、入门闭环、基础补齐中、完整功能补齐中、高级边界补齐中、集成验收中、完整对齐、有证据的排除。标为完整对齐前，本章清单没有未解释缺项；适用测试通过；代码、文档、架构图和快照一致。
