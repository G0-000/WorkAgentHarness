# M2 — 工具、中间件与流式事件

> 本章的实现目标是 WorkAgentHarness。文中出现的 AgentFlow 路径、状态和第一次学习记录均为历史对照；WorkAgentHarness 当前状态以本仓库和 02 全量功能矩阵为准。

## 本章目标

从模型发出 tool call 开始，追到工具 schema、权限过滤、执行、结果保存和工具结果回到模型；同时掌握 middleware 的插入次序和流式事件消费，最终按类别覆盖快照中的一方工具能力。

## 四级学习

### L1 入门闭环

实现一个纯函数 calculator/read-only 工具：schema → catalog → model tool call → executor → ToolMessage → 下一轮模型回答。用 fake model 检查 call/result 对应关系。

### L2 基础能力

补工具分组、可用性/allowlist、参数 schema 校验、异常转换、超时、结果摘要/大结果存储、middleware 注册顺序、CLI 事件迭代。明确工具执行的权限主体和副作用。

### L3 完整功能

根据 EvoFlow builtin、host_direct、zcode port 等真实分类建立清单，按用途覆盖文件、搜索/网页、命令执行、知识、计划/任务、交互澄清、浏览器、代码、图片/多媒体、子代理和管理类工具。核对工具可见性、参数、依赖、权限、返回格式、结果截断、UI tool call 展示及 MCP/插件注入路径。先用代表工具学会闭环，再逐类实现；不可只实现五个样例便标完整。

### L4 高级边界

验证工具异常、取消、超时、重试是否会重复副作用、并行调用、权限变更、恶意参数、超大结果、流中断、未知事件和不完整 SSE 帧。对有写入/命令执行能力的工具做安全测试和审计记录。

## 必须讲清的执行链

源码讲解按 `tools/tool_catalog.py` → `tools/tools.py`/tool assembly → 一个 `tools/builtins/` 工具 → `tools/tool_result_store.py` → `agents/middlewares/` → Agent factory → `cli/repl.py` 或 Gateway stream 逐层推进。用本地 checkout 核对每个路径/符号是否存在，解释参数 schema、授权、执行副作用、ToolMessage 和流事件；按工具类别扩展讲解，不复制超长 builtin 文件。

AgentFlow 第一版的 Archify 图（历史参考）：[M2 工具与中间件图](/Users/main/AgentFlow/doc/doc-dev/01-里程碑/diagrams/M2-tools-middleware-20261011-034339/M2.html)。它展示基础工具调用；全量 builtin/provider 覆盖完成后再扩展图。

```text
工具声明 → 可用工具筛选 → 模型选择工具 → 参数校验/授权
→ 执行器调用 → 副作用/结果存储 → ToolMessage → 模型续答
→ stream consumer 解析 token/tool/status/error/done 等事件
```

`CLI stream`、LangGraph stream、Gateway SSE 和前端 event parser 是不同层。任何一个层发生缓冲，都可能让用户看不到真实逐块输出。

## 动手练习与验收

1. 做纯函数工具、只读工具、有副作用工具三种最小实现，并比较授权/审计要求。
2. 注册 middleware 记录每次模型请求的 thread/tool 数量；验证顺序和异常传播。
3. 表驱动覆盖工具类别，断言 schema、权限、输出和执行路径；配置不可用时明确提示原因。
4. 模拟多段流、工具事件、异常和 EOF；验证 CLI、Gateway、前端的事件契约。
