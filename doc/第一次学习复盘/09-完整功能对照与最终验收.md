# 09 — 完整功能对照与最终验收

## 目的

本章是 M0–M8 全部阶段收口的强制验收，不是选学。它回答：从 EvoFlow 快照任意一项一方用户能力，能否找到 WorkAgentHarness 等价实现、入口、测试和解释文档，并解释 AgentFlow 第一版的差距？

## 和 M0 功能清单的关系

M0 在 WorkAgentHarness 建立并持续维护一份**唯一的逐功能活矩阵**，落在 [02-全量功能矩阵](02-全量功能矩阵.md)。矩阵并列记录 EvoFlow 证据、AgentFlow 第一版映射和 WorkAgentHarness 新实现。[01-功能域初始对照](01-功能域初始对照.md) 仅作域级导航和盘点起点，不作为逐功能状态或覆盖率来源。本章“必须关闭的全域清单”和最终验收关卡是矩阵的**覆盖检查/验收视图**，不另建第二份逐功能清单。每条功能用同一个 ID 在章节进度、测试证据和最终验收中互相引用；功能描述、路径映射和阶段状态只在 02 维护，09 只记录最终结论、证据与关闭日期。

## 最终关闭记录模板

本章不复制 02 的逐功能描述和路径映射。每项只引用既有功能 ID，写系统级验收结论与关闭证据：

| 功能 ID | 最终结论 | 系统级验收证据/限制 | 关闭日期与 WorkAgentHarness commit |
|---|---|---|---|
| WAH-<域>-001 | 待验收 / 已通过 / 有证据的排除 | 入口、场景、命令或操作、结果；真实依赖与替代测试分别说明 | 日期 / commit |

## 必须关闭的全域清单

- **运行核心**：配置、模型 provider/resolver、Lead/子 Agent、状态、thread/session、checkpointer、业务持久化、生命周期和迁移。
- **智能能力**：全部一方 tools/builtins、middleware、memory、knowledge/owned/vector、code_index、context/guardrails、文件/上传和结果管理。
- **任务执行**：subagents/builtins、sandbox providers、execution_security、session execution/tool binding、cancellation、goal、collab、task plans、scheduler execution、automation、proactive、workflows/stage。
- **扩展治理**：MCP transports/connection lifecycle、community providers、plugins/capability/skills、external agents/A2A、authz、webui auth、organizations、license、observability/eval。
- **应用服务**：CLI commands、所有 Gateway routes、SSE/streaming/events、所有 IM channels、MessageBus/Manager/store/service、runtime ports/adapters、app_server、speech/v4/cancellation、健康/启动/关闭/多进程运行。
- **界面产品**：所有 Web pages/routes、聊天状态、API client、设置、上传、工具卡片、zcode-ui/services/shared/rpc/provider、desktop/Tauri、locale、权限和错误体验。
- **维护与交付**：数据库迁移、部署配置、升级兼容、密钥存储、日志/trace、故障恢复、性能与资源限制、文档及图的快照一致性。

## 最终验收关卡

1. **覆盖率审查**：矩阵没有空白 WorkAgentHarness 状态或未注明的缺失项；每个排除项都说明许可证/私有服务/凭据/生成产物等具体理由和替代方式。
2. **入口审查**：CLI、HTTP/SSE、IM、Web/桌面、后台 worker 的适用端到端旅程通过；独立模块无调用者的需明确标为未集成。
3. **安全审查**：鉴权真正覆盖被保护的 API、工具、channel、文件和组织资源；检查越权、撤权、日志脱敏、sandbox 边界。
4. **状态与恢复审查**：checkpoint、业务数据、任务状态、索引、流事件在异常/重启后保持一致，重复动作安全。
5. **发布/升级审查**：schema migration、配置升级、兼容、关闭清理、部署和健康检查经演练。
6. **文档审查**：代码解释和 HTML 图均绑定固定版本、路径正确；现状图与目标图分开；没有过时的“已完成/全链路”声明。

## 完成定义

所有适用功能项有行为等价实现和验收证据；所有外部依赖有稳定替代测试；每个 M 章节达到“完整对齐”或有据可查地排除；系统级跨域验收通过。剩余真实联调限制需具体列出，不能用“架构同构”或“测试通过”掩盖产品能力差异。
