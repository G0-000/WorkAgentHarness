# M4 — 子代理、执行安全与隔离

> 本章的实现目标是 WorkAgentHarness。文中出现的 AgentFlow 路径、状态和第一次学习记录均为历史对照；WorkAgentHarness 当前状态以本仓库和 02 全量功能矩阵为准。

## 本章目标

理解主 Agent 如何委派任务、构造子代理、限定可用工具、控制并发、汇总结果和停止任务；同时区分代码级 path guard、审批策略与操作系统/容器级隔离。

## 四级学习

### 核心代码讲解清单

按 EvoFlow 与 AgentFlow 第一版当前存在的代码追 `subagents/registry` → `subagents/executor` → builtin definitions；再读 `sandbox` provider/interface、路径 guard、execution permission/approval policy、audit repository、session execution/tool binding 和 cancellation 的调用者。逐项说明策略从哪里配置、在哪个边界强制、拒绝如何返回、进程/文件副作用由谁执行和怎样清理。

### L1 入门闭环

主 Agent 用 dispatcher 委派一个 fake 子任务；子任务返回结构化结果；主 Agent 收到结果后完成回答。先不执行 shell，不开放任意文件路径。

### L2 基础能力

加入 registry/config、子代理类型/提示词、专属工具 allowlist、并行任务数限制、工作目录白名单、超时、失败结果和审计记录。至少四个并行 fake task 验证并发上限，而不是只跑两个任务。

### L3 完整功能

盘点原版 subagent modes/builtins、任务拆分/派发、预算/深度/并发、结果流、重试、子任务状态、工具绑定、命令/文件审批策略、不同 sandbox provider 和 session 生命周期。核对 UI/IM 上的子任务事件如何呈现。凡 AgentFlow 第一版当前不存在的 execution_security、session_execution、session_tool_binding 行为，都列为功能缺口而非默认简化。

### L4 高级边界

验证路径穿越、符号链接、命令注入、环境变量/凭据泄漏、危险命令、越权工具、并发资源耗尽、取消传播、子任务孤儿、超时之后副作用、重试幂等和审计完整性。明确哪种隔离是真 OS/container sandbox，哪种只是应用层检查。

## 练习与验收

AgentFlow 第一版的 Archify 图（历史参考）：[M4 子代理与沙箱图](/Users/main/AgentFlow/doc/doc-dev/01-里程碑/diagrams/M4-subagents-sandbox-20261011-034339/M4.html)。它表示初版实现边界；执行安全策略、审批和隔离 provider 清点后需补充目标图。

1. 设计四个可控 fake subagent：慢任务、失败任务、取消任务和正常任务；验证限流、聚合、错误可见性。
2. 对只读工具/写入工具/命令工具实施差异权限，测试拒绝与审计。
3. 中断父任务，验证子任务能停止且状态不会永久停在 running。
4. 在安全隔离环境里验证真实 sandbox provider；若无法跑容器，报告隔离等级和缺口。
