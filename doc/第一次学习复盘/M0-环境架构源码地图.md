# M0 — 环境、架构与完整源码地图

> 本章的实现目标是 WorkAgentHarness。EvoFlow 是源码事实；AgentFlow 第一版仅作历史对照，不能把旧版目录和完成状态当成新仓库现状。

## 本章目的

M0 暂不搬 Agent 功能代码。它要核实三个本地仓库的工具链和边界，理解 EvoFlow 的 app/core/UI/数据分层，复盘 AgentFlow 第一版，并为干净的 WorkAgentHarness 确定工程方案、入口文档和全量功能矩阵，避免再次只学到一个缩小版。

## 学习前准备

- 确认 EvoFlow 参照 `v1.1.2` / commit `b9def02fc84d21a4e38f422e8e66525d481dfd5d`；确认 AgentFlow 第一版 `d39429698752ce01770896c2be887d2ca952cb2b`；确认 WorkAgentHarness 起点 `2e37f01970f687b6f0ce598da86eb5d553e0df3c`。
- 分别读三个仓库的 README、Git 状态和目录。EvoFlow 读 `backend/ARCHITECTURE.md`，确认 app→core 依赖约束及现存例外；AgentFlow 阅读已有实现和历史验收；WorkAgentHarness 记录“当前无后端/前端/测试实现”，并区别初始提交与本次新增文档。
- EvoFlow 根说明提及的 `.codebasewiki/index/index.md` 与 `architecture.md` 在当前 checkout 缺失；用 `backend/ARCHITECTURE.md`、`backend/CLAUDE.md`（若存在）、真实入口、测试和调用点替代导航，并记为资料缺口。
- 记录当前 Python、Node、包管理器和可用外部服务；在 WorkAgentHarness 未建立工程前，不要把旧项目的测试/运行命令套用到新仓库，也不要伪造通过结果。

## 四级学习

### L1 入门：确认仓库状态与运行前置条件

阅读 EvoFlow 与 AgentFlow 第一版的根文档、manifest、workspace、CLI/Gateway/前端入口。记录 WorkAgentHarness 当前只有初始化 README 和 `.gitignore`；提出新仓库的最小项目骨架及依赖决策，但先用 ADR/设计说明记录理由，再逐步创建，不复制 AgentFlow 双包目录作为默认方案。

### L2 基础：画分层和主要数据边界

并读 EvoFlow `backend/ARCHITECTURE.md`、核心包 `evoflow/`、`backend/app/` 与 `evopanel/`，再对照 AgentFlow 第一版实际调用。画出三方 core、应用层、UI、持久化及外部服务边界。说明 R1 依赖方向：app 可以依赖 core；core 通过 core 声明的 port 使用应用能力，不能反向 import app。WorkAgentHarness 的目标分层需写出理由，不因旧项目同名路径而照搬。

### L3 完整地图：盘点每个功能入口

对 EvoFlow 路由、CLI 命令、工具注册、配置 schema、数据库迁移、渠道、worker、前端路由、桌面入口和协议目录做清单。至少检查核心包 `backend/packages/harness/evoflow/` 下的一方域：`agents`、`models`、`config`、`tools`、`memory`、`knowledge`、`code_index`、`subagents`、`sandbox`、`execution_security`、`collab`、`plans`、`scheduler`、`automation`、`proactive`、`mcp`、`plugins`、`community`、`authz`、`organizations`、`observability`、`workflows`、`a2a`、`runtime`、`app_server` 等。应用层 `backend/app/gateway/` 另行盘点 `v4/`、`speech/`、`cancellation/` 等路由和服务目录；核心层也有独立的 `cancellation/`，需按真实调用关系分别记录。

将 `evopanel` 作为独立产品面盘点：普通页面与 React 聊天入口、`evopanel/src/zcode-ui/`、`evopanel/src/zcode-services/`、`evopanel/src/zcode-shared/`、`evopanel/src/zcode-rpc/`、`evopanel/src/zcode-provider/`、协议 v4、桌面/Tauri 和本地服务调用关系。不能把“文件多”当目标，也不能漏掉这些用户功能。

### L4 高级：运行维护和仓库差异

列出数据库及迁移、启动/关闭、健康探针、恢复、后台进程、并发和配置部署方式；检查哪些代码有真实调用者、哪些只是独立模块。对缺失的 `.codebasewiki` 索引留证据说明，并用现存架构文档和测试替代导航。

## 核心代码讲解清单

- `backend/pyproject.toml` 与 `backend/packages/harness/pyproject.toml`：workspace 成员、包依赖和 CLI script 入口。
- `backend/langgraph.json`：graph id、模块符号和 checkpointer 装配；再用 CLI/服务端找到实际加载者。
- `backend/app/gateway/app.py`：FastAPI app 创建、lifespan 和路由注册；区分声明与实际运行。
- `evopanel/src` 的 package scripts、boot/router 和 API proxy：浏览器如何启动并连接后端。

讲解时给出当前快照的文件/符号位置、输入输出、启动副作用和失败点；代码细节随版本更新重查。

当前源码分层图：[EvoFlow M0：源码分层与 Runtime Port](diagrams/M0-evoflow-layers-20261020-185709/M0-evoflow-layers.html)，对应源码阅读记录见 [M0 记录 01](../学习记录/起点/EvoFlow分层源码阅读.md)。这张图固定到 EvoFlow `b9def02fc84d21a4e38f422e8e66525d481dfd5d`，展示已核实的 app/core/持久化边界；M0 全量功能盘点完成后，再补齐全域入口图。

1. 核实 EvoFlow 与 AgentFlow 第一版的现存运行入口和命令；在 WorkAgentHarness 只确认当前仓库状态，记录预计首个可运行闭环，不把空仓库写成“启动通过”。
2. 从 CLI、HTTP、IM、Web 各选一个入口，写出入口→装配→核心→存储/外部服务→输出链。
3. 建立三方功能矩阵，给每项分配 M1–M8 和 L1–L4，分别标识 AgentFlow 第一版表现与 WorkAgentHarness 的待设计/未实现/实现状态。
4. 将 EvoFlow 和 AgentFlow 第一版目录地图分别与调用点、测试、配置、数据库迁移交叉核对；为 WorkAgentHarness 明确新增目录/模块的职责和入口，不从目录名推定功能。
5. **入口文档与快照一致性验收（§7 P1）**：逐一检查 WorkAgentHarness 根 README、`doc/README.md`、本手册入口，以及 AgentFlow 第一版中的历史 [AI 接管指南](/Users/main/AgentFlow/doc/doc-dev/00-快速上手/AI接管指南.md)、`doc/doc-dev/README.md`、[验收体系 README](/Users/main/AgentFlow/doc/doc-dev/05-验收体系/README.md)。区分新仓库当前入口与旧仓库历史材料；确认新仓库文档标明 M0–M8 状态、EvoFlow/AgentFlow 参照 commit，并链接到唯一当前学习路线和功能矩阵。旧状态只能作为注明日期的历史记录，不得继续充当当前状态入口。检查所有相关链接可打开、相互矛盾的完成声明已改正或标为历史。验收记录列出文件、修订项和复核日期。
6. **盘点和索引验收（§7 P1/P2）**：确认全量功能矩阵每行有稳定 ID、EvoFlow 证据和章节归属，缺失实现标为缺失；删除非必要且没有快照/统计口径的文件数、目录数、组件数。核对 EvoFlow 索引引用是否在固定 checkout 中存在；若不存在，记录替代阅读路径及源码核验依据。

## 验收

- 能解释三个仓库的结构差异、已有运行命令、WorkAgentHarness 当前尚无实现的状态和 core/app 边界。
- 功能矩阵覆盖核心、服务端、前端/桌面和运维域；每项至少有 EvoFlow 证据、AgentFlow 第一版对照、WorkAgentHarness 状态和章节归属。
- 入口文档指向同一当前路线、固定快照和功能矩阵；历史状态有日期和用途标记，不能与当前状态混用。
- 全量功能项有稳定 ID、源码/入口/测试证据和 M 章节归属；失效索引有经过源码核验的替代导航。
- 架构图标明来源 commit 和“现状/目标”，不以文件数量作为完成标准。
- 输出：完整源码地图、功能矩阵初版、依赖先修图、待确认项。
