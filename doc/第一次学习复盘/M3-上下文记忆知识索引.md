> 本章的实现目标是 WorkAgentHarness。文中出现的 AgentFlow 路径、状态和第一次学习记录均为历史对照；WorkAgentHarness 当前状态以本仓库和 02 全量功能矩阵为准。

## 本章目标

区分当前请求上下文、会话状态、跨会话用户记忆、文档知识库和代码索引；沿摄取→切块→向量化→索引→检索→权限过滤→prompt 注入→答案引用走通全链路。

## 四级学习

### L1 入门闭环

用户说“记住我喜欢 X”→规则或 mock 提取→SQLite 写入→新 thread recall→注入 prompt。另做一篇纯文本：切块→fake embedding→cosine top-k→knowledge tool 返回来源。

### L2 基础能力

实现 provider 注册/维度校验、文档 CRUD、去重、分块元数据、embedding 失败处理、top-k/阈值过滤、来源引用、删除和重新索引；对 thread/user/组织作用域做数据隔离。

### L3 完整功能

逐项盘点 memory 层级/合并/衰减/召回排序/隐私删除；knowledge 基础库、owned 知识中心、vector backend、文档上传/处理任务、索引构建、知识图谱/worker/job/migration；code_index 的解析、chunking、embedding、检索、更新、删除和代码上下文注入；以及面向 Agent、Gateway、UI 的工具和 API。当前 AgentFlow 第一版的简易 memory + 单库向量检索仅是起点，不覆盖原版的 owned 或 code index 域。

### L4 高级边界

检验权限/租户过滤是否发生在检索之前；索引并发更新、重复摄取、部分失败重试、删除后不可召回、向量维度变更、迁移、过期索引、召回成本和 prompt token 限额。逐条验证检索来源能追溯到原文。

## 关键概念

源码讲解至少覆盖 `agents/thread_state.py`/上下文 middleware、`memory/facade.py` 与 consolidation/存储、`knowledge/chunker.py`、embedding interface/registry、knowledge service/repositories，以及 `code_index/` 的真实 builder/index/retrieval 调用链。对每块记录写入者、读取者、数据形态、过滤权限、删除入口和对应测试；只看到目录不能认定接入。

AgentFlow 第一版的 Archify 图（历史参考）：[M3 记忆与知识图](/Users/main/AgentFlow/doc/doc-dev/01-里程碑/diagrams/M3-memory-knowledge-20261011-034339/M3.html)。图按首次学习的单库检索路径编制，尚不能代表 owned knowledge 与 code index 的完整目标。

- **短期上下文**随一次 thread 变化；**长期记忆**是从多次对话提炼的偏好/事实；**知识**是可引用资料；**code index**索引的是工作区代码。四者数据来源、所有者、生命周期和权限不同。
- **embedding 近邻**提供相关候选，不等于事实正确；排序/过滤和来源展示决定检索可用性。
- **删除**要覆盖原始文档、chunks、向量、缓存和派生索引；只删 UI 列表记录不算完成。

## 练习与验收

1. 给 memory、knowledge、code index 各画一个读写数据流和生命周期图。
2. 建立 provider/backend/格式/配置/入口矩阵；每个矩阵项连到原版测试或实现证据。
3. 用假 embedding 测检索逻辑，用真实 provider 做单独联调记录。
4. 做跨用户越权、文档撤回、索引更新失败恢复和召回来源核验。
5. 从 [02-全量功能矩阵](02-全量功能矩阵.md) 筛出本章 owned knowledge 与 code_index 的功能 ID，各选一项沿真实 API/tool/worker/UI 入口完成摄取或索引更新→权限过滤→检索/上下文注入→删除或重建，并记录端到端证据。对目前缺少实现或产品入口的条目明确标记未完成，不以单元测试或目录存在关闭 §7 的 M3 出口。
